## 背景

模型的输入是 token 编号，文本要先**分词**。几种粒度各有问题：

| 粒度 | 问题 |
| --- | --- |
| 按词 | 词表巨大；没见过的词（新词、拼写错误）无法表示 |
| 按字符 | 词表很小，但序列很长，每个 token 携带的信息太少 |
| **子词** | 常见词是一个 token，罕见词拆成几个常见片段，兼顾两者 |

**BPE**（Byte Pair Encoding，字节对编码）是最常用的子词算法，GPT 系列、LLaMA 都使用它的变体。

## 核心思想

**训练**：从单个字符开始，反复找出语料中**出现次数最多的相邻符号对**，把它合并成一个新符号，记录下这条合并规则。合并 $M$ 次后，词表大小 = 初始字符数 + $M$。

**词尾标记** `</w>`：每个词末尾加一个特殊符号，这样 `est</w>`（词尾的 est，如 newest）和词中间的 `est`（如 estimate）是不同的 token。

**例子**：语料中各词的出现次数为 `low` ×5、`lower` ×2、`newest` ×6、`widest` ×3。拆成字符后统计相邻对（按词频加权）：

| 符号对 | 次数 |
| --- | --- |
| `e s` | $6 + 3 = 9$ |
| `s t` | $6 + 3 = 9$ |
| `t </w>` | $6 + 3 = 9$ |
| `w e` | $2 + 6 = 8$ |
| `l o`、`o w` | $5 + 2 = 7$ |

最高频的对被合并，例如 `e s` → `es`。之后 `es t` 成为高频对，再合并成 `est`……几轮之后 `est</w>`、`low` 都会成为单独的 token。

**编码**：把新文本按词拆成字符（加上 `</w>`），然后**按学到的顺序**依次应用每条合并规则。先学到的规则优先级更高。

## 用到的 Python 工具

- 用 `tuple` 表示一个词的符号序列，它可以作为字典的键；字典值是这个词在语料中的出现次数。
- `max(pairs, key=pairs.get)`：频率最高的符号对。
- 合并时从左到右扫描，遇到目标对就合并并跳过两个位置。

## 常见坑

- **统计符号对时没有乘词频**：同一个词出现 5 次，它的每个相邻对都要算 5 次。
- **重叠的合并**：`a a a` 合并 `(a, a)` 时，从左到右得到 `aa a`，不能把中间的 `a` 用两次。
- **编码时不按训练顺序**：比如贪心地找最长匹配，结果会和训练时的切分不一致。
- **忘了 `</w>`**：训练和编码都要加。
- **`self.merges` 没有按顺序保存**：测试会检查第一个合并的是最高频的对。
- 自检：把一个词编码后的 token 拼起来，去掉 `</w>`，应得到原词。

## 延伸

- **本题是教学版**：本题按空白切词、以字符为初始符号。真实系统有两点不同。一是初始符号换成 256 个字节（byte-level BPE，GPT-2 起使用），这样任何输入都能编码；按本题的写法，没在训练中见过的字符只能原样保留，相当于一个退化的 OOV。二是先做**预分词**，用正则把文本切成块，合并只发生在块内部，整体对比见「分词」专题。
- **训练的代价**：朴素做法每一步都重新扫一遍全部不同的词，总代价约为 $O(M \cdot N)$（$M$ 是合并次数，$N$ 是不同词的符号总数）。这也是为什么训练只在「词 → 频数」的字典上做，而不是扫原始语料。工业实现还会维护符号对到所含词的索引，只更新受影响的词，并用堆取最高频的对。
- **平局的处理**：几个符号对频数相同时，选哪一个会影响后续所有合并，所以实现要固定一条确定的规则，否则同一份语料训练两次可能得到不同的合并表。
- **编码的实现**：编码也可以换一种等价的写法。不是逐条规则扫描，而是看当前序列里出现的所有相邻对，反复合并其中**序号最靠前**的那一条规则，直到没有可合并的对为止。常见实现还会按词缓存结果，因为自然语言里的词反复出现。
- **同一个词，切法是确定的**：训练时一个词被合并成什么样，编码时按同样的顺序回放就得到同样的切分。这也是「编码不统计频数」的含义。
- **BPE-dropout**：编码时以一定概率随机跳过某些合并，同一个词会得到不同的切分，起到数据增强的作用。需要这类采样时，Unigram 是更自然的选择。
- **解码与特殊 token**：把 token 拼起来即可还原文本。实际词表里还有不参与合并的特殊 token，比如文本结束符，它们只在预分词前被单独识别出来。

## 面试追问

1. **BPE 训练和编码分别做什么？为什么编码不需要频数？**
   训练统计相邻对频数，反复合并最高频的一对，产出有序的合并表；编码只是把这张表按顺序回放到新文本上，用到的是规则的先后，不再统计任何频数。
2. **BPE 的 `</w>` 有什么用？byte-level BPE 里怎么处理？**
   它区分词尾和词中的同一段字符，如词尾的 `est` 和 `estimate` 里的 `est`。GPT-2 一类的 byte-level BPE 不加词尾符，而是把前导空格并入后面的词（` hello` 和 `hello` 是不同的 token），预分词也负责划定词的边界。
3. **BPE 和 WordPiece 的合并准则有什么不同？**
   BPE 取频数最高的相邻对；WordPiece 取使语言模型似然增益最大的对，打分近似为 $\text{freq}(ab) / (\text{freq}(a)\,\text{freq}(b))$，会压低那些只是因为单个符号都很常见而经常相邻的对。
4. **为什么 GPT-2 要用字节而不是字符做初始符号？**
   Unicode 的字符太多，全收进词表既大又稀疏；用 256 个字节做初始符号，词表基础固定，任何输入都不会 OOV，且解码无损。代价是罕见字符（如一部分汉字）会变成多个字节 token。
5. **增加合并次数，会发生什么？**
   词表变大，同一段文本编码出的 token 变少（对应本题中「更多合并 → 更少 token」那条测试），但合并到后面的规则对应的片段越来越罕见，每个新 token 的训练样本变少，模型参数 $V \times D$ 也随之增加。
