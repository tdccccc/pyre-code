## 背景

上下文长到百万 token 时，即使用了 FlashAttention，单张卡也存不下整条序列的 Q、K、V 和激活。**环形注意力**（Ring Attention）是一种**序列并行**：把序列切成 $N$ 段，每张卡负责一段。

每张卡的查询需要和**所有**位置的键值做注意力，但每张卡只有一段 K/V。做法是把 $N$ 张卡连成一个环，每一轮：

1. 用手上的 K/V 块和自己的 Q 块计算，累加进结果
2. 把手上的 K/V 块传给下一张卡，同时从上一张卡接收一块

$N$ 轮后，每张卡都见过了所有 K/V 块。传输可以和计算重叠，几乎不增加耗时；每张卡的显存只与 $S/N$ 有关。

## 核心公式

卡 $i$ 持有 $Q_i$，第 $j$ 轮（$j = 0, \dots, N-1$）处理的是第 $(i + j) \bmod N$ 个 K/V 块。

跨块合并 softmax 用的是和 FlashAttention 相同的**在线 softmax**：维护运行最大值 $m$、分母 $\ell$ 和输出 $o$。对新块的分数 $s$：

$$
m' = \max\bigl(m,\ \max_j s_j\bigr),
\qquad
\ell' = \ell\, e^{m - m'} + \sum_j e^{s_j - m'}
$$

本题保存的 $o$ 是**已经归一化**的输出，所以更新时先还原成未归一化的累加值，再加上新块，再除以新分母：

$$
o' = \frac{o \cdot \ell\, e^{m - m'} + \sum_j e^{s_j - m'}\, v_j}{\ell'}
$$

初始 $m = -\infty$、$\ell = 0$、$o = 0$。

softmax 的分子和分母都是求和，与处理顺序无关，所以环形顺序不影响结果，和标准注意力**精确相等**。

## 形状

| 量 | 形状 |
| --- | --- |
| `Q`、`K`、`V` | `(B, S, D)` |
| 每个块 | `(B, S/N, D)` |
| 块间分数 | `(B, S/N, S/N)` |
| $m$、$\ell$ | `(B, S/N, 1)` |
| $o$ | `(B, S/N, D)` |
| 拼接后输出 | `(B, S, D)` |

## 常见坑

- **修正因子漏乘**：之前的 $o$ 和 $\ell$ 都是按旧最大值 $m$ 算的，必须乘 $e^{m - m'}$ 对齐到新最大值。
- **混淆两种累加形式**：如果 $o$ 存未归一化的累加值，就在最后除以 $\ell$；如果存归一化后的值，每步都要先乘回 $\ell$。两种都对，但不能混用。
- **缩放因子**：分数要乘以 $1/\sqrt{D}$。
- **切块维度**：沿序列维 `dim=1` 切，不是特征维。
- 本题没有因果掩码。

## 延伸

- **通信量**：每轮把 K 和 V 各一块（$T/P$ 个 token）传给下一张卡，共 $P-1$ 轮，每卡共发送

$$
2\cdot\frac{P-1}{P}\,T h
$$

  个元素，$T$ 是整条序列的 token 数，$h$ 是 K（或 V）的宽度。它不随 $P$ 减小。用 GQA 时 $h$ 换成 K/V 的总宽度，通信量随 KV 头数一同下降。
- **能不能被计算盖住**：每轮一块的计算约 $4c^2 h$ FLOPs（$c = T/P$），传输 $2ch$ 个元素（bf16 下 $4ch$ 字节）。设峰值算力 $F$、单向带宽 $B$，计算不短于传输的条件是

$$
c \ \ge\ \frac{F}{B}
$$

  H100 的 $F \approx 989$ TFLOP/s，NVLink 单向 $450$ GB/s 时 $c \gtrsim 2\times10^3$ 个 token，单块 $50$ GB/s 的网卡时 $c \gtrsim 2\times10^4$（按峰值估算，真实 kernel 达不到峰值，条件会宽松一些）。块越大越容易盖住，所以长序列才是它的适用场景。
- **因果掩码带来负载不均**：连续切分时，第 $i$ 张卡的 Q 块只需要看前 $i+1$ 个 K/V 块，最后一张卡的计算量是第一张卡的 $P$ 倍，其他卡在等它。常见补救是打乱序列的分配方式（交错或「之字形」），让每张卡拿到的因果工作量接近。本题没有因果掩码。
- **块内用 FlashAttention**：每一块的计算可以交给 FlashAttention kernel。因为要跨块合并，kernel 需要把每行的 log-sum-exp 一并返回，合并时用它还原出分母。设备间的环和块内的分块，是同一个在线 softmax 在两个层级上的使用（见「IO 感知 kernel」专题）。
- **反向同样要绕环**：每张卡要算本地 Q 的梯度，也要算路过的 K/V 块的梯度，$dK$、$dV$ 的累加值随着 K/V 块一起传，反向的通信量约为前向的两倍。
- **显存**：每卡只保存自己的 Q 块和一份正在算的 K/V 块，加一份正在接收的缓冲区（双缓冲），与 $T/P$ 成正比；加卡就能线性地增加可处理的序列长度。

## 面试追问

1. **为什么 Ring Attention 的结果和标准注意力精确相等？**
   softmax 的分子和分母都是求和，与处理顺序无关。在线 softmax 在每个新块到来时用 $e^{m-m'}$ 把旧的累加值对齐到新的最大值，所以按任意顺序处理 K/V 块，数学上都与一次性算出完整 softmax 相同（浮点下有舍入差）。
2. **通信能被计算隐藏吗？需要什么条件？**
   可以：每轮计算当前块时，下一块已经在传输。条件是计算时间不短于传输时间，推出每卡的块长 $c \ge F/B$。NVLink 上约几千个 token，跨机要大一个数量级。
3. **因果注意力下 Ring 有什么问题？**
   连续切分时各卡的工作量不均衡：Q 块靠后的卡要看的 K/V 块更多，最慢的卡决定整体速度。解决办法是改变序列在各卡上的排布，使每卡的因果工作量接近。
4. **Ring Attention 和 FlashAttention 的在线 softmax 是什么关系？**
   同一个技巧：维护运行最大值、分母和输出，逐块合并。FlashAttention 是在一张卡上按 SRAM 大小分块，为了少访问 HBM；Ring Attention 是按设备分块，为了让显存不再受限于整条序列。
5. **序列长度翻倍，Ring Attention 需要怎样的资源？**
   保持每卡块长不变就要卡数翻倍，每卡显存不变；注意力总计算量翻两番，所以每卡的计算量翻倍。若卡数不变，每卡的 K/V 和激活都翻倍。
