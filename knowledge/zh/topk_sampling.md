## 背景

语言模型每一步输出词表上的一个概率分布，下一个 token 怎么选？

- **贪心**（取 argmax）：确定但单调，容易重复。
- **直接按分布采样**：多样，但词表有几万个 token，概率很低的「长尾」加起来不可忽视，偶尔会采到离谱的词。

常用做法是先用**温度**调整分布的尖锐程度，再用 **top-k** 或 **top-p** 砍掉长尾，最后在剩下的 token 中采样。

## 核心公式

**温度** $T$：

$$
p_i = \frac{e^{z_i / T}}{\sum_j e^{z_j / T}}
$$

- $T < 1$：分布更尖锐，$T \to 0$ 时趋向 argmax
- $T = 1$：原分布
- $T > 1$：分布更平坦，$T \to \infty$ 时趋向均匀分布

**top-k**：只保留 logits 最大的 $k$ 个 token，其余设为 $-\infty$（概率为 $0$）。$k = 1$ 即贪心。

**top-p（核采样）**：把 token 按概率从大到小排序为 $p_{(1)} \ge p_{(2)} \ge \dots$，保留**最小的**前缀集合，使其累积概率达到 $p$：

$$
\text{保留第 } r \text{ 名} \iff \sum_{s < r} p_{(s)} < p
$$

即只要排在它**前面**的 token 的概率之和还没到 $p$，它就保留。概率第一的 token 永远保留。和 top-k 相比，top-p 的保留个数会随分布形状自适应：分布很集中时只剩几个，很平坦时保留很多。

过滤后对剩下的 logits 重新做 softmax，概率自动重新归一化。

## 形状

`logits` 为 `(V,)`。排序后得到排好序的值和原始下标 `sorted_idx`，过滤在排序后的顺序上做，然后要按 `sorted_idx` 放回原来的位置。

## 用到的 PyTorch 操作

- `logits.topk(k).values[-1]`：第 $k$ 大的值，作为阈值。
- `torch.sort(t, descending=True)`：返回 `(values, indices)`。
- `torch.cumsum(p, dim=-1)`：累积和。
- `torch.empty_like(t).scatter_(0, sorted_idx, sorted_vals)`：把排序后的值写回原始位置。
- `torch.multinomial(probs, 1)`：按概率采样一个下标；`.item()` 转成 Python 整数。

## 常见坑

- **顺序不对**：先温度，再 top-k，再 top-p。
- **top-p 没有排序**：累积概率必须按从大到小的顺序计算。
- **过滤后没有放回原位**：在排序空间里采到的是名次，不是 token 编号。
- **把概率第一的 token 也过滤掉了**：如果单个最大概率就超过 $p$，用 `cumsum > p` 作条件会把它也去掉。正确条件看的是「它前面的累积和」。
- **返回张量**：题目要求返回 `int`。
- 可以把 $-\infty$ 直接留在 logits 里交给 softmax：$e^{-\infty} = 0$。

## 延伸

- **温度对分布的影响**：温度改变的是分布的尖锐程度，不改变 token 的排序。$T \to 0$ 时趋向贪心，工程上 $T = 0$ 通常单独当作 argmax 处理，避免除以零。
- **top-k 与温度的顺序**：温度对所有 logits 是同一个单调变换，所以 top-k 选出的集合与温度先后无关；top-p 看的是概率，先温度还是后温度会得到不同的保留集合，所以顺序必须固定。
- **top-p 在 top-k 之后**：top-k 过滤后，剩下的 logits 重新做 softmax，top-p 的累积概率是在这个重新归一化的分布上算的。
- **top-p 的代价**：需要对整个词表排序，词表有十几万时比 top-k 贵。实现时常见的做法是先用 top-k 缩小候选范围，再对剩下的做排序和累积。
- **采样的另一种写法**：Gumbel-max 技巧——给每个 logit 加上独立的 Gumbel 噪声再取 argmax，得到的分布与按 softmax 采样相同。它只需要逐元素运算和一次 argmax，便于在 GPU 上并行，不用显式算 softmax 和累积和。
- **top-p 的局限**：当分布非常平坦时，要累积到很多 token 才够 $p$，长尾里的不合理词也被放了进来；min-p 用相对阈值缓解这一点，见「解码与采样」专题。

## 面试追问

1. **top-k 和 top-p 有什么区别？各自的问题是什么？**
   top-k 固定保留 $k$ 个，分布很集中时会混进不合理的词，很平坦时又砍掉合理的词。top-p 保留累积概率达到 $p$ 的最小集合，个数随分布形状自适应，但在分布很平坦时仍可能放进一大段长尾。
2. **温度调高或调低，分别发生什么？**
   $T$ 越大分布越平坦、输出越多样也越容易出错；$T$ 越小越尖锐，趋向贪心、更稳定但更单调。温度不改变 token 的概率排序。
3. **`top_k=1` 和 `temperature → 0` 有什么关系？**
   两者都退化成贪心。区别是：`top_k=1` 精确等价于 argmax；温度趋于 $0$ 是极限，数值上可能下溢，实现里一般对 $T = 0$ 单独处理。
4. **同时设置 top-k 和 top-p，谁先谁后？为什么顺序重要？**
   常见的约定是温度 → top-k → top-p。top-p 依赖概率分布，top-k 过滤并重新归一化会改变累积概率，所以先后不同保留集合可能不同。
5. **top-p 的实现里，为什么看「前面的累积和」，而不是「含自己的累积和」？**
   用含自己的累积和，一旦概率第一的 token 就已经超过 $p$，它会被自己过滤掉，候选集合为空。看排在它前面的累积和，概率第一的 token 永远被保留，才符合「最小的、累积概率达到 $p$ 的前缀」这一定义。
