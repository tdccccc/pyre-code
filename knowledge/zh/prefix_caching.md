## 背景

线上大量请求共享相同的开头：同一个系统提示词、同一段 few-shot 示例、多轮对话里的历史消息。每次都为这些前缀重新做预填充，是在重复劳动。**前缀缓存**把算过的 KV 块按内容登记起来，新请求如果以相同的 token 开头，就直接复用那些块，跳过对应的预填充。vLLM 的 Automatic Prefix Caching 和 SGLang 的 RadixAttention 都是这个思想。

## 核心概念

**键必须是整个前缀**：第 $i$ 个块（块大小 $P$）的键是

$$
\text{key}_i = \text{tokens}\bigl[0 : (i+1) P\bigr]
$$

而不仅仅是这一块自己的 $P$ 个 token。原因是一个 token 的 K、V 经过了注意力，依赖于它**前面所有** token。两个块内容相同、但前面的内容不同，它们的 KV 也不同，不能共享。

**只缓存满块**：最后一块没填满，之后还会追加新 token、改变内容，不能共享。

**遇到第一个不命中就停止复用**：块 $i$ 的 KV 只有在前面所有块都完全相同时才有效。

**块的三种状态**：

| 状态 | 引用计数 | 已登记 | 去向 |
| --- | --- | --- | --- |
| 使用中 | $> 0$ | 可能 | — |
| 可驱逐（缓存着但没人用） | $0$ | 是 | 再次命中时「复活」；空间不够时按 LRU 被驱逐 |
| 空闲 | $0$ | 否 | 直接分配 |

**分配新块的优先顺序**：

1. 空闲池中编号最小的块
2. 否则，驱逐**最早**变为可驱逐的块（LRU：最近最少使用），删除它的登记
3. 否则抛 `RuntimeError`

引用计数归零的已登记块不立即回收，留着等待以后的命中；真的缺空间时才驱逐最久没人用的那个。

## 用到的 Python 工具

- `tuple(tokens[:end])`：列表不可哈希，转成元组才能作字典的键。
- 两个字典：`键 → 块`、`块 → 键`，用于查找和驱逐时删除登记。
- `heapq` 最小堆管理空闲池；一个单调递增的计数器记录「变为可驱逐的时刻」。
- 向上取整：`-(-n // P)` 或 `math.ceil(n / P)`。

## 常见坑

- **只用块内容作键**：不同前缀后面的相同内容会被错误共享，测试专门检查。
- **共享了不满的最后一块**。
- **前面某块没命中，后面又去复用**：一旦不命中，之后所有块都要新分配。
- **复用一个可驱逐块时没有把它移出可驱逐集合**：它可能在使用中被驱逐。
- **驱逐顺序**：按变为可驱逐的先后，不是按块编号。同一次 `free_sequence` 释放的块，按它们在块表中的位置先后计时。
- **未登记的块归零后进了可驱逐集合**：它应直接回到空闲池。
- **同一个键登记两次**：键已登记给别的块时，新块保持未登记。
