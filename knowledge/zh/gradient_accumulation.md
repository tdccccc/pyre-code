## 背景

大 batch 训练更稳定，但显存装不下。**梯度累积**把一个大 batch 拆成 $n$ 个小的**微批次**（micro-batch），逐个做前向和反向，把梯度累加起来，最后只做一次参数更新。效果等价于用大 batch 训练一步，显存只需要容纳一个微批次。

## 核心公式

大 batch 有 $N$ 个样本，损失取均值：

$$
L = \frac{1}{N} \sum_{i=1}^{N} \ell_i
$$

平均拆成 $n$ 个微批次，每个大小 $N/n$，各自的平均损失为 $L_k$：

$$
L_k = \frac{n}{N} \sum_{i \in \text{第 } k \text{ 批}} \ell_i
\qquad\Rightarrow\qquad
L = \frac{1}{n} \sum_{k=1}^{n} L_k
$$

梯度是线性的：

$$
\nabla L = \sum_{k=1}^{n} \nabla\!\left(\frac{L_k}{n}\right)
$$

所以每个微批次对 $L_k / n$ 做反向传播，累加起来恰好就是大 batch 的梯度。

**PyTorch 的梯度是累加的**：`loss.backward()` 会把新梯度**加到** `.grad` 上，而不是覆盖。这本来是需要每步 `zero_grad()` 的原因，在这里正好被利用来实现累积。

## 流程

1. 清零梯度（只做一次）
2. 对每个微批次：前向 → 损失除以 $n$ → 反向（梯度累加进 `.grad`）
3. 优化器更新一次

## 用到的 PyTorch 操作

- `optimizer.zero_grad()`、`optimizer.step()`。
- `loss.backward()`。
- `loss.item()`：取出数值用于记录，不保留计算图。

## 常见坑

- **在循环里调用 `zero_grad()`**：前面微批次的梯度被清掉，只剩最后一个。
- **在循环里调用 `step()`**：变成了 $n$ 次小 batch 更新，不再等价。
- **没有除以 $n$**：累加后的梯度是大 batch 梯度的 $n$ 倍，相当于学习率放大了 $n$ 倍。
- **把 `loss` 张量本身累加起来**：会一直持有所有微批次的计算图，显存不会释放。用 `.item()`。
- 只有各微批次大小相同时，「除以 $n$」才严格等价；大小不同时应按样本数加权。

## 延伸

- **有效 batch**：真正的全局 batch 是

$$
B_{\text{eff}} = B_{\text{micro}} \times n \times W
$$

$B_{\text{micro}}$ 是每张卡的微批次大小，$n$ 是累积步数，$W$ 是数据并行的卡数。学习率调度、权重衰减等超参都按 $B_{\text{eff}}$ 来定。
- **省了什么、没省什么**：激活值只需要保留一个微批次，参数、梯度和优化器状态一份不少。它不增加额外的浮点运算，但微批次太小会让 GPU 利用不满，吞吐可能下降。
- **不严格等价的情况**：
  - **BatchNorm**：统计量是按微批次算的，不是按大 batch（见「归一化」专题）。
  - **批内负样本的对比损失**：每个微批次里的负样本变少了（见「损失函数」专题）。
  - **按 token 平均的损失 + padding**：各微批次的有效 token 数不同时，应该除以整个大 batch 的 token 总数，而不是简单除以 $n$。
- **和 DDP 配合**：DDP 默认每次 `backward()` 都会触发梯度的 all-reduce。累积时前 $n-1$ 个微批次应该放在 `model.no_sync()` 里，只在最后一个微批次同步，否则通信量白白放大 $n$ 倍。
- **别和流水线并行的 micro-batch 混淆**：流水线并行也会把 batch 切成微批次，但目的是让各个 stage 同时有活干，减少气泡（见「分布式训练」专题的 1F1B 一题）。
- **日志**：`loss.item()` 之后别忘了还原缩放，记录的是各微批次损失的平均，而不是缩放后的值。

## 面试追问

1. **梯度累积为什么等价于大 batch？**
   梯度对损失是线性的，而均值损失可以拆成各微批次均值损失的平均，所以对 $L_k / n$ 各自反向后累加，与对整个大 batch 的均值损失反向的结果相同。
2. **忘了除以 $n$ 会怎样？SGD 和 Adam 一样吗？**
   梯度被放大 $n$ 倍。SGD 里等价于学习率放大 $n$ 倍，很容易发散；Adam 对梯度整体尺度不敏感，更新基本不受影响，但梯度裁剪的阈值比较会失真，所以仍然要除。
3. **梯度累积和激活检查点都能省激活显存，区别是什么？**
   累积靠缩小每次前反向处理的样本数，不增加计算，不改变单样本的激活大小；检查点靠丢弃并重算中间激活，多花约三分之一的计算，样本数不变。两者可以叠加。
4. **哪些层在梯度累积下行为会变？**
   带 batch 统计量的层（BatchNorm），以及依赖 batch 内其他样本的损失（对比学习）。Dropout 等逐样本随机的层不受影响。
5. **梯度累积会让训练变快吗？**
   不会。它省的是显存，不是时间；单位样本的计算量没变。只有当它让你能在不开重计算、不换更小的模型的前提下达到目标 batch 时，才间接避免了更慢的方案。
