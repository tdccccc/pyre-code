## 背景

**消息传递神经网络**（MPNN，Gilmer 等 2017，用于预测分子性质）给出了 GNN 的统一框架：一层分三步：

1. **消息**（message）：每条边根据两端节点（和边本身）的特征算出一条消息
2. **聚合**（aggregate）：每个节点把收到的消息汇总
3. **更新**（update）：用自己的旧特征和汇总的消息算出新特征

GCN、GIN、GAT 都是它的特例，区别只在于这三个函数怎么选。MPNN 的一般形式还能利用**边特征**，比如分子中化学键的类型（单键、双键……）。

## 核心公式

**消息**：拼接接收节点 $i$、发送节点 $j$ 和边 $(i, j)$ 的特征，经过线性层和 ReLU：

$$
m_{ij} = \operatorname{ReLU}\bigl([\, x_i \,\Vert\, x_j \,\Vert\, e_{ij} \,]\, W_{\text{msg}}\bigr)
$$

**聚合**（求和，只对邻居）：

$$
\bar{m}_i = \sum_{j \in \mathcal{N}(i)} m_{ij} = \sum_{j} A_{ij}\, m_{ij}
$$

**更新**：

$$
x'_i = \operatorname{ReLU}\bigl([\, x_i \,\Vert\, \bar{m}_i \,]\, W_{\text{upd}}\bigr)
$$

**对应关系**：比如 GIN 就是消息 $m_{ij} = x_j$、聚合求和、更新 $\operatorname{MLP}((1+\epsilon)x_i + \bar{m}_i)$。

## 形状

用广播一次算出所有节点对的消息：

| 量 | 形状 |
| --- | --- |
| `X` | `(N, F)` |
| `E` | `(N, N, D_e)` |
| $x_i$ 沿列复制 | `(N, N, F)`，第 $(i, j)$ 个位置是 $x_i$ |
| $x_j$ 沿行复制 | `(N, N, F)`，第 $(i, j)$ 个位置是 $x_j$ |
| 拼接后 | `(N, N, 2F + D_e)` |
| 消息 | `(N, N, F_msg)` |
| 聚合（对 $j$ 求和） | `(N, F_msg)` |
| 更新输入 | `(N, F + F_msg)` |
| 输出 | `(N, F_out)` |

这种稠密写法需要 $O(N^2)$ 的显存；真实的大图会用边列表只计算存在的边。

## 用到的 PyTorch 操作

- `X.unsqueeze(1).expand(N, N, F)`：第 $i$ 行全是 $x_i$；`X.unsqueeze(0).expand(N, N, F)`：第 $j$ 列全是 $x_j$。`expand` 不复制数据。
- `torch.cat([...], dim=-1)`。
- `msgs * A.unsqueeze(-1)`：用邻接矩阵屏蔽非边，`(N, N, 1)` 广播到消息的最后一维。
- `.sum(dim=1)`：对发送方 $j$ 求和。

## 常见坑

- **忘了屏蔽非边**：在非边的位置，$x_i$、$x_j$ 照样非零，算出的消息也不为零，会被错误地加进聚合结果。只把边特征 `E` 置零是不够的，要在算出消息之后乘以 $A$。
- **拼接顺序**：$[x_i, x_j, e_{ij}]$，与 $W_{\text{msg}}$ 的行对应，顺序错了结果就不对。
- **求和维度错**：节点 $i$ 收到的消息在第 $i$ 行，沿 `dim=1`（$j$）求和。
- **更新时拼接顺序**：$[x_i, \bar{m}_i]$。
- 没有边的图：所有消息被屏蔽，聚合结果为零，仍应正常输出。
