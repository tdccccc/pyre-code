## 背景

**蒙特卡洛树搜索**（MCTS）是 AlphaGo 的核心算法。在 LLM 推理中，它被用来搜索推理路径：树的每个节点是一个部分推理（已经写下的若干步），子节点是接下来可能的一步，价值由验证器或奖励模型评估。

每一轮搜索包含四步：

1. **选择**：从根节点出发，按某个打分规则一路选子节点，直到叶子
2. **扩展**：为叶子生成新的子节点
3. **模拟**（rollout）：从新节点往下随机走到底，得到一个结果价值
4. **反向传播**：把这个价值沿路径传回，更新经过的每个节点的统计量

本题实现其中一层的「选择 → 模拟 → 更新」。

## 核心公式

**探索与利用的权衡**：只选当前价值最高的子节点（利用）可能错过被低估的选项；均匀尝试（探索）又浪费在明显不好的选项上。**UCB1** 打分把两者合起来：

$$
\operatorname{UCB}(i) = \underbrace{Q(i)}_{\text{利用}} + \underbrace{c \cdot \sqrt{\frac{\ln(N + 1)}{n_i + 1}}}_{\text{探索}}
$$

- $Q(i)$：子节点 $i$ 目前的平均价值
- $n_i$：子节点 $i$ 被访问的次数；$N$：父节点的访问次数
- $c$：探索常数，越大越倾向于探索

$n_i$ 越小，探索项越大，所以很少被访问的节点会得到加分。随着 $N$ 增大，$\ln N$ 增长很慢，而访问多的节点分母大，探索项逐渐变小。$c = 0$ 时退化为纯利用（贪心）。

**更新平均价值**：设新的模拟价值为 $v$，旧访问次数为 $n$，

$$
Q_{\text{new}} = \frac{Q_{\text{old}} \cdot n + v}{n + 1} = Q_{\text{old}} + \frac{v - Q_{\text{old}}}{n + 1}
$$

这正是 $n + 1$ 个样本的平均值，不需要保存所有历史价值。然后 $n \leftarrow n + 1$。

## 形状

`values`、`visit_counts` 都是 `(N,)`；`parent_visits` 是整数。返回选中的下标（`int`）和两个更新后的张量。

## 用到的 PyTorch 操作

- `torch.log`、`torch.sqrt`：参数要是浮点张量。`parent_visits` 是 Python 整数，先转成 `torch.tensor(..., dtype=torch.float32)`，或者用 `math.log`。
- `visit_counts.float()`：访问次数可能是整数张量。
- `t.argmax().item()`。
- `torch.rand(1).item()`：$[0, 1)$ 的随机数作为模拟结果。
- `t.clone()`：返回更新后的副本。

## 常见坑

- **对整数张量取 `log`**：会报错，先转浮点。
- **用更新后的访问次数算平均**：公式里的 $n$ 是**旧**的访问次数。
- **直接修改了输入张量**：应返回更新后的副本。
- **返回张量形式的下标**：要返回 Python `int`。
- 自检：未访问过的节点（$n_i = 0$）探索项最大，在价值相同时应被优先选中。

## 延伸

- **UCB1 的出处**：UCB1 来自多臂老虎机（Auer 等，2002），Kocsis 和 Szepesvári（2006）把它用到树的每个节点上，称为 **UCT**。标准形式是 $Q + c\sqrt{\ln N / n_i}$，$c=\sqrt{2}$ 时是原始版本，本题默认的 $1.414$ 就是 $\sqrt{2}$。本题用 $\ln(N+1)/(n_i+1)$，是为了避开 $n_i = 0$ 和 $N=0$ 时的除零或 $\ln 0$。
- **PUCT**：AlphaGo / AlphaZero 系列在探索项里乘上策略网络给出的先验概率 $P(a)$，形如 $Q + c\,P(a)\sqrt{N}/(1+n_a)$。先验高的动作更早被探索，对分支很多的问题更重要。公式对比见「奖励、评测与推理时搜索」专题。
- **用在 LLM 上要换什么**：节点是已写下的若干步推理；先验可以取语言模型对下一步的概率；评估用过程奖励模型、价值模型或最终答案的验证器，取代随机 rollout。本题的随机 `rand` 只是占位。
- **动作空间**：围棋每步几百个落子，LLM 每个 token 是整个词表，所以通常以「一步推理」（比如一句话或一段）为节点，每个节点采样若干候选来扩展。
- **价值的尺度要和 $c$ 匹配**：$Q$ 取值在 $[0,1]$ 时，$c$ 约为 $1$ 左右才合适；如果价值的量纲变了，探索项会被淹没或压过价值，需要重新调 $c$。
- **最终怎么选动作**：搜索结束后一般选**访问次数最多**的子节点，而不是平均价值最高的。
- **计算代价**：每次模拟都要调用大模型生成和评估。同一个前缀的 KV 缓存可以复用（见「推理服务」专题的前缀缓存），多条路径也可以批量并行评估。
- **搜索结果反过来训练模型**：AlphaZero 式的做法是把搜索得到的访问次数分布作为策略的训练目标，价值作为价值网络的目标。

## 面试追问

1. **UCB 为什么能平衡探索与利用？**
   价值项鼓励选当前最好的节点，探索项在访问次数少的节点上更大，所以被冷落的节点会逐渐被轮到。节点被访问的次数增加后探索项变小，而父节点的访问次数 $N$ 只以 $\ln N$ 的速度增大，所以每个节点都会被访问，访问频率又会偏向价值高的节点。
2. **UCT 和 PUCT 的区别？**
   UCT 对所有子节点一视同仁，探索项只与访问次数有关；PUCT 加入了策略网络的先验概率，先验高的动作优先探索。动作多、需要先验引导时选 PUCT。
3. **MCTS 用在 LLM 推理上，和围棋相比有哪些难点？**
   动作空间大（要以推理步为节点）；没有像胜负那样明确的中间价值，需要过程奖励模型或价值模型，而这类模型很难训练；每次评估的成本也高。
4. **搜索结束后为什么选访问次数最多的节点，而不是平均价值最高的？**
   访问次数多的节点估计更可靠；平均价值最高的可能只被访问了一两次，是噪声造成的。访问次数本身也已经把价值信息融进去了，因为价值高的节点会被更多地选中。
5. **MCTS 和 Best-of-N 比，各有什么利弊？**
   Best-of-N 实现简单、容易并行，但每个回答从头到尾独立生成，算力平均分配。MCTS 能把算力集中到有希望的中间步骤，但需要可靠的中间价值评估，实现和调参都更复杂，评估不准时反而不如 Best-of-N。
