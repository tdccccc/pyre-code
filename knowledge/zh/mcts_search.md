## 背景

**蒙特卡洛树搜索**（MCTS）是 AlphaGo 的核心算法。在 LLM 推理中，它被用来搜索推理路径：树的每个节点是一个部分推理（已经写下的若干步），子节点是接下来可能的一步，价值由验证器或奖励模型评估。

每一轮搜索包含四步：

1. **选择**：从根节点出发，按某个打分规则一路选子节点，直到叶子
2. **扩展**：为叶子生成新的子节点
3. **模拟**（rollout）：从新节点往下随机走到底，得到一个结果价值
4. **反向传播**：把这个价值沿路径传回，更新经过的每个节点的统计量

本题实现其中一层的「选择 → 模拟 → 更新」。

## 核心公式

**探索与利用的权衡**：只选当前价值最高的子节点（利用）可能错过被低估的选项；均匀尝试（探索）又浪费在明显不好的选项上。**UCB1** 打分把两者合起来：

$$
\operatorname{UCB}(i) = \underbrace{Q(i)}_{\text{利用}} + \underbrace{c \cdot \sqrt{\frac{\ln(N + 1)}{n_i + 1}}}_{\text{探索}}
$$

- $Q(i)$：子节点 $i$ 目前的平均价值
- $n_i$：子节点 $i$ 被访问的次数；$N$：父节点的访问次数
- $c$：探索常数，越大越倾向于探索

$n_i$ 越小，探索项越大，所以很少被访问的节点会得到加分。随着 $N$ 增大，$\ln N$ 增长很慢，而访问多的节点分母大，探索项逐渐变小。$c = 0$ 时退化为纯利用（贪心）。

**更新平均价值**：设新的模拟价值为 $v$，旧访问次数为 $n$，

$$
Q_{\text{new}} = \frac{Q_{\text{old}} \cdot n + v}{n + 1} = Q_{\text{old}} + \frac{v - Q_{\text{old}}}{n + 1}
$$

这正是 $n + 1$ 个样本的平均值，不需要保存所有历史价值。然后 $n \leftarrow n + 1$。

## 形状

`values`、`visit_counts` 都是 `(N,)`；`parent_visits` 是整数。返回选中的下标（`int`）和两个更新后的张量。

## 用到的 PyTorch 操作

- `torch.log`、`torch.sqrt`：参数要是浮点张量。`parent_visits` 是 Python 整数，先转成 `torch.tensor(..., dtype=torch.float32)`，或者用 `math.log`。
- `visit_counts.float()`：访问次数可能是整数张量。
- `t.argmax().item()`。
- `torch.rand(1).item()`：$[0, 1)$ 的随机数作为模拟结果。
- `t.clone()`：返回更新后的副本。

## 常见坑

- **对整数张量取 `log`**：会报错，先转浮点。
- **用更新后的访问次数算平均**：公式里的 $n$ 是**旧**的访问次数。
- **直接修改了输入张量**：应返回更新后的副本。
- **返回张量形式的下标**：要返回 Python `int`。
- 自检：未访问过的节点（$n_i = 0$）探索项最大，在价值相同时应被优先选中。
