## 背景

模型大到单张 GPU 放不下一层的权重时，就要把**一个矩阵切开**，分到多张卡上各算一部分，这叫**张量并行**。Megatron-LM 给出了 Transformer MLP 的经典切法：第一层按**列**切，第二层按**行**切，整个 MLP 只需要在最后做一次通信。

## 核心公式

MLP：$Y = \operatorname{GELU}(X W_1)\, W_2$，$W_1 \in \mathbb{R}^{d \times d_{ff}}$，$W_2 \in \mathbb{R}^{d_{ff} \times d}$，切成 $n$ 份。

**第一层按列切**：

$$
W_1 = \bigl[\, W_1^{(1)} \ \ W_1^{(2)} \ \cdots \ W_1^{(n)} \,\bigr]
\quad\Rightarrow\quad
X W_1 = \bigl[\, X W_1^{(1)} \ \ \cdots \ \ X W_1^{(n)} \,\bigr]
$$

每张卡拿到完整的 $X$，算出隐藏层的一段。GELU 是**逐元素**的，所以可以各自在本地算：

$$
H^{(i)} = \operatorname{GELU}\bigl(X W_1^{(i)}\bigr)
$$

**第二层按行切**：

$$
W_2 = \begin{pmatrix} W_2^{(1)} \\ \vdots \\ W_2^{(n)} \end{pmatrix}
\quad\Rightarrow\quad
H W_2 = \bigl[\, H^{(1)} \ \cdots \ H^{(n)} \,\bigr] \begin{pmatrix} W_2^{(1)} \\ \vdots \\ W_2^{(n)} \end{pmatrix} = \sum_{i=1}^{n} H^{(i)} W_2^{(i)}
$$

这是分块矩阵乘法。每张卡算出一个完整形状的部分和，最后做一次 **all-reduce（求和）**：

$$
Y = \sum_{i=1}^{n} \underbrace{H^{(i)} W_2^{(i)}}_{\text{第 } i \text{ 张卡的部分结果}}
$$

**为什么不能反过来切**：如果第一层按行切，每张卡只得到 $X W_1$ 的一个部分和，必须先求和才能过 GELU，因为

$$
\operatorname{GELU}(a + b) \ne \operatorname{GELU}(a) + \operatorname{GELU}(b)
$$

这样就要多一次通信。

## 形状

| 量 | 形状 |
| --- | --- |
| `x` | `(B, d_model)` |
| 每个 $W_1^{(i)}$ | `(d_model, d_ff / n)` |
| 每个 $H^{(i)}$ | `(B, d_ff / n)` |
| 每个 $W_2^{(i)}$ | `(d_ff / n, d_model)` |
| 每个部分和、最终输出 | `(B, d_model)` |

## 用到的 PyTorch 操作

- `nn.ParameterList([nn.Parameter(...), ...])`：存放一组参数，会被正确注册。普通 Python 列表里的参数不会被注册。
- `@` 矩阵乘、`torch.erf`（精确 GELU）。
- 用一个循环模拟 $n$ 张卡，把部分结果相加模拟 all-reduce。

## 常见坑

- **先求和再 GELU**，或者对每个分片 GELU 之后再整体 GELU：GELU 只能在第一层之后、各分片本地做一次。
- **把部分结果拼接**（concat）：第二层的部分结果形状都是完整的 `(B, d_model)`，要**相加**。
- **切错方向**：$W_1$ 切的是输出维 $d_{ff}$（列），$W_2$ 切的是输入维 $d_{ff}$（行），两者的切法必须对应。
- **用 Python 列表存分片参数**：参数不会被注册，优化器和测试都找不到。

## 延伸

- **反向也要通信**：Megatron 把通信写成一对共轭算子，$f$ 前向是恒等、反向是 all-reduce；$g$ 前向是 all-reduce、反向是恒等。列并行层的输入处放 $f$：每张卡只拿到 $dX$ 的一个部分和，反向要求和；行并行层的输出处放 $g$：前向求部分和，反向时各卡拿到的 $dY$ 相同，无需通信。所以一个 MLP 前向 $1$ 次、反向 $1$ 次 all-reduce。
- **注意力的切法**：QKV 投影按头做列切（每卡负责一部分头，头与头独立，不需要通信），输出投影按行切，和 MLP 完全同构。因此一个 Transformer 层前向 $2$ 次、反向 $2$ 次 all-reduce，共 $4$ 次；开了重计算则前向多重算一遍，还要再多 $2$ 次。TP 度必须整除头数；用 GQA 时若 KV 头数少于 TP 度，KV 头要在多卡间复制。
- **SwiGLU 的切法**：gate 和 up 两个投影都按列切，并且要按相同方式切，因为它们逐元素相乘；down 按行切。通信次数不变。
- **偏置的位置**：行并行层的偏置只能在 all-reduce **之后**加一次，放进每个分片的部分和里会被加 $t$ 次。
- **通信在关键路径上**：all-reduce 的输入是刚算完的矩阵乘结果，输出马上被下一步使用，很难藏到别的计算后面。每层一次的张量大小是 $b \cdot s \cdot h$，与 token 数成正比，不能靠增大 batch 摊薄。取 $h=4096$、$n=4096$ 个 token、$t=8$，一层前后向 $4$ 次 all-reduce 每卡约发送 $235$ MB，NVLink 上约 $0.5$ ms，与该层约 $1.6$ ms 的计算相比不可忽略；换成机间网络就会反超计算（量级估算，详见「分布式训练」专题）。
- **序列并行（Megatron-SP）**：LayerNorm、dropout、残差这些逐 token 的区域在 TP 下每卡都重复一份。序列并行把这些区域沿序列维切开：把 all-reduce 拆成 reduce-scatter 和 all-gather，前者放在行并行层之后，后者放在下一个列并行层之前，通信量不变，却把这些区域的激活降为 $1/t$。
- **TP 度的限制**：度数越大，每卡的矩阵越小，GPU 利用率下降，通信占比上升，而且受头数整除的约束。实践里 TP 度一般不超过一台机器的卡数。

## 面试追问

1. **为什么第一层按列切、第二层按行切？反过来或都按列切可以吗？**
   第一层按列切，每卡得到隐藏层的一段，GELU 逐元素，可以在本地做，不需要通信；第二层按行切，正好吃这一段，算出完整形状的部分和，最后一次 all-reduce。第一层若按行切，每卡只有部分和，要先求和才能过 GELU，多一次通信；两层都按列切，第二层的输入又要先 all-gather 才能用。
2. **一个 Transformer 层的 TP 需要几次通信？**
   前向 $2$ 次 all-reduce（注意力输出投影后、MLP 第二层后），反向 $2$ 次，共 $4$ 次，每次的张量大小是 $b \cdot s \cdot h$。
3. **TP 为什么一般只在机内用？**
   通信频繁（每层 $4$ 次）、量大（与 token 数成正比）、在关键路径上。NVLink 的带宽大约是机间网卡的 $10$ 倍量级，跨机后通信时间会超过计算。
4. **注意力层怎么做 TP？对头数有什么要求？**
   按头把 Q、K、V 投影列切，每卡算自己那几个头的注意力，输出投影行切，再 all-reduce。所以 TP 度要整除头数；GQA 的 KV 头少于 TP 度时，KV 头在多卡间复制。
5. **序列并行解决了 TP 的什么问题？通信量会变吗？**
   TP 不切 LayerNorm、dropout 等区域的激活，每卡重复一份。序列并行把这些区域沿序列切开，all-reduce 换成 reduce-scatter 加 all-gather，两者的总量相同，所以通信量不变，只多省了激活显存。
