## 背景

Transformer 处理的是 token 序列。**Vision Transformer**（ViT，论文标题是 *An Image is Worth 16x16 Words*）的做法很直接：把图像切成不重叠的小方块（patch），每块展平成一个向量，再用线性层投影成嵌入，这样一张图像就变成了一个 token 序列。

## 核心公式

图像尺寸 $H \times W$、通道数 $C$，块大小 $P$：

$$
N = \frac{H}{P} \cdot \frac{W}{P}
$$

每块展平后的长度是 $C \cdot P \cdot P$，投影为 $d$ 维嵌入：

$$
z_n = E\, \operatorname{flatten}(\text{patch}_n) + b,
\qquad E \in \mathbb{R}^{d \times C P^2}
$$

**例子**：$224 \times 224$ 的 RGB 图像，$P = 16$：$N = 14 \times 14 = 196$ 个块，每块 $3 \times 16 \times 16 = 768$ 维。

**等价于卷积**：这个操作和「卷积核大小 = 步长 = $P$、输出通道为 $d$」的卷积完全等价。很多实现直接用 `nn.Conv2d(C, d, kernel_size=P, stride=P)`。

## 形状

关键在于把每个块的像素正确地聚到一起：

| 步骤 | 形状 |
| --- | --- |
| 输入 | `(B, C, H, W)` |
| 拆分高和宽 | `(B, C, n_h, P, n_w, P)`，$H = n_h P$，$W = n_w P$ |
| 调整维度顺序 | `(B, n_h, n_w, C, P, P)` |
| 合并 | `(B, n_h · n_w, C · P · P)` |
| 线性投影 | `(B, N, embed_dim)` |

块按行优先排列：先第一行的所有块，从左到右，再第二行。每块内部按通道、行、列的顺序展平。

## 用到的 PyTorch 操作

- `x.reshape(B, C, n_h, P, n_w, P)`：把 $H$ 拆成「第几块 × 块内第几行」，$W$ 同理。
- `x.permute(0, 2, 4, 1, 3, 5)`：把两个块编号维放到前面，块内维度放到后面。
- `.reshape(B, N, C * P * P)`：`permute` 之后内存不连续，用 `reshape` 而不是 `view`。
- `nn.Linear(C * P * P, embed_dim)`。

## 常见坑

- **不做 `permute` 直接 `reshape(B, N, C·P·P)`**：形状对了，但每个「块」里混进了不同位置的像素。
- **展平顺序不对**：要按 $(C, P, P)$ 的顺序展平（与下面的卷积等价对应）。测试用单通道图像，拿手动切出的块逐块比对 `self.proj` 的输出，所以块的排列顺序和块内像素顺序必须正确。
- **投影层的属性名**：测试会通过 `self.proj`（`nn.Linear`）取权重和偏置。
- **忘了保存 `self.num_patches`**：测试会访问这个属性。
- **`permute` 后用 `view` 报错**：换成 `reshape`，或先 `.contiguous()`。

## 延伸

- **序列长度与块大小**：块大小 $P$ 越小，token 越多，信息越细，但注意力的代价按 $N^2$ 增长。$224\times224$ 的图像，$P=32$ 得到 $49$ 个 token，$P=16$ 得到 $196$ 个，$P=8$ 得到 $784$ 个。$P$ 减半，$N$ 变成 $4$ 倍，注意力的计算量变成 $16$ 倍。ViT 的命名里 `ViT-B/16` 的 `/16` 就是块大小。
- **为什么不把每个像素当 token**：$224\times224$ 有 $50176$ 个像素，注意力矩阵有 $50176^2 \approx 2.5\times10^9$ 项（每头每层），放不下也算不起。切块是在序列长度和细节之间的折中。
- **参数量**：投影层 $d\cdot CP^2 + d$ 个参数，$d=768$、$C=3$、$P=16$ 时为 $768\times768 + 768 = 590592$。
- **图像尺寸要能被 $P$ 整除**：否则最右、最下的像素放不进完整的块。本题的测试输入都能整除；用卷积实现时，多出来的边缘像素会被悄悄丢掉。
- **位置信息**：patch embedding 之后还要加位置嵌入（ViT 原文用可学习的一维位置嵌入），否则 Transformer 对 token 的顺序一无所知，把 patch 打乱输出只是跟着打乱。位置编码的各种方案见「位置编码」专题。本题只有切块和投影，不含位置嵌入和 CLS token（后者在 ViT Transformer Block 一题的输入里出现）。
- **用卷积实现**：`nn.Conv2d(C, d, P, stride=P)` 的权重形状是 `(d, C, P, P)`，展平后就是 $E$，展平顺序也是 $(C, P, P)$，与本题一致。卷积的输出是 `(B, d, n_h, n_w)`，再 `flatten(2).transpose(1, 2)` 得到 `(B, N, d)`。这样不用手动 `permute`，也方便加载按卷积保存的预训练权重。
- **一次线性投影的局限**：每个块只做一次线性投影，块内的局部结构要靠后面的注意力层去学。有工作用几层小卷积（conv stem）代替这一步，据报告训练更稳，这是 CNN 与 ViT 混合设计的一种思路（见「卷积与视觉」专题）。

## 面试追问

1. **$224\times224$ 的 RGB 图像，块大小 $16$，嵌入维度 $768$：有多少个 token？投影层多少参数？**
   $14\times14 = 196$ 个 token，每块展平后 $3\times16\times16 = 768$ 维。投影层 $768\times768 + 768 = 590592$ 个参数。
2. **patch embedding 和哪种卷积等价？**
   核大小和步长都等于 $P$、输出通道为嵌入维度的卷积。块互不重叠，每块一次线性投影；很多实现直接用 `nn.Conv2d`。
3. **块大小变小有什么影响？**
   token 更多，细节更多，但注意力代价按 $N^2$ 增长：$P$ 减半，计算量大约变成 $16$ 倍（线性层和 MLP 的代价则是 $4$ 倍）。需要在精度和算力之间取舍。
4. **为什么 ViT 需要位置嵌入？输入分辨率变了怎么办？**
   注意力对 token 顺序不敏感，patch 的位置信息必须显式加进去。微调时分辨率变大，token 数变多，预训练的位置嵌入个数对不上，常见做法是把它按二维网格插值到新的大小。
5. **为什么不直接用像素当 token？**
   序列太长，注意力矩阵随长度平方增长，$224\times224$ 的图像有五万个像素，在计算和显存上都不现实。
