## 背景

推理时的 KV 缓存是长上下文的主要显存开销。几种注意力变体每个 token、每层要缓存的元素数（$H$ 个头，每头 $d_h$ 维）：

| 方法 | 每 token 每层缓存 |
| --- | --- |
| MHA | $2\, H\, d_h$ |
| GQA（$H_{kv}$ 个 KV 头） | $2\, H_{kv}\, d_h$ |
| **MLA** | $d_c$（一个潜在向量） |

**MLA**（Multi-head Latent Attention，DeepSeek-V2/V3）不缓存 K、V 本身，而是缓存一个**低维潜在向量** $c$，需要时再从它「解压」出 K 和 V。DeepSeek-V2 中 $H = 128$、$d_h = 128$，MHA 每层要缓存 $32768$ 个数，而 MLA 的 $d_c = 512$，缩小了几十倍。

## 核心公式

**压缩**（down-projection）：

$$
c = X\, W_{\text{dkv}},\qquad W_{\text{dkv}} \in \mathbb{R}^{D \times d_c}
$$

**解压**（up-projection），K、V 共享同一个潜在向量：

$$
K = c\, W_{\text{uk}},\qquad V = c\, W_{\text{uv}},\qquad W_{\text{uk}}, W_{\text{uv}} \in \mathbb{R}^{d_c \times H d_h}
$$

**查询**：$Q = X\, W_q$。然后拆成 $H$ 个头，做普通的缩放点积注意力。

**低秩**：$K = X W_{\text{dkv}} W_{\text{uk}}$，这个 $D \times H d_h$ 的投影矩阵的秩不超过 $d_c$，这就是「低秩压缩」的含义。

**吸收技巧**（推理时的关键）：第 $h$ 个头的注意力分数

$$
q_h^{\top} k_h = q_h^{\top} \bigl(W_{\text{uk}}^{(h)}\bigr)^{\top} c = \Bigl(W_{\text{uk}}^{(h)}\, q_h\Bigr)^{\top} c
$$

可以把 $W_{\text{uk}}$ 并入查询一侧，直接和缓存的 $c$ 算点积，根本不需要显式解压出 K。$W_{\text{uv}}$ 同理可以并入输出投影。（实际 DeepSeek 的 MLA 还有一条单独的 RoPE 分支，本题不涉及。）

## 形状

| 量 | 形状 |
| --- | --- |
| `X` | `(B, S, D)` |
| 潜在向量 $c$ | `(B, S, kv_rank)` |
| $Q$、$K$、$V$ | `(B, S, H·d_h)` → 拆头为 `(B, H, S, d_h)` |
| 注意力分数 | `(B, H, S, S)` |
| 输出 | `(B, S, H·d_h)` |

$d_h$ 可以从 `W_q.shape[1] // num_heads` 得到。

## 用到的 PyTorch 操作

- `@` 矩阵乘。
- `t.view(B, S, H, d_h).transpose(1, 2)` 拆头；`transpose(1, 2).reshape(B, S, -1)` 合头。
- `torch.softmax`。

## 常见坑

- **K、V 用了不同的潜在向量**：两者都从同一个 $c$ 解压。
- **查询也经过压缩**：本题的 $Q$ 直接由 $X$ 投影。（DeepSeek-V2 也会压缩查询，但那是为了省训练时的激活，不影响 KV 缓存。）
- **拆头的 `view` 顺序**：先 `(B, S, H, d_h)` 再交换维度。
- **缩放因子**：$\sqrt{d_h}$，每个头的维度。

## 延伸

- **RoPE 与矩阵吸收的冲突**：RoPE 会按位置旋转 $q$ 和 $k$，使分数只依赖相对位置。带上旋转 $R$ 之后，分数里是

$$
q_i^{\top} R_{j-i}\, \bigl(W_{\text{uk}}^{\top} c_j\bigr)
$$

  位置相关的 $R_{j-i}$ 夹在 $q_i$ 和 $W_{\text{uk}}$ 之间，$W_{\text{uk}}$ 就无法提前并入查询一侧。DeepSeek 的做法是**解耦 RoPE**：每个头的 $q$、$k$ 拆成两部分，一部分不带位置，走潜向量，可以吸收；另一部分很小，带 RoPE，其中 $k$ 的这一部分被所有头共享、单独缓存（位置编码见「位置编码」专题）。
- **真实的缓存大小**：每 token 每层缓存 $d_c + d_h^R$ 个数，$d_h^R$ 是带 RoPE 的那一小段的维度。DeepSeek-V2 / V3 中是 $512 + 64 = 576$。作为对比，$d_h = 128$ 时 GQA 缓存 $2 H_{kv} d_h$，令 $2 H_{kv} \cdot 128 = 576$ 得 $H_{kv} = 2.25$，所以相当于大约 $2.25$ 个 KV 头。
- **吸收后像 MQA**：吸收后，所有头共用缓存里同一个 $c$，每个头的分数是 $d_c$ 维（而不是 $d_h$ 维）的点积。算得多了一些，但解码本来就受限于访存，缓存小了很多，反而划算。训练和预填充则是计算受限，更常见的做法是显式解压出 K、V，按普通多头注意力来算。
- **训练时不省**：训练仍要得到每个头的完整 K、V，MLA 省的是推理时的缓存，不是训练的计算量。
- **与 GQA 的区别**：GQA 靠**减少 KV 头数**省缓存，同组的头看到的是完全相同的 K、V；MLA 保留每个头独立的 K、V，靠它们来自低秩空间这一点压缩，表达力更强，实现也更复杂。

## 面试追问

1. **MLA 缓存了什么？比 MHA 小多少？**
   缓存低维的潜向量 $c$（再加一小段带 RoPE 的 $k$），而不是每个头的完整 K、V。MHA 每 token 每层缓存 $2 H d_h$ 个数，DeepSeek-V2 中是 $32768$，MLA 是 $512 + 64$，相差大约几十倍。
2. **什么是低秩压缩？为什么可行？**
   $K = X W_{\text{dkv}} W_{\text{uk}}$，投影矩阵的秩不超过 $d_c$。这等于假设 K、V 所在的子空间维度远低于 $H d_h$，各头的 K、V 之间有很多冗余，先压到 $d_c$ 维再还原，损失不大。
3. **吸收技巧是什么？**
   $q^{\top} k = q^{\top} W_{\text{uk}}^{\top} c = (W_{\text{uk}} q)^{\top} c$，把上投影并入查询，直接和缓存的 $c$ 算点积，不需要还原出 K。$W_{\text{uv}}$ 同理，可以并入输出投影。
4. **为什么 RoPE 和 MLA 冲突？怎么解决？**
   RoPE 的旋转矩阵和位置有关，夹在 $q$ 与 $W_{\text{uk}}$ 之间，使 $W_{\text{uk}}$ 无法并入查询。解法是解耦：再拆出一小段专门带 RoPE，并在所有头之间共享，缓存里多存这一段。
5. **MLA 能加快训练吗？**
   不能直接加快。训练需要算出完整的 K、V，MLA 压缩的是推理时的 KV cache。
