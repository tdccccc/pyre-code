## 背景

语言模型容易陷入重复：同一个词、同一句话反复出现。推理引擎在采样前会对 logits 做一系列处理（logits processor），常见的有：

- **重复惩罚**（repetition penalty，CTRL 论文提出）：出现过的 token 一律降低概率
- **频率惩罚**、**存在惩罚**（OpenAI API 中的 `frequency_penalty`、`presence_penalty`）：按出现次数或是否出现扣分
- **温度**
- **min-p 过滤**：去掉相对最可能 token 而言概率太低的 token

## 核心公式

**重复惩罚**（$\theta > 1$，每个出现过的不同 token 只做一次）：

$$
z_t \leftarrow
\begin{cases}
z_t / \theta, & z_t > 0 \\
z_t \cdot \theta, & z_t \le 0
\end{cases}
$$

为什么要分正负：目的是**降低** logit。正数除以 $\theta$ 变小；负数如果也除以 $\theta$ 会变得更接近 $0$，反而**升高**了，所以负数要乘以 $\theta$。

**频率与存在惩罚**（$c_t$ 为 token $t$ 已出现的次数）：

$$
z_t \leftarrow z_t - \alpha_{\text{freq}} \cdot c_t - \alpha_{\text{pres}} \cdot \mathbb{1}[c_t > 0]
$$

频率惩罚随次数累加，存在惩罚只要出现过就扣一次。

**温度**：$z \leftarrow z / T$，然后 $p = \operatorname{softmax}(z)$。

**min-p**：保留相对于最大概率不太小的 token，再重新归一化：

$$
\text{保留 } i \iff p_i \ge p_{\min} \cdot \max_j p_j
$$

和 top-p 相比，min-p 的阈值随模型的「信心」自动调整：最大概率很高（模型很确定）时阈值高，砍掉更多；分布平坦时阈值低，保留更多候选。

**顺序**：惩罚 → 温度 → softmax → min-p。惩罚作用于温度缩放**之前**的 logits。

## 用到的 Python / PyTorch 工具

- `collections.Counter(prev_tokens)`：统计每个 token 出现的次数，键就是去重后的 token。
- `logits.clone()`：先复制，避免修改调用方的张量。
- 用 token 列表做高级索引：`logits[ids]` 取出、`logits[ids] = vals` 写回。
- `torch.where(cond, a, b)`：按条件逐元素选择，适合做分正负的惩罚和 min-p 过滤。

## 常见坑

- **重复出现的 token 被重复惩罚**：重复惩罚对每个**不同**的 token 只做一次；次数只影响频率惩罚。
- **存在惩罚乘了次数**：存在惩罚与次数无关。
- **负 logit 也用除法**：会让该 token 概率上升。
- **先温度后惩罚**：顺序不同结果不同，测试会检查。
- **min-p 边界**：恰好等于阈值的保留，只去掉严格小于阈值的。
- **原地修改了输入**的 `logits`。

## 延伸

- **加性惩罚等价于概率乘一个系数**：从 logit 里减 $a$，相当于未归一化概率乘以 $e^{-a}$。所以频率惩罚是出现 $c$ 次就乘以 $e^{-\alpha c}$，随次数指数级压低；存在惩罚是一次性的固定倍数。
- **乘性与加性的区别**：重复惩罚的效果取决于 logit 本身的大小——$|z|$ 越大，改变量 $|z|(1 - 1/\theta)$ 或 $|z|(\theta - 1)$ 越大，而且不会把 logit 的正负翻转。加性惩罚的力度则和 logit 大小无关。
- **作用范围因引擎而异**：例如 vLLM 的重复惩罚同时看提示词和已生成的 token，频率、存在惩罚只看已生成部分。接口名字相同，覆盖的 token 范围不一定相同。
- **为什么惩罚在温度之前**：先惩罚再除以 $T$，惩罚的力度也跟着被 $T$ 缩放；反过来则惩罚是在缩放后的 logits 上扣固定的量。同样的参数就是两种效果，所以顺序必须固定，这也是测试检查顺序的原因。
- **min-p 与温度配合**：min-p 作用在已经做过温度缩放的概率上，门槛是相对最大概率的比例。温度调高让分布变平坦，需要靠 min-p 把长尾里的 token 砍掉，两者常一起使用。
- **其他抑制重复的手段**：Hugging Face 提供 `no_repeat_ngram_size`，直接禁止重复出现已有的 n-gram；还可以通过 `logit_bias` 对指定 token 手动加偏置。它们和本题的惩罚是互补的。
- **更多的 logits 处理**：结构化输出会在这里把不合法的 token 的 logit 设为 $-\infty$（如 JSON 语法约束）。这些处理器和本题一样，都是在采样前串成一条链依次改写 logits。

## 面试追问

1. **重复惩罚、频率惩罚、存在惩罚有什么区别？**
   重复惩罚是乘性的，出现过就缩一次，与次数无关；频率惩罚是加性的，随出现次数线性累加；存在惩罚是加性的，出现过就减一次。
2. **重复惩罚为什么要区分 logit 的正负？**
   要让 logit 变小。正数除以 $\theta > 1$ 变小，负数除以 $\theta$ 会变得更接近 $0$，等于变大，所以负数要乘以 $\theta$。
3. **惩罚为什么要放在温度之前？**
   这是约定，不是数学上的必然。惩罚改的是原始 logits，温度再整体缩放；反过来则惩罚的力度不再受 $T$ 影响。两种顺序结果不同，要和所用的引擎保持一致。
4. **min-p 和 top-p 有什么区别？**
   top-p 看累积概率，min-p 看单个 token 相对最大概率的比例。模型很确定时，min-p 的门槛高、砍得多；分布平坦时门槛低、保留得多，在高温度下更不容易放进长尾里的杂词。
5. **惩罚参数设置过大会有什么问题？**
   合理的重复会被压制：代码里反复出现的变量名、数学里的符号、需要原样引用的内容。模型被迫选别的词，可能不通顺甚至出错。所以通常取接近中性的小值。
