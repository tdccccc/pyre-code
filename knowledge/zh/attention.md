## 背景

注意力机制让序列中的每个位置去「查询」其他位置，按相关程度加权汇总信息。可以把它想成一次软性的字典查找：

- **Query（查询）** $q$：我想找什么
- **Key（键）** $k$：每个位置「我有什么」的标签
- **Value（值）** $v$：每个位置真正提供的内容

用 $q$ 和每个 $k$ 的相似度决定从每个 $v$ 取多少。

## 核心公式

$$
\operatorname{Attention}(Q, K, V) = \operatorname{softmax}\!\left(\frac{Q K^{\top}}{\sqrt{d_k}}\right) V
$$

拆成三步：

1. **打分**：$S = Q K^{\top} / \sqrt{d_k}$，$S_{ij} = q_i \cdot k_j / \sqrt{d_k}$ 表示第 $i$ 个查询和第 $j$ 个键的相似度（点积）。
2. **归一化**：$A = \operatorname{softmax}(S)$，对每一行（每个查询）做 softmax，$\sum_j A_{ij} = 1$。
3. **加权求和**：$O = A V$，即 $o_i = \sum_j A_{ij}\, v_j$。

**为什么除以 $\sqrt{d_k}$**：设 $q, k$ 的各分量独立、均值 $0$、方差 $1$，则

$$
\operatorname{Var}(q \cdot k) = \operatorname{Var}\!\left(\sum_{t=1}^{d_k} q_t k_t\right) = d_k
$$

维度越大，点积的数值越大，softmax 会变得极其尖锐（几乎变成 one-hot），梯度接近 $0$。除以标准差 $\sqrt{d_k}$ 把方差拉回 $1$。

## 形状

| 量 | 形状 |
| --- | --- |
| $Q$ | `(B, S_q, D)` |
| $K$ | `(B, S_k, D)` |
| $V$ | `(B, S_k, D_v)` |
| $Q K^{\top}$、$A$ | `(B, S_q, S_k)` |
| 输出 $A V$ | `(B, S_q, D_v)` |

$S_q$ 和 $S_k$ 可以不相等（交叉注意力：查询来自一个序列，键值来自另一个）。softmax 沿最后一维 $S_k$ 做，也就是每个查询在所有键上归一化。

## 用到的 PyTorch 操作

- `K.transpose(1, 2)` 或 `K.transpose(-2, -1)`：交换最后两维，得到 `(B, D, S_k)`。
- `torch.bmm(a, b)`：批量矩阵乘，`(B, n, m) @ (B, m, p) → (B, n, p)`；`@` / `torch.matmul` 也可以。
- `torch.softmax(x, dim=-1)`。
- `K.size(-1)` 取 $d_k$，`math.sqrt` 开方。

## 常见坑

- **转置了错误的维度**：`K.T` 对三维张量会把所有维度倒过来，变成 `(D, S_k, B)`。要只交换最后两维。
- **softmax 方向错了**：沿 `dim=-1`（键的方向）归一化。沿 `dim=1` 归一化，形状照样对得上，但结果是错的。
- **缩放因子写错**：除以 $\sqrt{d_k}$，不是 $d_k$；$d_k$ 是 Q/K 的特征维，不是序列长度。

## 延伸

- **加权平均的视角**：$o_i = \sum_j A_{ij}\, v_j$，权重非负且和为 $1$，所以每个输出都落在 $v_1, \dots, v_{S_k}$ 的凸包里。注意力只能「挑选并混合」已有的 $v$，要产生新的特征，靠的是后面的线性层和 MLP。
- **Q、K、V 从哪来**：本题把 $Q$、$K$、$V$ 直接作为输入。网络里它们由同一个输入 $X$ 经三个不同的线性投影得到：$Q = X W_Q$，$K = X W_K$，$V = X W_V$（见「多头注意力」一题）。
- **代价**：打分和加权求和各是一次矩阵乘，合计约

$$
4\, S_q\, S_k\, D \ \text{FLOPs}
$$

  朴素实现还要存下 $S_q \times S_k$ 的分数矩阵和权重矩阵。序列长度翻倍，计算和显存都变成 $4$ 倍。避免把它写进显存的做法见「IO 感知 kernel」专题。
- **对顺序不敏感**：把 $K$、$V$ 的行同时打乱，输出不变；把 $Q$ 的行打乱，输出的行跟着打乱。注意力本身不知道位置，所以需要位置编码（见「位置编码」专题）。
- **屏蔽 padding**：batch 里的序列长短不一时，对补齐出来的键，在 softmax 之前把分数填成 $-\infty$。更一般的掩码见「因果自注意力」一题。
- **实际调用**：PyTorch 提供了 `F.scaled_dot_product_attention(q, k, v, attn_mask=None, is_causal=False)`，内部会选择融合 kernel。

## 面试追问

1. **为什么 $Q$ 和 $K$ 要用不同的投影，而不是直接拿 $X X^{\top}$？**
   共用同一个投影时，分数矩阵是对称的，且 token 和自己的点积往往最大，注意力会偏向自己。分开投影后，「$i$ 在找什么」和「$j$ 提供什么」是两个独立的子空间，$i$ 关注 $j$ 不要求 $j$ 也关注 $i$。
2. **点积注意力和加性注意力有什么区别？**
   加性注意力用一个小的前馈网络给 $(q, k)$ 打分，点积注意力直接做内积。两者理论复杂度相近，但点积注意力就是矩阵乘法，在硬件上快得多、省空间。Transformer 的论文观察到，不缩放时 $d_k$ 较大的话加性注意力更好，于是给点积加上了 $1/\sqrt{d_k}$ 的缩放。
3. **序列长度翻倍，注意力的计算量和显存怎么变？**
   分数矩阵从 $S^2$ 变成 $(2S)^2$，计算和（朴素实现的）显存都是 $4$ 倍。这是长上下文的核心瓶颈，也是滑动窗口、线性注意力、FlashAttention 各自从不同角度要解决的问题。
4. **把 $K$ 和 $V$ 的行同时打乱，输出变吗？**
   不变。注意力对键值集合是置换不变的，位置信息必须靠位置编码额外注入。
5. **自注意力和交叉注意力有什么区别？**
   区别只在输入来源：自注意力的 $Q$、$K$、$V$ 来自同一个序列，交叉注意力的 $K$、$V$ 来自另一个序列，$S_q$ 与 $S_k$ 可以不等。公式完全一样。
