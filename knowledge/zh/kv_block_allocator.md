## 背景

早期推理系统给每个请求按**最大长度**预留一段连续的 KV 缓存，但大多数请求生成不到最大长度，显存大量浪费；不同长度的请求来来去去，还会留下碎片。vLLM 借鉴操作系统的**分页**：把 KV 缓存切成固定大小的**物理块**，按需分配，用一张表记录每个序列用了哪些块。每个序列最多浪费最后一块里没填满的部分。

块还可以在序列之间**共享**：

- **并行采样**：一个提示生成多个回答，提示部分的 KV 完全相同
- **束搜索**：多条候选共享相同的前缀

共享靠**引用计数**管理；某个序列要往共享块里写新内容时，先复制一份再写，即**写时复制**（copy-on-write，CoW）。

## 核心概念

**引用计数**：块 $b$ 的引用计数 $\text{ref}(b)$ = 当前持有它的序列数。不变式：

$$
\text{块 } b \text{ 空闲} \iff \text{ref}(b) = 0 \iff b \in \text{空闲池}
$$

| 操作 | 效果 |
| --- | --- |
| `allocate()` | 取最小的空闲块，$\text{ref} \leftarrow 1$ |
| `fork(b)` | 又一个序列共享 $b$：$\text{ref}(b) \mathrel{+}= 1$ |
| `free(b)` | 一个持有者放弃 $b$：$\text{ref}(b) \mathrel{-}= 1$，减到 $0$ 时回到空闲池 |
| `copy_on_write(b)` | 见下 |

**写时复制**：

- $\text{ref}(b) = 1$：只有自己在用，直接写，返回 $b$
- $\text{ref}(b) > 1$：分配一个新块 $b'$，自己改用 $b'$；$b$ 少了一个持有者，$\text{ref}(b) \mathrel{-}= 1$，返回 $b'$

**最小堆**：要求每次分配「当前最小的空闲编号」。最小堆支持 $O(\log n)$ 的插入和取最小值，比每次排序或线性扫描都快。`list(range(n))` 本身已经满足堆的性质，可以直接用。

## 用到的 Python 工具

- `heapq.heappop(h)`、`heapq.heappush(h, x)`：最小堆。
- 一个列表 `refs = [0] * n` 存引用计数。
- `raise RuntimeError(...)`、`raise ValueError(...)`。

## 常见坑

- **写时复制失败时状态被改了**：如果没有空闲块，要在修改任何引用计数**之前**抛异常。先分配，成功后再给旧块减引用。
- **重复释放没有报错**：对引用计数为 $0$ 的块做 `free`、`fork`、`copy_on_write` 都要抛 `ValueError`。
- **引用计数没减到 $0$ 就放回空闲池**：其他序列还在用这个块。
- **`copy_on_write` 在 $\text{ref} = 1$ 时也分配了新块**：浪费，且测试会检查返回的是同一个编号。
- **用普通列表取最小值**：`min()` + `remove()` 是 $O(n)$，结果对但慢。
