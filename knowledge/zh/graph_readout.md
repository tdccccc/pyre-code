## 背景

有些任务要对**整张图**做预测，比如判断一个分子是否有毒。GNN 层输出的是每个节点的表示，还需要一个**读出**（readout，也叫图池化）操作，把一张图所有节点的表示汇总成一个图级向量。

**批处理多张图**：不同的图节点数不同，常见做法是把一个 batch 里所有图的节点拼成一个大矩阵，再用一个 `batch` 向量记录每个节点属于第几张图：

$$
\texttt{batch} = [\underbrace{0, 0, 0}_{\text{图 } 0},\ \underbrace{1, 1}_{\text{图 } 1},\ \underbrace{2, 2, 2, 2}_{\text{图 } 2}]
$$

## 核心公式

记 $\mathcal{V}_g$ 为第 $g$ 张图的节点集合：

$$
\text{sum:}\ \ h_g = \sum_{v \in \mathcal{V}_g} x_v,
\qquad
\text{mean:}\ \ h_g = \frac{1}{|\mathcal{V}_g|} \sum_{v \in \mathcal{V}_g} x_v,
\qquad
\text{max:}\ \ h_{g,k} = \max_{v \in \mathcal{V}_g} x_{v,k}
$$

max 是对每个特征维**分别**取最大值。

**置换不变性**：图的节点没有固有顺序，同一张图换一种节点编号，读出结果必须不变。求和、平均、最大值都只依赖节点的**集合**，满足这个要求。

**表达能力的差别**（见「GIN」一题）：

| 读出 | 能区分 | 不能区分的例子 |
| --- | --- | --- |
| sum | 节点特征的多重集合（含个数） | — |
| mean | 特征的分布（比例） | $\{a\}$ 与 $\{a, a\}$ |
| max | 出现过的最大值 | $\{a, b\}$ 与 $\{a, a, b\}$ |

## 形状

| 量 | 形状 |
| --- | --- |
| `X` | `(total_nodes, D)` |
| `batch` | `(total_nodes,)` |
| 图的数量 | `batch.max() + 1` |
| 每张图的节点数 | `(num_graphs,)` |
| 输出 | `(num_graphs, D)` |

## 用到的 PyTorch 操作

- `out.index_add_(0, batch, X)`：把 `X` 的第 $v$ 行加到 `out` 的第 `batch[v]` 行，一次完成分组求和。
- 节点计数：对全 $1$ 向量做同样的 `index_add_`，或用 `torch.bincount(batch)`。
- `count.unsqueeze(1)`：`(G,)` → `(G, 1)`，才能按行广播相除。
- max：按图循环，`X[batch == g].max(dim=0).values`；或用 `scatter_reduce(..., reduce='amax')`。

## 常见坑

- **图数写成 `batch.max()`**：编号从 $0$ 开始，图数要 $+1$。
- **平均时广播错位**：节点数要变成列向量再除。
- **max 的初始值**：如果先建结果张量再逐步取最大，初始值要用 $-\infty$，不能用 $0$（特征可能全为负）。
- **不支持的模式**应报错。

## 延伸

- **批处理为什么不 pad**：不同图的节点数相差很大，补齐到最大节点数会浪费计算。把一批图的节点拼成一个大矩阵，邻接矩阵写成块对角（图之间没有边），消息传递不会跨图；`batch` 向量只在最后的读出里使用。
- **三种读出的取舍**：sum 保留图的大小（分子的大小常常本身就有信息），但尺度随节点数增长；mean 与节点数无关，适合比较不同大小的图，但看不出大小；max 抓每个维度最突出的信号，比如图中是否出现某种子结构。三者在表达能力上的区别见「GIN」一题。
- **可学习的读出**：除了固定的 sum、mean、max，还有注意力读出（对每个节点打一个门控分数，在每张图内部做 softmax 后加权求和）、Set2Set、分层池化（如 DiffPool，逐层把图粗化）等。
- **多层读出**：只用最后一层的节点表示，浅层的局部信息可能已被平滑掉。GIN 对每一层分别做读出再拼接。
- **工程细节**：`num_graphs` 若由 `batch.max() + 1` 推出，末尾没有节点的空图会被漏掉；实际接口常让调用方显式传入图的数量。`index_add_` 在 GPU 上的原子加操作，浮点求和的顺序不固定，结果可能有微小的不确定性。
- **与 Transformer 的类比**：ViT 用 `[CLS]` token 或对所有 patch 做平均来得到整个输入的表示，对应这里的可学习读出与 mean 读出。

## 面试追问

1. **读出为什么必须置换不变？**
   图的节点没有固定顺序，同一张图换一种编号，图级向量不应该变。sum、mean、max 都只依赖节点的集合，满足要求；而把节点特征按编号拼接起来就不满足。
2. **sum、mean、max 怎么选？**
   任务和图的大小有关就用 sum；想去掉图的大小影响用 mean；关心是否出现某种特征用 max。sum 的表达能力最强，但尺度随节点数增长，数值上要留意。
3. **一个 batch 里的图大小不同，怎么高效处理？**
   不 pad，把所有节点拼成一个大矩阵，用 `batch` 向量记录归属，读出时按图分组累加（`index_add_`、`scatter_reduce`）。
4. **如何实现按图分组的注意力读出？**
   给每个节点打一个分数，在每张图内部单独做 softmax（分组 softmax），再用权重做加权求和。分组 softmax 需要按图求最大值和求和，同样可以用分组的 scatter 操作完成。
5. **读出前 GNN 堆很多层有什么问题？**
   过平滑：节点表示趋同，读出的向量里能区分图的信息减少。可以少堆几层，或把各层的读出结果拼接起来。
