## 背景

数据并行训练中，每个 rank 用自己的数据算出一份完整梯度，然后所有 rank 要得到梯度之和（**all-reduce**）。

朴素做法：所有 rank 把梯度发给 rank 0 求和，再由 rank 0 广播回去。rank 0 要接收 $(W - 1) L$ 个元素、再发送 $(W - 1) L$ 个，它的网络链路成了瓶颈，耗时随 $W$ 线性增长。

**环形 all-reduce**（NCCL 的默认算法之一）让每个 rank 只和环上的下一个 rank 通信，所有链路同时工作，每个 rank 的通信量与 $W$ 基本无关。

## 核心公式

每个缓冲区切成 $W$ 块，每块约 $L/W$ 个元素。分两个阶段，各 $W - 1$ 步，每一步每个 rank 都向下一个 rank 发一块。

**阶段一：reduce-scatter**。第 $t$ 步（$t = 0, \dots, W-2$），rank $r$ 把第 $(r - t) \bmod W$ 块发给 rank $(r+1) \bmod W$，对方**累加**到自己的同一块上。

一块数据沿环流动时，每经过一个 rank 就多加上一份。发出时它已经包含 $t + 1$ 个 rank 的贡献，接收方加上自己的变成 $t + 2$ 份。走完 $W - 1$ 步后，每块恰好汇集了全部 $W$ 份，此时 rank $r$ 持有完整求和好的第 $(r+1) \bmod W$ 块。

**阶段二：all-gather**。第 $t$ 步，rank $r$ 把第 $(r + 1 - t) \bmod W$ 块发给下一个 rank，对方**覆盖**自己的同一块。再走 $W - 1$ 步，每块都传遍全环。

**通信量**：每个 rank 共发送

$$
2(W - 1) \cdot \frac{L}{W} = \frac{2(W-1)}{W} L < 2L
$$

无论 $W$ 多大，都不超过 $2L$，这就是它**带宽最优**的原因。

**同时发送**：同一步里所有 rank 同时收发，所以每一步发出的数据必须是这一步**开始前**的值。

## 用到的 PyTorch 操作

- `t.tensor_split(W)`：切成 $W$ 块，允许不整除（前 $L \bmod W$ 块各多一个元素）。
- `t.clone()`：复制，避免修改输入；`torch.cat(chunks)` 拼回。
- 模运算 `%` 处理环形下标（Python 的 `%` 对负数也返回非负结果）。

## 常见坑

- **边收边改**：如果直接在循环中修改块，后面的 rank 可能发出已被本步修改过的值。先把本步要发的块全部取出（快照），再统一更新。
- **两个阶段的操作弄反**：reduce-scatter 是**累加**，all-gather 是**覆盖**。
- **块下标公式**：reduce-scatter 发 $(r - t)$，all-gather 发 $(r + 1 - t)$，都要对 $W$ 取模。
- **整数张量转成浮点**：整数输入要精确求和，保持原 dtype。
- **输出共享存储**：每个输出必须是独立的张量。
- $W = 1$ 时没有任何通信，日志为空。

## 延伸

- **时间的两项**：设每步固定延迟 $\alpha$、链路带宽 $B$，一次 ring all-reduce 的时间约为

$$
T \approx 2(W-1)\,\alpha + \frac{2(W-1)}{W}\cdot\frac{L}{B}
$$

  第二项是带宽项，不随 $W$ 增长；第一项是延迟项，随 $W$ 线性增长。梯度这类大消息由带宽项主导，ring 很合适；消息很小或卡数很多时延迟项变得显眼，NCCL 会改用步数是 $O(\log W)$ 的树形算法。
- **为什么带宽最优**：每张卡自己数据里有 $\frac{W-1}{W}$ 属于别的卡负责的段，必须发出去；最终结果里也有 $\frac{W-1}{W}$ 是别的卡算出来的，必须收进来。ring 正好只发这么多。对比朴素做法：rank 0 要收 $(W-1)L$、发 $(W-1)L$，时间随 $W$ 线性增长，而 ring 的带宽项不变。
- **最慢的链路决定速度**：环的每一步是同步推进的，整个环的速度由其中最慢的一条链路决定。多机时环要穿过网卡，常见的优化是分层：先在机内归约、再跨机、最后机内广播，让慢链路上传输的数据尽量少。
- **与计算重叠**：DDP 把梯度分成若干桶，反向算完一桶就立即开始这一桶的 all-reduce，通信藏在后面层的反向计算之下。
- **分解的价值**：reduce-scatter 和 all-gather 各自就是一个独立的集合通信。ZeRO 在两者之间只更新自己那一段，FSDP 则把 all-gather 放到前向之前、参数用完即弃，都是把 all-reduce 拆开用。
- **浮点求和的顺序**：第 $c$ 块的求和顺序是 $x_c + x_{c+1} + \dots + x_{c-1}$，每一块的起点不同，所以结果和顺序求和在浮点下可能差一两个末位，不同块之间的求和次序也不同。但 all-gather 阶段是整块复制，所以**所有 rank 得到的结果逐位相同**，参数副本不会因此慢慢分叉。
- **量级**：7B 模型的 bf16 梯度约 $14$ GB，ring 下每卡约发送 $28$ GB。H100 机内 NVLink 单向约 $450$ GB/s 时约 $60$ ms；只有一块 $50$ GB/s 的网卡时约 $0.56$ s，必须靠重叠来藏住（量级估算）。

## 面试追问

1. **ring all-reduce 每个 rank 发送多少数据？为什么说它带宽最优？**
   共 $2(W-1)$ 步，每步一块 $L/W$，合计 $\frac{2(W-1)}{W}L < 2L$，与 $W$ 基本无关。每张卡必须发出别人负责的 $\frac{W-1}{W}$、收进别人算出的 $\frac{W-1}{W}$，这是下界，ring 达到了它。
2. **all-reduce 为什么等于 reduce-scatter 加 all-gather？这个拆分有什么用？**
   reduce-scatter 让每个 rank 拿到一段求好和的结果，all-gather 再把各段发给所有人。拆开后可以在两段之间插入别的操作：ZeRO 在中间只更新自己那一段的优化器状态，省下优化器状态的显存而通信总量不变。
3. **ring 有什么缺点？什么时候用别的算法？**
   延迟项 $2(W-1)\alpha$ 随卡数线性增长，小消息或超大规模时用树形算法更快；另外整个环被最慢的链路拖住，跨机时要做分层。NCCL 按消息大小和拓扑自动选择。
4. **朴素的「汇总到 rank 0 再广播」慢在哪里？**
   rank 0 的链路承担了所有流量，要接收 $(W-1)L$ 再发出 $(W-1)L$，其他卡的链路却是空闲的。ring 让所有链路同时工作，每张卡的流量与 $W$ 无关。
5. **ring all-reduce 之后，各个 rank 的结果逐位相同吗？和顺序求和一样吗？**
   各 rank 之间相同，因为每一块只在一个 rank 上归约完成，之后整块复制给其他 rank。但和一个 rank 上顺序求和未必逐位相同，浮点加法不满足结合律，每一块的求和顺序是环上的一个循环移位。
