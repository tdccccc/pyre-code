## 背景

普通数据并行中，每个 rank 都保存完整的参数、梯度和 Adam 状态。Adam 的两个动量 $m$、$v$（fp32）加上 fp32 主权重，占了模型状态的绝大部分（见「训练显存估算」一题）。

**ZeRO-2** 把梯度和优化器状态切成 $W$ 份：rank $r$ 只负责参数向量的第 $r$ 段，只保存这一段的梯度、$m$、$v$，也只更新这一段。最后再把各段更新后的参数收集起来，每个 rank 重新拥有完整参数。

## 核心公式

**为什么可以切**：Adam 的更新是**逐元素**的，每个参数的新值只依赖它自己的梯度和动量：

$$
\begin{aligned}
m_i &\leftarrow \beta_1 m_i + (1 - \beta_1) g_i \\
v_i &\leftarrow \beta_2 v_i + (1 - \beta_2) g_i^2 \\
p_i &\leftarrow p_i - \eta \frac{m_i / (1 - \beta_1^t)}{\sqrt{v_i / (1 - \beta_2^t)} + \epsilon}
\end{aligned}
$$

所以把元素任意分组、各组独立更新，结果和整体更新完全一样。

**一步的三个阶段**（$N$ 个参数，$W$ 个 rank，分区大小 $n = N/W$）：

**① reduce-scatter**：rank $r$ 得到第 $r$ 段的**平均**梯度

$$
g^{(r)} = \frac{1}{W} \sum_{k=1}^{W} \text{grad}_k\bigl[\, rn : (r+1)n \,\bigr]
$$

取平均是因为全局损失是全局 batch 上的均值，每个 rank 的梯度只是其中一份数据的梯度。

**② 本地 Adam**：rank $r$ 用 $g^{(r)}$ 和自己保存的 $m^{(r)}$、$v^{(r)}$ 更新第 $r$ 段参数。

**③ all-gather**：把 $W$ 段新参数按顺序拼接。

**显存**：每个 rank 的优化器状态和梯度降为原来的 $1/W$。**通信**：reduce-scatter + all-gather 的总量和一次 all-reduce 相同，没有额外开销。

## 形状

| 量 | 形状 |
| --- | --- |
| `flat_param`、每个 `rank_grads[k]` | `(N,)` |
| 每个分区的 $g$、$m$、$v$、新参数段 | `(N / W,)` |
| 返回的完整参数 | `(N,)` |

## 用到的 PyTorch 操作

- 切片 `t[lo:hi]`。
- `torch.stack([...]).mean(dim=0)`：多个 rank 的梯度取平均。
- `torch.cat(parts)`：模拟 all-gather。
- `t.sqrt()`。

## 常见坑

- **梯度求和而不是平均**：Adam 对梯度的整体缩放几乎不敏感（只有 $\epsilon$ 项受影响），所以差别不明显，但仍和在平均梯度上运行的 Adam 对不上，梯度很小时尤其明显。换成 SGD，求和则等价于学习率放大 $W$ 倍。
- **原地修改 $m$、$v$ 或参数**：题目要求返回新张量，输入保持不变。
- **偏差校正的步数**：用传入的 `step`，不要自己计数。
- **状态没有传回**：返回的状态在下一步要原样传入，布局必须和输入一致（每个 rank 一个 `{"m", "v"}` 字典）。
- $\epsilon$ 加在 $\sqrt{\hat v}$ 之外。

## 延伸

- **ZeRO 的三个阶段**：按切什么递进。设 $\Psi$ 为参数量，混合精度 + Adam（bf16 参数 $2\Psi$、bf16 梯度 $2\Psi$、fp32 主权重和 $m$、$v$ 共 $12\Psi$），每卡的模型状态为

$$
\text{ZeRO-1: } 4\Psi + \frac{12\Psi}{W},\qquad
\text{ZeRO-2: } 2\Psi + \frac{14\Psi}{W},\qquad
\text{ZeRO-3: } \frac{16\Psi}{W}
$$

  ZeRO-1 只切优化器状态，ZeRO-2 再切梯度（本题），ZeRO-3 连参数一起切（见 FSDP 一题）。三者的横向对比在「分布式训练」专题。
- **ZeRO-1 与 ZeRO-2 的区别只在梯度**：ZeRO-1 仍然先 all-reduce 梯度，每卡有完整梯度，只是只用自己那一段去更新；ZeRO-2 直接 reduce-scatter，非己负责的梯度一经发出就能释放，省下 $2\Psi(1 - 1/W)$ 字节。两者通信量相同。
- **通信量没有增加**：reduce-scatter 和 all-gather 各约 $\Psi$ 个元素，合起来约 $2\Psi$，等于一次 all-reduce。ZeRO-1/2 是用同样的通信换来了显存。
- **混合精度下的数据流**：每卡的 fp32 主权重分片在本地更新，更新完转成 bf16，再 all-gather 成完整的 bf16 参数供下一步的前向使用。梯度也是 bf16 下 reduce-scatter 的，所以通信走的是低精度。
- **哪些优化器可以这样切**：只要更新是逐元素的就行，Adam、SGD 都满足。需要全局信息的要补通信：按全局梯度范数裁剪，每卡先算自己那段的平方和，再 all-reduce 一个标量即可；按整个矩阵做运算的优化器（如 Shampoo、Muon）不能把一个矩阵随意切到不同的卡上，需要按矩阵整体分配或额外通信。
- **ZeRO 没有减少的东西**：每张卡仍然对完整的层做前向反向，激活的大小不变。显存的瓶颈如果是激活（序列长），要配合重计算、序列并行等手段。

## 面试追问

1. **7B 模型、8 张卡，ZeRO-2 比普通数据并行每卡省多少模型状态？**
   混合精度 + Adam 下，DP 为 $16\Psi \approx 112$ GB；ZeRO-2 为 $2\Psi + 14\Psi/8 \approx 26$ GB。ZeRO-1 约 $38.5$ GB，ZeRO-3 约 $14$ GB。
2. **为什么 ZeRO-2 的通信量和普通 DDP 一样？**
   DDP 做一次 all-reduce，等于 reduce-scatter 加 all-gather。ZeRO-2 把这两步拆开，中间插入「只更新自己那一段」；reduce-scatter 的对象是梯度，all-gather 的对象是更新后的参数，总量不变。
3. **为什么 Adam 的状态可以任意切分？**
   Adam 的更新是逐元素的：每个参数的新值只依赖它自己的梯度、$m$、$v$。把元素任意分组、各组独立更新，结果与整体更新逐元素一致。
4. **梯度为什么要取平均而不是求和？**
   全局损失是全局 batch 上的均值，每个 rank 的梯度只是其中一份数据的均值梯度，各 rank 的平均才是全局梯度。求和得到的是 $W$ 倍的梯度：对 SGD 相当于学习率放大 $W$ 倍；Adam 对梯度的整体缩放基本不敏感，只剩 $\epsilon$ 项受影响，但结果仍不等于在平均梯度上做 Adam。
5. **ZeRO 和张量并行有什么本质区别？**
   ZeRO 仍是数据并行：每卡处理不同的数据，对完整的层做完整的计算，只是不长期保存别人负责的状态。张量并行把单个矩阵乘切开，所有卡处理同一份数据。所以 ZeRO 不降低激活，也不要求改模型结构。
