## 背景

**SFT**（Supervised Fine-Tuning，监督微调）用人写或强模型生成的示范对话训练模型，是后训练的第一步，后面的偏好学习和 RL 都从 SFT 模型出发。

一条对话先经过**聊天模板**（chat template）渲染成一个 token 序列，例如：

```
<|system|>你是助手<|end|><|user|>1+1=?<|end|><|assistant|>等于 2<|end|>
```

模型只该学会「怎么回答」，不该学「用户会问什么」，所以只有助手写的 token（包括它的结束符 `<|end|>`，否则模型学不会停下来）是学习目标。

为了不在填充上浪费算力，训练框架会把多条短样本首尾相接**打包**（packing）进同一行。这时要防止上一条样本的结尾去预测下一条样本的开头，两条样本之间没有任何因果关系。

## 核心公式

位置 $t$ 的目标是 $x_{t+1}$。设 $\mathcal{V}$ 为计入的目标集合（目标是助手 token、与当前 token 属于同一个样本、不是填充），每个目标的负对数似然为

$$
\ell_t = -\log \pi(x_{t+1} \mid x_{\le t})
$$

两种归约：

$$
L_{\text{token}} = \frac{1}{|\mathcal{V}|} \sum_{t \in \mathcal{V}} \ell_t,
\qquad
L_{\text{sample}} = \frac{1}{N} \sum_{i=1}^{N} \frac{1}{|\mathcal{V}_i|} \sum_{t \in \mathcal{V}_i} \ell_t
$$

- $\mathcal{V}_i$：第 $i$ 个样本的目标集合；$N$：至少有一个目标的样本数。
- token 平均：每个 token 权重相同，长回答在总损失里占比更大。
- 样本平均：每个样本权重相同，短回答里的每个 token 权重更大。

## 形状

| 张量 | 形状 | 说明 |
| --- | --- | --- |
| `logits` | (B, T, V) | 取 `[:, :-1]` 后与目标对齐 |
| `input_ids`、`assistant_mask`、`seq_ids` | (B, T) | 目标侧都取 `[:, 1:]` |
| 逐 token 损失、有效掩码 | (B, T−1) | |
| 输出 | 标量 | |

## 用到的 PyTorch 操作

- `torch.logsumexp`、`gather`：稳定地算出目标位置的负对数似然。
- 布尔运算 `&`：把三个条件合成一个掩码 `valid`。
- `torch.unique(keys, return_inverse=True)`：把 (行, seq_id) 编成一个整数 key，再得到每个目标属于第几组。
- `t.new_zeros(n).index_add(0, idx, src)`：按组求和、计数。

## 常见坑

- **掩码按输入位置取**：要用 `assistant_mask[:, 1:]`，看的是**目标** token 是不是助手写的。
- **跨样本预测**：只看助手掩码不够。继续预训练时整行都是目标，必须再要求 `seq_ids[:, t+1] == seq_ids[:, t]`。
- **把 seq_id 当成全局编号**：每行的 seq_id 都从 0 开始，第 0 行的样本 0 和第 1 行的样本 0 是两条不同的样本，分组 key 必须包含行号。
- **填充泄漏**：有的数据管线会把填充位置的助手掩码也置 1，所以还要排除 `seq_id == -1`。
- **没有目标时返回 Python 的 0**：返回 `logits.sum() * 0.0`，计算图仍然连着，`backward()` 不会报错。分布式训练里每个进程都要参与梯度同步，这一点很重要。

## 延伸

- **HF 里的写法**：Transformers 用 `labels = -100` 表示不计入，损失内部做错位。TRL 的 `SFTTrainer` 用 `assistant_only_loss=True` 或 `completion_only_loss` 生成这种标签，靠的是聊天模板里的 `{% generation %}` 标记。
- **打包还要改注意力**：本题只处理了损失。真正打包时，每条样本的位置编码要从 0 重新开始（`position_ids`），注意力也不能跨样本（FlashAttention 的 varlen 接口用 `cu_seqlens`，见「变长序列打包注意力」一题）。只改损失不改注意力，样本之间仍会互相看到。
- **梯度累积的坑**：2024 年 HF 和 Unsloth 发现，梯度累积时每个微批先做 token 平均、再对微批取平均，不等于整个大批的 token 平均，微批之间 token 数不同时损失会偏。正确做法是先累加损失之和与 token 数，最后统一相除。
- **该用哪种平均**：token 平均是主流，跟预训练一致；样本平均让短回答的样本也有同等话语权。多轮对话里还有按轮次加权的做法。
- **只训练最后一轮还是所有轮**：多轮数据可以只训练最后一个助手回答（前面的轮次当上下文），也可以每个助手轮次都训练。后者数据利用率高，但前面轮次的回答如果质量差，也会被学进去。

## 面试追问

1. **SFT 为什么不训练提示词部分？**
   提示词是用户写的，让模型学习它既浪费容量，又可能让模型学会「替用户说话」。只训练回答，模型学到的是条件分布 $\pi(y \mid x)$。
2. **packing 有什么好处，要注意什么？**
   好处是没有填充，算力利用率接近 100%。要注意三点：损失不跨样本、位置编码按样本重置、注意力不跨样本。
3. **为什么结束符也要计入损失？**
   模型要学会在回答结束时输出结束符，否则推理时会一直生成下去。
4. **梯度累积时 token 平均为什么会出错？**
   每个微批的平均值以各自的 token 数为分母，再平均就成了「平均的平均」。应该在整个累积周期内统一用总 token 数做分母。
5. **SFT 之后为什么还需要 RL？**
   SFT 只模仿示范，模型从没见过自己犯的错，也学不到「哪种回答更好」。偏好学习和 RL 能利用比较信号或可验证的奖励，在模型自己的分布上继续改进。
