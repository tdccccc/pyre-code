## 背景

生成序列时，我们想要整体概率最高的那一条：

$$
y^* = \arg\max_{y}\ P(y) = \arg\max_{y} \prod_{t} P(y_t \mid y_{<t})
$$

穷举所有序列有 $V^L$ 种（$V$ 为词表大小，$L$ 为长度），不可能做到。

- **贪心**：每步只选当前概率最大的 token。但当前最好的选择不一定通向整体最好的序列。
- **束搜索**：每步保留得分最高的 $B$ 条候选（束宽 beam width），是贪心和穷举之间的折中。机器翻译、语音识别中常用。

## 核心公式

**对数概率**：很多个小于 $1$ 的概率连乘会下溢为 $0$。取对数后乘法变加法：

$$
\operatorname{score}(y_{1:t}) = \log \prod_{s=1}^{t} P(y_s \mid y_{<s}) = \sum_{s=1}^{t} \log P(y_s \mid y_{<s})
$$

扩展一个 token 时，新得分 = 旧得分 + 新 token 的对数概率。对数概率都 $\le 0$，所以序列越长得分越低。

**一个贪心失败的例子**：

| 第 1 步 | 第 2 步 | 序列概率 |
| --- | --- | --- |
| A（0.6） | 之后最好的只有 0.4 | $0.6 \times 0.4 = 0.24$ |
| B（0.4） | 之后最好的有 0.9 | $0.4 \times 0.9 = 0.36$ |

贪心在第 1 步选了 A，错过了更好的 B 开头的序列；$B = 2$ 的束搜索会同时保留 A 和 B。

**每一步**：$B$ 条束 × $V$ 个可能的下一个 token = $B \cdot V$ 个候选，按累积得分保留前 $B$ 个。实际上每条束只需考虑它自己得分最高的 $B$ 个扩展就够了：全局前 $B$ 名里，来自同一条束的最多也就 $B$ 个。

**结束**：以 `eos` 结尾的序列不再扩展，放进「已完成」列表；所有束都结束或达到最大长度时停止，在已完成和未完成的序列中选得分最高的。

## 用到的 PyTorch / Python 操作

- `log_probs.topk(k)`：返回最大的 $k$ 个值和它们的下标。
- `torch.tensor(seq)`：把当前序列交给 `log_prob_fn`。
- Python 列表排序：`candidates.sort(key=lambda c: c[0], reverse=True)`。
- `.item()`：把单个元素张量转成 Python 数。

## 常见坑

- **概率直接相乘**：长序列会下溢。用对数概率相加。
- **按单步概率而不是累积得分排序**：那就退化成了每条束各自贪心。
- **继续扩展已经结束的束**：以 `eos` 结尾的序列应该保持不变。
- **返回的序列缺了起始 token**：结果应以 `start_token` 开头。
- 自检：$B = 1$ 时必须和贪心完全一致。
- 实际系统中常对得分做**长度归一化**（除以长度），否则偏向短序列；本题不要求。

## 延伸

- **长度归一化**：每个 token 的对数概率都 $\le 0$，序列越长累积得分越低，所以不做处理会偏向短序列。常见做法是用平均对数概率，或者除以 $|y|^{\alpha}$：

$$
\operatorname{score}(y) = \frac{1}{|y|^{\alpha}} \sum_{t} \log P(y_t \mid y_{<t})
$$

  其中 $|y|$ 是序列长度，$\alpha \in [0, 1]$ 控制归一化的力度；$\alpha = 0$ 就是不归一化。

- **不是精确搜索**：束搜索是启发式的，$B$ 越大越接近全局最优，但也不保证找到。$B = 1$ 就是贪心。翻译任务里，束宽超过一定大小后质量反而下降的现象有过报道，所以 $B$ 不是越大越好。
- **成本**：每步要同时前向 $B$ 条序列，可以合并成一个 batch；每步还要从 $B \cdot V$ 个候选里选 top-$B$。显存方面，每条束都有自己的 KV cache，而且重新选束之后，新的束要继承父束的缓存。这些束共享大部分前缀，用分页管理加写时复制（copy-on-write）可以避免整份拷贝，见「推理服务」专题和 Paged Attention 一题。
- **为什么大模型对话很少用**：最大化概率的序列往往平淡、重复，各条束之间差别很小。需要多样性时有 diverse beam search 等变体，或者直接采样出多条再挑选。
- **仍然常用的场景**：机器翻译、语音识别、需要一个「最可能」答案的结构化生成。

## 面试追问

1. **贪心和束搜索有什么区别？$B = 1$ 时呢？**
   贪心每步只选当前最优，束搜索同时保留 $B$ 条累积得分最高的候选，可以避开「当前最优不通向整体最优」的情况。$B = 1$ 时二者完全一致。
2. **为什么要用对数概率，而不是直接乘概率？**
   连乘很多个小于 $1$ 的数会下溢到 $0$。取对数后乘法变加法，数值稳定，排序结果不变，因为对数是单调的。
3. **为什么需要长度归一化？**
   序列越长，累积对数概率越低，不处理就系统性地偏向短序列，甚至过早生成结束符。除以长度的某个幂次可以补偿，但 $\alpha$ 需要调。
4. **束搜索一步的复杂度是多少？**
   $B$ 条束各自前向一次得到 $B \times V$ 个候选，再选 top-$B$。每条束只取自己得分最高的 $B$ 个扩展就够了，因为全局前 $B$ 名里来自同一条束的最多 $B$ 个。
5. **束搜索一定能找到概率最高的序列吗？为什么对话不用它？**
   不一定，它是启发式的，$B$ 有限时可能漏掉最优序列。即使找到了，概率最高的序列在开放式生成里往往平淡重复，所以对话和创作更常用采样。
