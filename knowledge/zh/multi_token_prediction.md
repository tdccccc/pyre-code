## 背景

标准语言模型在每个位置只预测**下一个** token。**多 token 预测**（MTP，Meta 2024；DeepSeek-V3 也使用了类似的做法）在同一个隐藏状态上接 $N$ 个独立的输出头，同时预测接下来的 $N$ 个 token。

好处：

- **训练信号更密**：每个位置提供 $N$ 个监督目标
- **鼓励模型「往前想」**：要预测更远的 token，隐藏状态必须编码更多关于后续内容的规划信息
- **推理加速**：额外的头可以充当草稿模型，配合推测解码一次产出多个 token

## 核心公式

位置 $t$ 的隐藏状态 $h_t$，第 $i$ 个头 $W^{(i)} \in \mathbb{R}^{D \times V}$ 预测第 $t + i$ 个 token：

$$
z^{(i)}_t = h_t\, W^{(i)},
\qquad
\ell^{(i)}_t = -\log \operatorname{softmax}\bigl(z^{(i)}_t\bigr)_{y_{t,i}}
$$

**总损失**：先对所有位置平均，再对 $N$ 个头平均：

$$
L = \frac{1}{N} \sum_{i=1}^{N} \frac{1}{B S} \sum_{b, t} \ell^{(i)}_{b,t}
$$

$N = 1$ 时就是普通的下一个 token 交叉熵。

**稳定的 log-softmax**：

$$
\log \operatorname{softmax}(z)_k = (z_k - m) - \log \sum_j e^{z_j - m},
\qquad m = \max_j z_j
$$

减去最大值后所有指数都 $\le 0$，不会溢出，求和至少为 $1$，对数也不会出问题。

## 形状

| 量 | 形状 |
| --- | --- |
| `hidden_states` | `(B, S, D)` |
| 每个头 `heads[i]` | `(D, V)` |
| 每个头的 logits / log 概率 | `(B, S, V)` |
| `targets` | `(B, S, N)`，`targets[:, :, i]` 是第 $i$ 个头的标签 |
| 取出的目标 log 概率 | `(B, S)` |
| 输出 | 标量 |

## 用到的 PyTorch 操作

- `hidden_states @ heads[i]`。
- `t.max(dim=-1, keepdim=True).values`、`torch.exp`、`torch.log`、`.sum(dim=-1, keepdim=True)`。
- `log_probs.gather(-1, idx.unsqueeze(-1)).squeeze(-1)`：`gather` 要求索引与输入维数相同，所以先在末尾补一维，取完再去掉。

## 常见坑

- **用了 `F.cross_entropy` 或 `F.log_softmax`**：本题要求手写。
- **不减最大值**：logits 大时 `exp` 溢出。
- **标签取错**：第 $i$ 个头用 `targets[:, :, i]`。
- **平均方式**：每个头先对所有位置取均值，再对头取均值。
- `gather` 的索引必须是 `long` 类型。

## 延伸

- **两类设计**：Meta 的原版是共享主干，后面并行接 $N$ 个头，每个头独立预测自己的位置，头与头之间没有依赖，这也是本题的设定。DeepSeek-V3 则用**串行**的 MTP 模块：预测第 $t + 2$ 个 token 时，把上一层的表示和第 $t + 1$ 个 token 的嵌入合并后再过一个 Transformer 块，保持了完整的因果链。后者在 DeepSeek-V3 中只多预测一个 token。
- **主要用途**：训练时增加监督信号。推理时，额外的头可以直接丢掉，主模型照常工作；也可以保留它们做草稿，配合推测解码（见「解码与采样」专题）。
- **和推测解码的关系**：额外的头先一次性猜出后面几个 token，再让主模型用一次前向验证，猜对的保留。这样不需要另外训练一个草稿模型。并行独立的头每个只依赖主干的隐藏状态，不依赖前面的草稿，越远的位置猜得越不准，接受率也越低；串行的做法在这点上更有优势。Medusa 也是在已有模型上加多个头，用同样的思路加速解码。
- **模型规模**：Meta 的论文报告，MTP 的收益在更大的模型上更明显，在代码任务上收益尤其突出。小模型上不一定有收益，是否采用要看具体规模和任务。
- **损失的开销**：每个头都要算一遍 $(B, S, V)$ 的 logits，词表大时显存压力成倍增加。可以分块计算损失，见「损失函数」专题的分块交叉熵一题。
- **序列末尾的处理**：位置 $t$ 的第 $i$ 个目标是 $y_{t+i}$，序列最后 $i$ 个位置没有对应的标签，实际训练里需要用忽略标记屏蔽掉。本题的 `targets` 已经给定，不涉及这一点。
- **头的权重**：各头的损失也可以加权，例如给近的位置更大的权重，本题是简单平均。

## 面试追问

1. **MTP 为什么能提升效果？**
   每个位置有 $N$ 个监督目标，训练信号更密；预测更远的 token 要求隐藏状态编码更多关于后文的信息，这被认为有助于模型学到更长程的结构。
2. **MTP 怎么加速推理？**
   用额外的头一次猜出多个 token，主模型一次前向验证，猜对的全部接受，这就是自推测解码。收益取决于接受率。
3. **$N = 1$ 时是什么？**
   就是普通的下一个 token 预测，交叉熵与标准语言模型完全相同。
4. **Meta 的并行头和 DeepSeek-V3 的串行模块有什么区别？**
   并行头互相独立，实现简单，但每个头看不到前面草稿的内容；串行模块把前一个预测位置的信息传下去，保留因果链，但结构更复杂，计算也更多。
5. **手写交叉熵为什么要先减最大值？**
   $e^{z}$ 在 $z$ 较大时会溢出。减去最大值后所有指数都不超过 $0$，求和中至少有一项是 $1$，对数不会出现 $\log 0$。结果在数学上不变，因为分子分母同乘了 $e^{-m}$。
