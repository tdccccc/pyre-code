## 背景

混合专家（MoE）层里，路由器为每个 token 选 top-k 个专家。在**专家并行**中，不同专家放在不同的卡上，token 要通过 all-to-all 发到对应专家所在的卡，算完再发回来。

为了让通信缓冲区和专家计算的形状**固定**（方便高效实现），每个专家只预留 $C$ 个槽位，即**专家容量**。路由不均衡时，热门专家的槽位会被占满，多出的分配直接**丢弃**（这些 token 在这个专家上的贡献为 $0$，它们仍然可以通过残差连接往下传）。GShard、Switch Transformer 都这样做。

## 核心公式

**门控**：$p = \operatorname{softmax}(\text{router\_logits})$，取每个 token 概率最大的 $k$ 个专家 $e_{n,0}, \dots, e_{n,k-1}$（按概率从大到小），在这 $k$ 个之间重新归一化：

$$
g_{n,r} = \frac{p_{n,\, e_{n,r}}}{\sum_{r'=0}^{k-1} p_{n,\, e_{n,r'}}}
$$

**容量**：总分配数是 $N k$，平均每个专家 $Nk/E$ 个，再乘一个余量系数（如 $1.25$）并**向上**取整：

$$
C = \left\lceil \frac{\text{capacity\_factor} \cdot N \cdot k}{E} \right\rceil
$$

系数越大，丢弃越少，但空槽位（浪费的计算和通信）越多。

**分配优先级**：先按 token 顺序处理所有 token 的**第一选择**，再处理所有第二选择……这样每个 token 最想去的专家优先得到满足，不会因为排在后面就被别人的次选挤掉。

**输出**：

$$
y_n = \sum_{r\,:\,(n, r) \text{ 被接收}} g_{n,r} \cdot \operatorname{Expert}_{e_{n,r}}(x_n)
$$

被丢弃的分配贡献为 $0$，剩下的门控权重**不再**重新归一化。

## 形状

| 量 | 形状 |
| --- | --- |
| `x`、输出 | `(N, D)` |
| `router_logits`、$p$ | `(N, E)` |
| top-k 的概率、下标、门控 | `(N, k)` |
| 专家 $e$ 的输入 | `(n_e, D)`，$n_e \le C$ |

## 用到的 PyTorch 操作

- `probs.topk(k, dim=-1)`：返回按从大到小排序的值和下标。
- 用整数下标列表索引：`x[tokens]`，把分给某个专家的 token 堆叠起来，一次调用专家。
- `out.index_add(0, tokens, src)`：把 `src` 的各行加到 `out` 的指定行上（同一行可以被加多次）。它返回新张量，不会原地修改。
- `math.ceil`。

## 常见坑

- **容量向下取整**：要用 $\lceil \cdot \rceil$。
- **按 token 优先而不是按选择序号优先**：先处理完 token 0 的两个选择再处理 token 1，会让 token 0 的次选挤掉 token 1 的首选。
- **丢弃后重新归一化门控**：本题要求不重新归一化。
- **每个 token 单独调用专家**：结果对，但慢，且测试要求每个专家只调用一次、按接收顺序堆叠行。
- **门控断开了梯度**：比如用 `.item()` 取出门控值再参与计算，梯度就传不回 `router_logits`。
- 不要原地修改输入。
