## 解决什么问题

神经网络吃的是整数编号，文本要先切成一串**符号**（token），再把每个符号映射成编号，查 embedding 表变成向量。切分的粒度决定了两个互相拉扯的量：

- **词表大小 $V$**：embedding 表和输出层都是 $V \times D$ 量级的参数，输出层每个位置还要算 $V$ 个 logit。
- **序列长度 $S$**：注意力的计算量随 $S$ 平方增长，KV cache 随 $S$ 线性增长，上下文窗口也是按 token 数算的。

| 粒度 | 词表 | 序列 | 问题 |
| --- | --- | --- | --- |
| 词 | 巨大 | 短 | 词表爆炸；没见过的词（新词、拼写错误、变形）变成 OOV（out-of-vocabulary） |
| 字符 | 很小 | 很长 | 每个 token 信息量低，模型要先学会「拼词」 |
| **子词**（subword） | 中等 | 中等 | 常见词是一个 token，罕见词拆成几个常见片段 |

子词分词的共同思路：**从语料统计里学出一张词表**，让高频片段独占一个 token，低频的靠组合表示。三类主流算法都是这个框架，区别在于**怎么选出词表里的片段**，以及**怎么把新文本切成这些片段**。

## 对比

| 方法 | 词表怎么建 | 编码方式 | 典型使用 |
| --- | --- | --- | --- |
| BPE | 自底向上：反复合并频数最高的相邻对 | 按合并规则的学习顺序依次应用 | GPT-2 起的 GPT 系列、LLaMA 等 |
| WordPiece | 自底向上：合并使训练语料似然增益最大的相邻对 | 从左到右贪心取最长匹配 | BERT |
| Unigram LM | 自顶向下：从大词表出发，反复剪掉对似然影响最小的片段 | 在所有切分里取概率最大的（Viterbi） | SentencePiece 支持 |

### BPE

**训练**：初始词表是单个字符，每一步统计相邻符号对的频数，把最高频的一对合并成新符号，并把这条规则记下来。合并 $M$ 次，词表大小就是初始符号数加 $M$。**输出是一张有序的合并表**，顺序本身就是信息。

**编码**：新文本拆成字符后，按合并表的顺序依次应用规则。

### WordPiece

整体流程与 BPE 相同，区别在选哪一对来合并。BPE 看原始频数 $n_{ab}$，WordPiece 看合并带来的语言模型似然增益。把每个 token 当作独立采样，近似有：

$$
\Delta \mathcal{L} \approx n_{ab} \log \frac{p(ab)}{p(a)\,p(b)}
$$

$n_{ab}$ 是相邻对 $(a, b)$ 的出现次数，$p(\cdot)$ 是 token 在语料中的相对频率。实现里常直接用 $\dfrac{\text{freq}(ab)}{\text{freq}(a)\,\text{freq}(b)}$ 作为打分：两个单独很常见的符号即使经常相邻，得分也不高；本身很少见却几乎总是一起出现的符号，得分更高。

编码时不回放合并表，而是在词表里从左到右找**最长匹配**。BERT 的词表里非词首的片段带 `##` 前缀，用来区分词中的 `est` 和词首的 `est`。这和 BPE 用 `</w>` 标记词尾，是同一个需求的两种记法。

### Unigram LM

反过来走：先用一个很大的种子词表（高频子串），假设句子按下式生成，每个片段独立：

$$
P(x) = \prod_{i} p(x_i), \qquad x^* = \arg\max_{x \in \mathcal{S}(s)} P(x)
$$

$s$ 是一个词，$\mathcal{S}(s)$ 是它所有可能的切分，$x_i$ 是切分里的片段，$p(x_i)$ 是片段的概率。训练用 EM 估计 $p$，然后把去掉后总似然下降最少的片段剪掉一批，重复直到词表缩到目标大小。

它是**概率模型**，一个词有多种切分，各有概率。训练时可以按概率采样切分当作数据增强（subword regularization），BPE 对应的做法是 BPE-dropout，合并时随机跳过一部分规则。

## byte-level BPE 与预分词

**byte-level BPE**（GPT-2 起使用）把初始符号从字符换成 **256 个字节值**。任何字符串都能用 UTF-8 编码成字节序列，所以：

- **不存在 OOV**：最坏情况每个字节单独成一个 token，编码永远成功，也能无损解码回原文。
- 初始词表固定为 256，不用担心 Unicode 里数以十万计的字符怎么收录。
- 代价是罕见字符要用多个 token：一个汉字的 UTF-8 编码占 3 个字节，如果词表里没有对应的合并，就要用最多 3 个 token。

GPT-2 的词表大小是 50257 = 256 个字节 + 50000 次合并 + 1 个特殊 token `<|endoftext|>`。

**预分词**（pre-tokenization）：先用规则（GPT-2 起用一条正则）把文本切成「词」的块，BPE 只在块内部合并，不跨块。这样做有几个作用：

- 避免跨类别的无意义合并，比如把词尾和标点（`dog` 和 `.`、`!`）合成一个 token。
- 把统计量压缩成「词 → 频数」的字典，训练只需要在这份字典上循环，不必扫整个语料。
- 可以用规则约束数字、空白的切法，比如限制数字块的长度。

不使用预分词的做法以 SentencePiece 为代表：把整段文本（含空白）看成一个字符流，空格用可见的 `▁` 表示，所以编码解码不依赖语言相关的预处理。它同时实现了 BPE 和 Unigram。

## 词表大小的取舍

| | 词表变大 | 词表变小 |
| --- | --- | --- |
| 序列长度 | 更短：注意力、KV cache、上下文窗口都受益 | 更长 |
| embedding 和输出层 | 参数 $V \times D$ 更多；输出层每个位置要算更多 logit | 更少 |
| 罕见 token | 更多 token 见得很少，向量训练不充分 | 每个 token 都见得多 |

两个额外的数字感觉：

- embedding 表的参数量是 $V \times D$。以 GPT-2 small 为例，$V = 50257$、$D = 768$，约 3860 万个参数，占总参数的相当一部分；GPT-2 的输出层与 embedding 共享权重（weight tying），所以不用再付一份。
- 训练时 logits 的形状是 `(B, S, V)`，$V$ 大了这个张量会很占显存，这也是「损失函数」专题里 chunked_cross_entropy 一题要解决的问题。

近几年的模型词表整体在变大，规模和语料越大、多语言越多，越倾向于大词表。大致的量级：BERT 英文版约 3 万，LLaMA 2 约 3.2 万，GPT-4 一代的词表约 10 万，LLaMA 3 约 12.8 万。

**一个陷阱**：不同分词器的 token 数不可比。比较两个模型的困惑度或 loss 时，若词表不同，每个 token 对应的文本长度不同，需要换算成每字节的损失（bits per byte）才公平。

## 分词带来的常见问题

模型看到的是 token，不是字符，很多「看似简单」的失败都来自这里：

- **数数字与算术**：一个数字会被切成不规则的块，同一个数在不同上下文里可能切法不同，模型很难学到统一的位值对齐。常见的缓解办法是在预分词里限制数字块的长度：GPT-4 一代的正则把数字切成最多 3 位一组，LLaMA 1、2 则把每个数字单独切开。
- **拼写与字符级任务**：数一个词里有几个字母、反转字符串、押韵，模型只看到词的 token 编号，看不到里面的字符。
- **多语言不公平**：词表主要由英文语料学出，其他语言的词被切得更碎，同样的内容需要更多 token。后果是上下文装得更少、推理更慢、按 token 计费更贵，模型在这些语言上也往往更弱。
- **空格与大小写**：在 GPT-2 一类的词表里，` hello`（带前导空格）、`hello`、`Hello`、`HELLO` 是不同的 token。提示词末尾多一个空格，会让最后的切分与训练中常见的切法不一致，影响续写。BERT 的 uncased 版本则先把文本转小写，换取更小的词表。
- **欠训练的 token**：词表是用分词器的语料统计出来的，和模型的训练语料不一定重合，有些 token 在训练中几乎没出现过，向量几乎没被训练，遇到时模型行为会很怪。
- **分词器和模型绑定**：词表一旦确定，embedding 的行就和 token 编号对应，换分词器等于重训 embedding。

针对这些问题的另一条路线是不要分词器，直接以字节为输入（如 ByT5），代价是序列变长很多，需要新的架构或压缩手段。

## 训练和编码是两个过程

| | 训练（学习） | 编码（应用） |
| --- | --- | --- |
| 输入 | 一份语料 | 任意一段新文本 |
| 做什么 | 反复统计、选择，**产出**合并表 / 词表 | 用已有的合并表把文本切开 |
| 产物 | 有序的合并规则（BPE），或词表加概率（Unigram） | 一串 token |
| 何时做 | 模型训练之前，一次 | 每次训练、推理时，数据量大，要快 |
| 之后是否改动 | 定好后冻结 | 结果确定（除非有意引入随机，如 BPE-dropout） |

这个区别在 BPE 里尤其容易混：训练要「找最高频的对」，编码**不再统计任何频数**，只按规则的先后顺序回放。分词器的语料不必和模型的预训练语料一致，但差得太远会导致词表利用率低。

## 怎么选

- **通用大模型、多语言或含代码**：byte-level BPE，不用担心 OOV，实现简单、速度快。
- **希望字符覆盖和语言无关的预处理**：SentencePiece，可选 BPE 或 Unigram。
- **需要子词采样做增强**（如低资源翻译）：Unigram 的采样是原生支持的。
- **词表大小**：看模型规模和语言覆盖。小模型用大词表要小心 embedding 占比过高。

## 题目顺序

只有一道题：

1. **BPE**：把整个流程亲手写一遍。训练是「统计相邻对、合并、重复」，编码是「按学到的顺序回放规则」，两者共用同一套符号序列表示，正好对应上面「训练和编码是两个过程」。

## 面试追问

1. **为什么要用子词分词，而不是词或字符？**
   词级词表太大，且遇到没见过的词就无从表示；字符级词表小，但序列太长，注意力的平方复杂度和 KV cache 都吃不消。子词让高频词保持一个 token，罕见词拆成已知片段，在词表大小和序列长度之间取折中。
2. **BPE、WordPiece、Unigram 有什么区别？**
   BPE 和 WordPiece 都是自底向上合并，BPE 按相邻对的频数，WordPiece 按似然增益；Unigram 是自顶向下，从大词表出发，按对总似然的影响剪枝。编码上，BPE 回放合并规则，WordPiece 做最长匹配，Unigram 取概率最大的切分。
3. **byte-level BPE 为什么没有 OOV？**
   初始符号是 256 个字节，任何文本都能编码成字节序列，最坏情况每个字节一个 token，且能无损还原。代价是罕见字符会占多个 token。
4. **词表大小怎么权衡？**
   词表大则序列短，但 embedding 和输出层的参数 $V \times D$ 更多、输出层每个位置的计算量更大、罕见 token 训练不充分；词表小则相反。规模更大、语言更多的模型倾向于更大的词表。
5. **模型为什么数不对字母、算不准多位数？**
   模型看到的是 token 编号，不是字符。一个词、一个数字被切成的块不规则，内部字符对模型不透明，位值也对不齐。缓解办法有限制数字块长度、把数字逐位切开，或在输入里把词拆成字符。
6. **同样的内容，为什么不同语言的 token 数差很多？**
   词表主要由英文等高资源语言的语料学出，这些语言的常见词都有对应的合并；其他语言的合并少，被切得更碎。结果是上下文窗口等效变短、推理变慢、按 token 计费变贵。
