## 解决什么问题

预训练得到的基础模型只会续写文本。**后训练**把它变成会对话、会按指令办事、会推理、会调用工具的助手。不管哪个阶段，训练代码都绕不开同一组操作：

- **把对话变成 token**：按聊天模板拼接系统提示、用户消息、助手回答、工具返回，并记住每个 token 是谁写的。
- **只在该学的位置算损失**：只有助手（也就是模型自己）写的 token 计入损失，提示词、工具返回、填充都屏蔽掉。
- **从 logits 取出每个 token 的对数概率**：SFT 用它算交叉熵，DPO 用它求和得到序列对数概率，PPO、GRPO 用它算重要性比率。

本专题的题目就是这几块地基，后面「偏好优化」「强化学习对齐」专题都建立在它们之上。

## 一条典型的后训练流水线

| 阶段 | 数据 | 损失 | 作用 |
| --- | --- | --- | --- |
| SFT | 人写或强模型生成的示范对话 | 只在助手 token 上的交叉熵 | 学会对话格式和基本的指令遵循 |
| 拒绝采样微调（RFT） | 模型自己生成、经过筛选的好回答 | 同 SFT | 用自己的高质量样本强化自己 |
| 蒸馏 | 强模型（教师）的输出或分布 | 序列级：SFT；token 级：KL | 把大模型或推理模型的能力迁移到小模型 |
| 偏好优化 | 成对偏好或好坏标签 | DPO 一族 | 对齐人的偏好 |
| 强化学习 | 问题 + 奖励（奖励模型或规则） | PPO、GRPO 一族 | 提升推理、代码这类能自动判对错的能力 |

不同团队的组合方式不同，几个有代表性的例子：

- **InstructGPT（2022）**：SFT → 奖励模型 → PPO。
- **Llama 2（2023）**：SFT 后多轮迭代，每轮先拒绝采样微调，后期再加 PPO。
- **Llama 3（2024）**：多轮 SFT + 拒绝采样 + DPO，没有用 PPO。
- **DeepSeek-R1（2025）**：少量长思维链数据冷启动 SFT → 推理 RL → 用 RL 模型拒绝采样出大批数据再做 SFT → 覆盖全场景的第二轮 RL；同时把 R1 的输出蒸馏到多个小模型（R1-Distill，只做 SFT，不做 RL）。

## 对比：几种「学别人的回答」

| | 数据来自 | 损失 | 特点 |
| --- | --- | --- | --- |
| SFT | 人或别的模型 | 交叉熵 | 简单稳定，但学的是别人的分布，容易出现训练和生成分布不一致 |
| RFT | 模型自己，经过筛选 | 交叉熵 | 数据和模型分布接近；只用好样本，坏样本被浪费 |
| 序列级蒸馏 | 教师生成的回答 | 交叉熵 | 等价于用教师数据做 SFT，只需要教师的文本输出 |
| token 级蒸馏 | 教师对每个位置的完整分布 | 前向 KL、反向 KL 或 JSD | 信号更密集，需要教师和学生共用词表 |
| 在线蒸馏 | 学生自己生成，教师打分布 | 反向 KL 为主 | 训练分布就是学生的生成分布，像不需要奖励的 RL |

## 演进

1. **指令微调（2021–2022）**：FLAN 等工作把大量任务改写成指令格式做 SFT；InstructGPT 用人写的示范对话做 SFT，作为 RLHF 的起点。
2. **用自己的样本训练自己（2023）**：拒绝采样微调流行起来。模型生成多个回答，用奖励模型或验证器挑出好的，再拿来做 SFT，Llama 2 的多轮迭代就是这么做的。
3. **偏好优化替代部分 RL（2023–2024）**：DPO 出现后，很多团队用 SFT + 拒绝采样 + DPO 的组合取代 PPO，比如 Llama 3。
4. **推理 RL 与蒸馏（2025）**：DeepSeek-R1 用规则奖励的大规模 RL 训练出长链推理，再把 R1 的输出直接蒸馏给小模型；在线蒸馏（学生自己生成、教师给 token 级分布）也被用作 RL 的廉价替代。
5. **Agent 化**：训练数据从单轮问答变成多轮工具调用轨迹，损失掩码要区分模型生成的 token 和环境返回的 token。

## 多轮与 Agent

Agent 轨迹是「助手 → 工具 → 助手 → 工具 → …」交替出现的长序列。两条规则：

- **工具和环境返回的 token 不计损失**：它们不是策略生成的，计入损失等于让模型去预测环境，在 RL 里还会让比率没有意义。
- **保留生成时的 token id**：不要把整段对话转成文本再重新分词。重新分词可能和生成时切得不一样，训练时算的对数概率就对不上生成时的分布。

另外，被截断的轨迹拿不到可靠的结果奖励，常见做法是整条屏蔽，不参与训练。

## 怎么选

- **刚起步、有示范数据**：先做 SFT，把格式和基本能力打牢，后面的偏好优化和 RL 都依赖一个靠谱的起点。
- **想要推理能力、手里有强推理模型**：小模型直接做蒸馏（R1 的报告指出，对小模型来说，蒸馏比直接在小模型上做 RL 效果更好）。
- **模型能生成一些好回答，但不稳定**：拒绝采样微调，或者直接上 RL。
- **训练 Agent**：多轮轨迹 + 屏蔽工具 token 的损失掩码，再接 RL。

## 题目顺序

1. **逐 token 对数概率**：logits 和 token 错一位对齐、按掩码取出回答部分，后面所有损失都从这里开始。
2. **SFT 损失：助手掩码与样本打包**：只在助手 token 上算交叉熵，多条样本拼成一行时不跨样本预测，两种平均方式的区别。
3. **知识蒸馏损失：前向 KL / 反向 KL / JSD**：前向 KL、反向 KL 和 JSD，以及温度。
4. **Agent 多轮轨迹掩码**：把多轮对话拼成训练张量，只训练助手 token，截断的轨迹整条屏蔽。

## 面试追问

1. **SFT 时为什么只在助手的 token 上算损失？**
   提示词是给定的条件，不是要学会生成的内容；在提示词上算损失会让模型浪费容量去模仿用户，还可能学会替用户说话。多轮对话里每一轮助手回答都要算。
2. **样本打包（packing）要注意什么？**
   不能让一个样本的最后一个 token 去预测下一个样本的第一个 token；注意力也要按样本隔开（变长注意力或块对角掩码），位置编号每个样本从 0 重新开始。
3. **拒绝采样微调和 RL 有什么关系？**
   RFT 可以看成只用正样本、奖励是 0/1 的离线策略改进；RL 还能利用负样本，并且一直在线地从当前策略采样。
4. **前向 KL 和反向 KL 蒸馏有什么不同？**
   前向 KL $\operatorname{KL}(p_T \Vert p_S)$ 要求学生覆盖教师所有有概率的地方（覆盖众数），小学生容易把概率摊得太平；反向 KL 让学生集中在教师的高概率区域（寻找众数），生成更干净，但可能丢掉多样性。
5. **训练 Agent 时，工具返回的内容为什么要屏蔽损失？**
   它们由环境产生，不是策略的动作；计入损失会让模型去拟合环境输出，在 RL 里这些 token 也没有对应的旧策略概率，比率没有意义。
