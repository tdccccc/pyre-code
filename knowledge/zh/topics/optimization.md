## 解决什么问题

训练就是反复做同一件事：前向算损失，反向算梯度，用梯度更新参数。把这一步抽象出来：

$$
\theta_t = \theta_{t-1} - \eta_t \cdot u_t, \qquad u_t = \operatorname{opt}(g_t, \text{状态})
$$

$g_t$ 是梯度，$\eta_t$ 是第 $t$ 步的学习率，$u_t$ 是优化器根据梯度（和它自己保存的状态）算出的更新方向。这个专题里的每个技巧，都在这条式子的某一处动手：

- **$u_t$**：优化器怎么把梯度变成更新。Adam 一题。
- **$\eta_t$**：学习率随时间怎么变。Cosine LR 一题。
- **$g_t$**：更新之前先处理梯度，防止异常值，或者攒出更大的 batch。梯度裁剪、梯度累积两题。
- **数值格式与激活**：在不改变数学的前提下，让同样的显存和时间装得下更大的模型、更长的序列。混合精度、激活检查点两题。

一个完整的训练迭代把它们串起来：

1. 对每个微批次：前向（低精度）→ 损失除以 $n$ → 反向，梯度累加进 `.grad`。
2. 累积完成后：（用了 loss scaling 就先反缩放）→ 梯度裁剪 → `optimizer.step()` → `scheduler.step()` → 清零梯度。

## 对比

| 技巧 | 作用在哪 | 解决什么 | 付出什么 |
| --- | --- | --- | --- |
| Adam / AdamW | 更新方向 $u_t$ | 各参数梯度尺度不同、噪声大 | 每个参数多两份 fp32 状态 |
| 学习率调度 | 学习率 $\eta_t$ | 早期不稳，后期不收敛 | 余弦要预先知道总步数 |
| 梯度裁剪 | 梯度 $g_t$ | 异常 batch 造成梯度突刺 | 多读一遍梯度，分布式要多一次通信 |
| 梯度累积 | batch 大小 | 单卡装不下目标 batch | 不省参数和状态，微批次小了会降低利用率 |
| 混合精度 | 数值格式 | 显存和速度 | fp16 有下溢风险，需要 loss scaling |
| 激活检查点 | 激活的存储 | 激活显存太大 | 约 $33\%$ 额外的前向计算 |

## 演进

**优化器**：

1. **SGD**：$\theta \leftarrow \theta - \eta\, g$，所有参数共用一个步长。
2. **Momentum**：对梯度做滑动累积，平滑噪声，在一致的方向上加速。

$$
m_t = \mu\, m_{t-1} + g_t, \qquad \theta_t = \theta_{t-1} - \eta\, m_t
$$

3. **自适应步长**（AdaGrad、RMSProp）：用梯度平方的累积（或滑动平均）给每个参数缩放步长。
4. **Adam（2014）**：动量加 RMSProp，再加偏差校正。大模型训练的基础。
5. **AdamW（2017）**：发现 Adam 里的 L2 正则和自适应缩放纠缠在一起，权重衰减的效果不稳定，于是把衰减解耦出来，直接作用在参数上（公式见 Adam 一题）。现在几乎所有大模型预训练的默认选择。
6. **新优化器**：近年出现的 Lion（只保存一份动量）、Muon（对矩阵形参数的更新做正交化）等在特定设置下有收益，但是否能稳健地取代 AdamW 仍在讨论，面试知道名字和大致思路即可。

**学习率调度**：

1. 常数学习率；SGD 时代常用阶梯式衰减。
2. **线性预热**：Transformer 训练的标配，解决早期不稳定（Adam 的二阶矩没估准，Post-LN 梯度不稳）。
3. **预热 + 余弦衰减**：GPT-3、LLaMA 一类模型的常见选择。
4. **WSD**：预热、稳定、末段衰减。不依赖预先固定的总步数，方便续训，近年的新做法之一。

## 余弦与 WSD

| | 预热 + 余弦 | WSD |
| --- | --- | --- |
| 曲线 | 预热后沿余弦持续下降 | 预热后保持恒定，末段快速衰减 |
| 是否需要预先知道总步数 | 需要，曲线形状由总步数决定 | 稳定阶段不需要，临近结束再决定衰减 |
| 中途的检查点 | 学习率还没降下来，评估偏差 | 稳定阶段的检查点接一段衰减即可得到可用模型 |
| 续训、加训 | 不方便 | 方便，从稳定阶段的检查点继续 |
| 使用情况 | LLaMA 等大量模型 | MiniCPM 等近年工作 |

两者在训练结束时学习率都要降到很低，衰减阶段是 loss 下降的主要来源（详见 Cosine LR 一题）。

## 用时间换显存

显存由四部分组成：参数、梯度、优化器状态，以及与 batch 和序列长度成正比的**激活**。后三种手段针对的部分不同：

| 手段 | 省的 | 付出的 | 不省的 |
| --- | --- | --- | --- |
| 梯度累积 | 激活，变成微批次大小 | 没有额外计算，但小批次利用率低 | 参数、梯度、优化器状态 |
| 混合精度 | 激活和梯度减半，矩阵乘更快 | 数值风险；多存一份主权重 | 优化器状态 |
| 激活检查点 | 激活，随层数成正比降到约 $\sqrt{L}$ 或每层仅存输入 | 约 $33\%$ 额外的前向计算 | 参数、梯度、优化器状态 |

参数、梯度、优化器状态的开销要靠 ZeRO / FSDP 把它们切到多张卡上（见「分布式训练」专题）。每一项占多少字节、总共需要多少显存，见「性能估算」专题的 Training Memory 一题。

混合精度是其中唯一**既省显存又更快**的，所以通常最先打开；剩下两种在需要时叠加。

## 怎么选

- **优化器**：Transformer 默认 AdamW。常见设置是 $\beta_1 = 0.9$、$\beta_2$ 取 $0.95$ 到 $0.999$、权重衰减 $0.1$ 左右。CNN 上 SGD 加动量仍然常用。
- **学习率调度**：线性预热加余弦衰减是安全的默认值；总训练量不固定、需要续训或加训时，考虑 WSD。
- **梯度裁剪**：基本都开，最大范数 $1.0$ 很常见。把范数记进日志，它是不稳定的早期信号。
- **数值格式**：有 bf16 硬件就用 bf16，不需要 loss scaling；只能用 fp16 时必须配动态 loss scaling。
- **显存不够时**，大致按这个顺序：
  1. 开 bf16。
  2. 微批次调小，用梯度累积凑目标 batch。
  3. 微批次已经是 $1$ 还装不下（长序列），开激活检查点，必要时只重算注意力部分。
  4. 参数和优化器状态本身装不下，上 ZeRO / FSDP 或张量并行。

## 题目顺序

1. **Adam**：整个专题的底座，先把一阶矩、二阶矩、偏差校正写对，也理解优化器状态为什么占显存。
2. **Cosine LR**：纯数学的分段函数，学习率怎么随步数变化，预热为什么需要。
3. **梯度裁剪**：处理梯度的最简单例子，全局范数和等比缩放。
4. **梯度累积**：用循环把多个微批次的梯度攒起来，注意缩放和清零的位置。
5. **混合精度**：数值格式登场，涉及 loss scaling、反缩放、主权重，需要前面的优化器和梯度处理作为背景。
6. **激活检查点**：最后一个，和 autograd 的保存机制打交道，用计算换激活显存。

## 面试追问

1. **一个训练迭代里，反缩放、梯度裁剪、优化器更新、学习率调度的顺序是什么？**
   反向 → 反缩放（用了 loss scaling 时）→ 梯度裁剪 → `optimizer.step()` → `scheduler.step()` → 清零梯度。反缩放必须在裁剪之前，否则阈值比的是被放大的梯度；梯度累积时，反缩放、裁剪和更新都在累积完成之后，各只做一次。
2. **训练中 loss 突然飙升或变成 NaN，怎么排查？**
   先看梯度范数和学习率的日志，确认是不是在某一步突刺。常见处理：加梯度裁剪、延长预热、调小学习率或 $\beta_2$；fp16 的话检查是否溢出，改用 bf16；检查数据里有没有异常样本。大规模训练还有一种做法（PaLM 采用）：回退到出问题之前的检查点，并跳过触发问题的那部分数据。
3. **显存不够，你会按什么顺序处理？**
   先开 bf16（几乎没有代价）；再用梯度累积把微批次调小；还装不下就加激活检查点，用约三分之一的计算换激活；参数和优化器状态太大时用 ZeRO / FSDP。关键是先判断显存主要花在哪一部分。
4. **梯度累积和激活检查点都能让你训练更大的 batch，区别是什么？**
   累积靠缩小每次前反向处理的样本数，不增加计算；检查点靠丢掉并重算中间激活，样本数不变、多花计算。两者可以同时用，也都不会减少参数和优化器状态。
5. **用 Adam 训练时，每个参数占多少字节？**
   常见的混合精度设置下是 $16$ 字节：低精度权重 $2$、梯度 $2$、fp32 主权重 $4$、一阶矩 $4$、二阶矩 $4$。优化器状态加主权重占了其中的 $12$ 字节，这就是 ZeRO 要切分的对象。
