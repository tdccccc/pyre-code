## 解决什么问题

预训练和 SFT 只教模型**模仿**数据里的文本，而我们真正想要的是「人更喜欢的回答」「答对了的推理」。**对齐**（alignment）就是用偏好或可验证的结果去调整模型。这类方法共享同一个目标：最大化奖励，同时不要离参考模型 $\pi_{\text{ref}}$（通常是 SFT 模型）太远：

$$
\max_{\pi}\ \mathbb{E}_{y \sim \pi(\cdot \mid x)}\bigl[r(x, y)\bigr] - \beta\, \operatorname{KL}\bigl(\pi \,\Vert\, \pi_{\text{ref}}\bigr)
$$

PPO、DPO、GRPO 是这个目标的三种求解方式，区别在于：奖励从哪来、优势怎么估计、要不要在线采样。

**经典 RLHF 流程**（InstructGPT 采用的三步）：

1. **SFT**：用人写的示范回答做监督微调，得到起点 $\pi_{\text{ref}}$。
2. **奖励模型**：对同一个问题收集多个回答，让人排序或挑出更好的；用 Bradley-Terry 模型训练一个打分器（Reward Model 一题）。
3. **强化学习**：采样回答，用奖励模型打分，用 PPO 优化策略，并用 KL 约束把它拴在 $\pi_{\text{ref}}$ 附近。

## 对比

| 方法 | 需要的模型 | 在线采样 | 显存 | 稳定性 |
| --- | --- | --- | --- | --- |
| PPO | policy、reference、reward、critic | 是 | 最大，四个模型 | 超参多，较难调 |
| DPO | policy、reference | 否 | 小，reference 的对数概率可预先算好 | 稳定，训练像监督学习 |
| GRPO | policy、reference、reward（可以是规则） | 是 | 中，没有 critic | 比 PPO 简单，仍要调采样和 KL |

其中 reward 可以是训练好的奖励模型，也可以是一段规则代码（见下面的可验证奖励）。DPO 不需要显式的奖励模型。

三种方法在「学习信号」和「KL 约束」上的做法：

| | 学习信号 | KL 约束 |
| --- | --- | --- |
| PPO | critic + GAE 得到每个 token 的优势 | 写进奖励：每个 token 扣 $\beta \log(\pi / \pi_{\text{ref}})$ |
| DPO | 偏好对的隐式奖励之差，没有显式优势 | 隐含在闭式解里，由 $\beta$ 和 reference 体现 |
| GRPO | 同一问题一组回答的组内标准化奖励 | 作为损失项直接加上 |

## 演进

1. **偏好学习与 PPO（2017）**：Christiano 等人提出从人类比较中学习奖励，同一年 Schulman 等人提出 PPO，成为后来 RLHF 的标准优化器。
2. **InstructGPT（2022）**：把 SFT → 奖励模型 → PPO 这条流水线用到大语言模型上，奠定了 RLHF 的标准流程。
3. **DPO（2023）**：把带 KL 约束的目标推成闭式，直接在偏好对上训练，绕开奖励模型和 RL 采样。之后有一批变体（IPO、KTO、SimPO 等，见 DPO 一题的延伸）。
4. **GRPO（2024）**：DeepSeekMath 提出，用组内相对奖励代替 critic，省掉一个与策略同尺寸的模型。
5. **可验证奖励（2025）**：DeepSeek-R1 在数学、代码等能自动判对错的任务上，直接用规则奖励配合 GRPO 训练推理能力。

## PPO 的核心思路

三个部件，各自解决一个问题：

- **裁剪目标**：同一批样本更新多步，靠重要性比率修正分布差异，再把比率裁剪在 $[1-\epsilon, 1+\epsilon]$ 内，防止一步走得太远（PPO 损失一题）。
- **KL 惩罚**：RLHF 里每个 token 的奖励是

$$
r_t = -\beta \log \frac{\pi_\theta(a_t \mid s_t)}{\pi_{\text{ref}}(a_t \mid s_t)}
$$

  序列最后一个 token 再加上奖励模型的打分。这样策略越偏离参考模型，累计奖励越低。
- **GAE**（Generalized Advantage Estimation，广义优势估计）：用 critic 给出的价值 $V$ 估计每个 token 的优势：

$$
\delta_t = r_t + \gamma V(s_{t+1}) - V(s_t)
$$

$$
\hat A_t = \sum_{l \ge 0} (\gamma \lambda)^l\, \delta_{t+l}
$$

  $\lambda = 0$ 是单步 TD，方差小、偏差大；$\lambda = 1$ 等于蒙特卡洛回报减基准，偏差小、方差大。$\lambda$ 在两者之间折中。这里的 GAE 与「图神经网络」专题里的 gae 题（图自编码器）同名不同物。

PPO 要同时维护 policy、reference、reward、critic 四个模型，critic 还要单独训练，这是它显存大、难调的主要原因。

## DPO 为什么能省掉奖励模型

关键在于带 KL 约束的目标有闭式最优解 $\pi^* \propto \pi_{\text{ref}}\, e^{r/\beta}$，于是奖励可以反过来用策略表示：

$$
r(x, y) = \beta \log \frac{\pi^*(y \mid x)}{\pi_{\text{ref}}(y \mid x)} + \beta \log Z(x)
$$

Bradley-Terry 只看两个回答的奖励之差，同一个 $x$ 下的 $\beta \log Z(x)$ 相减抵消。于是偏好对的似然只依赖策略和参考模型，直接对策略做最大似然，不用先训奖励模型，也不用采样。

代价是它是**离线**的：偏好数据通常来自别的模型，策略训练过程中自己的分布变了，数据却不变。

## GRPO 与可验证奖励

PPO 里 critic 的作用只是提供基准。GRPO 换一个思路：对同一个问题采样 $G$ 个回答，用组内平均奖励当基准，再除以组内标准差（GRPO 损失一题）。没有 critic，也就没有价值网络要训练。

这套办法特别适合**可验证奖励**（Reinforcement Learning with Verifiable Rewards，RLVR）：奖励由程序判定，比如

- 数学题：最终答案与标准答案是否一致；
- 代码题：能否通过单元测试；
- 格式：推理过程是否放在规定的标签里。

DeepSeek-R1-Zero 对基础模型直接用这类规则奖励（准确性奖励和格式奖励）做 GRPO，没有用神经网络奖励模型。规则奖励不会像神经网络打分器那样被「说服」，被利用的空间小得多，但并非完全没有，比如模型可能钻测试用例的漏洞。

## 奖励作弊与 KL 的作用

**奖励作弊**（reward hacking）：奖励模型只是人类真实偏好的**代理**。策略被优化得越狠，越容易找到代理打高分、真实质量却不高的输出，这是 Goodhart 定律的体现。常见表现有：

- 回答越写越长，因为奖励模型偏爱长回答；
- 语气谄媚、堆砌看起来很专业的措辞；
- 钻奖励模型没见过的分布里的漏洞，得到很高的分数。

Gao 等人（2022）的实验显示：随着策略偏离初始模型越来越远，代理奖励一路上升，而用「金标准」衡量的真实奖励先升后降。

**KL 惩罚的作用**就是限制策略偏离 $\pi_{\text{ref}}$，让它待在奖励模型见过、评分可信的区域。$\beta$ 的取舍：

- $\beta$ 太小：策略自由度大，更容易作弊，也可能丢掉 SFT 学到的语言能力。
- $\beta$ 太大：策略几乎不动，对齐效果有限。

其他缓解办法：奖励模型集成、早停、对长度做惩罚或归一化、定期用新数据更新奖励模型、改用规则奖励。DPO 没有显式奖励模型，但它的隐式奖励同样会被利用，常见的也是回答变长。

## MCTS 与推理时搜索

前面的方法都在**训练时**改权重。另一条线是**推理时**多花算力：不改模型，在生成时做搜索，由验证器或奖励模型挑出更好的结果。

| 方法 | 做法 |
| --- | --- |
| Best-of-N | 独立采 $N$ 个完整回答，用奖励模型或验证器挑最好的 |
| 带过程奖励的 Beam Search | 每走一步用过程奖励模型（PRM）打分，保留得分高的若干条路径 |
| MCTS | 用树结构记住各步的统计量，反复「选择 → 扩展 → 评估 → 回传」，把计算集中到有希望的分支 |

奖励模型可以给整条回答打一个分（结果奖励，ORM），也可以给每一步推理打分（过程奖励，PRM）。搜索需要中间步骤的价值，所以更依赖 PRM 或价值模型。

MCTS 选择子节点时用 **UCT**（UCB1 用在树上）。UCB1 来自多臂老虎机，经典形式是

$$
\operatorname{UCT}(i) = Q(i) + c \sqrt{\frac{\ln N}{n_i}}
$$

$Q(i)$ 是子节点平均价值，$n_i$ 是它的访问次数，$N$ 是父节点访问次数，$c$ 是探索常数。AlphaGo / AlphaZero 系列改用 **PUCT**，把策略网络给出的先验概率 $P(a)$ 加了进来：

$$
\operatorname{PUCT}(a) = Q(a) + c\, P(a)\, \frac{\sqrt{N}}{1 + n_a}
$$

先验大的动作更早被探索。用在 LLM 上，$P(a)$ 可以取语言模型对下一步的概率，$Q$ 由 PRM 或价值模型评估，取代随机 rollout。

LLM 上的 MCTS 比围棋难得多：动作空间是整个词表，通常要以「一步推理」而不是单个 token 为节点；价值模型难训练；每次评估都要调用大模型，很贵。DeepSeek-R1 的报告把 MCTS 列在没有成功的尝试里，原因包括搜索空间大和难以训练出足够好的价值模型。至于 o1 一类模型具体怎么做推理，细节没有公开，不要断言它用了 MCTS。

## 怎么选

- **有成对偏好数据、资源有限**：DPO 或它的变体，实现最简单，训练稳定。
- **任务能自动判对错**（数学、代码）：GRPO 配规则奖励，不需要奖励模型和 critic。
- **奖励难以验证，需要在线探索**：PPO，或者 GRPO 配奖励模型，要接受更高的工程成本。
- **不想动权重、可以在推理时多花算力**：Best-of-N、带 PRM 的 Beam Search 或 MCTS。

## 题目顺序

1. **Reward Model**：最基础的一环，先把成对偏好的 Bradley-Terry 损失写对，后面的 DPO 直接用到同一个形式。
2. **PPO 损失**：经典的在线 RL 目标，学会重要性比率和裁剪。
3. **DPO 损失**：把前两题合起来看，Bradley-Terry 的奖励换成策略与参考模型的对数概率比，不再需要采样。
4. **GRPO 损失**：回到在线 RL，把 critic 换成组内相对优势，需要按组统计。
5. **MCTS**：从训练转到推理时搜索，用 UCB 平衡探索与利用。

## 面试追问

1. **完整的 RLHF 流程是什么？**
   三步：SFT 得到初始策略；用人类成对偏好训练奖励模型（Bradley-Terry 损失）；用 PPO 在奖励模型上优化策略，并加 KL 惩罚拴住参考模型。
2. **PPO、DPO、GRPO 的核心区别？**
   PPO 在线采样，用 critic 估计优势，要四个模型；DPO 离线，直接在偏好对上训练，只要策略和参考模型；GRPO 在线采样，用组内相对奖励代替 critic，省掉一个模型。
3. **什么是奖励作弊？怎么缓解？**
   策略利用奖励模型的漏洞拿高分、真实质量却不高，比如把回答写得很长。缓解办法：KL 惩罚、奖励模型集成、早停、长度惩罚，能验证的任务就改用规则奖励。
4. **为什么 RLHF 里要有 KL 项？**
   一方面防止策略为了奖励偏离语言分布，丢掉预训练和 SFT 学到的能力；另一方面把策略限制在奖励模型评分可信的区域，减少作弊。
5. **DPO 真的不需要强化学习吗？**
   它不需要显式的奖励模型和在线采样，是闭式推导出的监督式损失，但它与带 KL 约束的 RL 目标等价，隐式奖励就是 $\beta \log(\pi_\theta / \pi_{\text{ref}})$。代价是离线、依赖偏好数据的分布，也依赖 Bradley-Terry 假设。
6. **可验证奖励的好处和局限？**
   好处是奖励准确、便宜、难以被「说服」；局限是只适用于有标准答案或可自动检验的任务，写作、开放对话这类任务仍然需要奖励模型，规则奖励也可能被钻空子。
7. **MCTS 和 Best-of-N 有什么不同？**
   Best-of-N 对每个回答独立采样、最后才评分，算力平均分配；MCTS 按中间步骤的价值动态分配算力，把更多采样给有希望的分支，但需要能评估中间步骤的价值模型，实现也更复杂。
