## 解决什么问题

SFT 只教模型**模仿**示范回答。想让模型学会「答对」「人更喜欢」，就要让它自己生成、拿到奖励、再往高奖励的方向调整，这就是强化学习（RL）这条线。几乎所有方法都在优化同一个目标：最大化奖励，同时不要离参考模型 $\pi_{\text{ref}}$（通常是 SFT 模型）太远：

$$
\max_{\pi_\theta}\ \mathbb{E}_{y \sim \pi_\theta(\cdot \mid x)}\bigl[r(x, y)\bigr] - \beta\, \operatorname{KL}\bigl(\pi_\theta \,\Vert\, \pi_{\text{ref}}\bigr)
$$

落到代码里，每个方法都要回答四个问题：

1. **学习信号**：每个 token 的优势 $A_t$ 怎么来？critic 加 GAE，还是同一问题多个回答之间互相比较？
2. **更新幅度**：同一批数据要更新多步，用重要性比率 $\rho = \pi_\theta / \pi_{\text{old}}$ 修正分布差异，再裁剪 $\rho$，防止一步走太远。比率按 token 算，还是按整条序列算？
3. **KL 放在哪**：扣在每个 token 的奖励里（PPO），作为损失项加上（GRPO），还是干脆不要（DAPO 等）？
4. **怎么平均**：每个 token 的损失怎么聚合成一个数？按序列平均、按 token 平均，还是除以常数？

本专题的题目就沿着这四个问题展开。偏好数据上的离线方法（DPO 一族）见「偏好优化」专题，奖励从哪来、怎么评测见「奖励、评测与推理时搜索」专题。

## 对比

| 方法 | 学习信号（基线） | 是否除以标准差 | 比率与裁剪 | KL | 聚合 |
| --- | --- | --- | --- | --- | --- |
| PPO（RLHF） | critic + GAE | 常做 batch 级白化 | token 级，对称 $\epsilon$ | 进奖励，每 token 扣 $\beta \cdot$ k1 | token 平均 |
| GRPO | 组内均值 | 组内标准差 | token 级，对称 $\epsilon$ | 进损失，k3 | 先序列内平均再跨序列平均 |
| Dr. GRPO | 组内均值 | 否 | token 级 | 通常不用 | 除以常数长度 |
| RLOO | 组内其他回答的均值（留一法） | 否 | 原论文不裁剪；框架里常配 PPO 裁剪 | 进奖励 | 依实现 |
| REINFORCE++-baseline | 组内均值 | 全 batch 白化 | token 级 | 进奖励或损失 | token 平均 |
| DAPO | 组内均值 | 组内标准差 | token 级，**上下界不对称**（clip-higher） | 不用 | token 平均 |
| GSPO | 组内均值 | 组内标准差 | **序列级**（长度归一化的几何平均），范围很小 | 可选 | 按序列 |

显存与工程成本：

| | 需要的模型 | 额外成本 |
| --- | --- | --- |
| PPO | actor、critic、reference、reward | critic 和 actor 同尺寸，还要单独训练 |
| GRPO 一族 | actor、reference（可省）、reward（可以是规则） | 每个问题要采 $G$ 个回答，生成量大 |

## 演进

1. **PPO（2017）**：Schulman 等人提出裁剪的代理目标，成为 RLHF 的标准优化器。
2. **InstructGPT（2022）**：SFT → 奖励模型 → PPO，KL 扣在每个 token 的奖励里。
3. **RLOO 回归（2024）**：Ahmadian 等人的 *Back to Basics* 指出，LLM 的 RLHF 不需要 PPO 的全部机制，REINFORCE 加留一法基线就够用，还省掉 critic。
4. **GRPO（2024）**：DeepSeekMath 用组内标准化奖励代替 critic，KL 改成损失项，用 k3 估计。
5. **DeepSeek-R1（2025）**：在数学、代码上用规则奖励配 GRPO，训练出长链推理，带火了可验证奖励（RLVR）。
6. **一批修补（2025）**：
   - **DAPO**：clip-higher 防熵塌缩，动态采样丢掉没有信号的组，超长回答按长度扣分，改成 token 平均。
   - **Dr. GRPO**：指出 GRPO 的两个偏差，即按序列平均带来的长度偏差和除以标准差带来的难度偏差，两处都去掉。
   - **REINFORCE++**：用全 batch 的统计量做归一化，比组内归一化更稳。
   - **GSPO**（Qwen3）：奖励是整条序列的，比率也应该按序列算；对 MoE 模型尤其更稳。

## PPO 的核心思路

三个部件，各自解决一个问题：

- **裁剪目标**：同一批样本更新多步，靠重要性比率修正分布差异，再把比率裁剪在 $[1-\epsilon, 1+\epsilon]$ 内（「PPO 损失」「完整版 PPO 损失」两题）。
- **KL 惩罚进奖励**：RLHF 里每个 token 的奖励是

$$
r_t = -\beta \log \frac{\pi_{\text{old}}(a_t \mid s_t)}{\pi_{\text{ref}}(a_t \mid s_t)}
$$

  序列最后一个 token 再加上奖励模型的打分。策略越偏离参考模型，累计奖励越低。
- **GAE**（广义优势估计）：用 critic 给出的价值 $V$ 估计每个 token 的优势：

$$
\delta_t = r_t + \gamma V(s_{t+1}) - V(s_t), \qquad \hat A_t = \sum_{l \ge 0} (\gamma \lambda)^l\, \delta_{t+l}
$$

  $\lambda = 0$ 是单步 TD，方差小、偏差大；$\lambda = 1$ 是蒙特卡洛回报减基线，偏差小、方差大（「RLHF 奖励与 GAE」一题）。这里的 GAE 与「图神经网络」专题里的 gae 题（图自编码器）同名不同物。

**KL 放奖励里还是放损失里**：放奖励里，KL 会经过 GAE 影响到前面所有 token 的优势，是在优化「带 KL 惩罚的回报」；放损失里，KL 只是对每个 token 单独加的正则，和优势无关，实现更简单。前者用 k1（采样估计、无偏），后者常用 k3（恒非负、方差小），细节见「KL 估计器 k1 / k2 / k3」。

## GRPO 与它之后的改进

GRPO 去掉 critic：对同一个问题采 $G$ 个回答，用组内均值当基线，再除以组内标准差。实践中暴露出几类问题，后来的方法各补一处：

- **没有信号的组**：一组回答全对或全错，组内优势全是 $0$，这组数据只贡献 KL 梯度，有效 batch 变小。DAPO 的**动态采样**把这些组过滤掉，再补采到够数。
- **熵塌缩**：对称裁剪下，低概率 token 的概率很难被大幅提高（上界 $1+\epsilon$ 对小概率是很小的绝对增量），策略越来越确定，探索消失。DAPO 把上界放宽（clip-higher，如 $0.2 / 0.28$）。
- **长度偏差**：按序列平均时，长回答里每个 token 的权重更小。答错的长回答被惩罚得轻，模型倾向于写长；答对的短回答被奖励得重。DAPO 改成 token 平均，Dr. GRPO 改成除以常数（「损失聚合方式」）。
- **难度偏差**：除以组内标准差，会放大奖励几乎一致（太难或太简单）的问题的权重。Dr. GRPO 不除标准差，REINFORCE++ 改用全 batch 的标准差（「组内基线：GRPO / Dr. GRPO / RLOO / REINFORCE++」）。
- **比率粒度**：奖励给的是整条序列，token 级的比率却在逐 token 修正，方差随长度累积。GSPO 改用长度归一化的序列级比率（「GSPO 序列级比率损失」）。

## 奖励作弊与 KL 的作用

**奖励作弊**（reward hacking）：奖励只是真实目标的**代理**。优化得越狠，越容易找到代理打高分、真实质量却不高的输出，即 Goodhart 定律。常见表现：

- 回答越写越长，因为奖励模型偏爱长回答；
- 语气谄媚、堆砌看起来专业的措辞；
- 钻规则奖励的漏洞，比如只输出格式正确的框、改测试而不是改代码。

Gao 等人（2022）的实验显示：随着策略偏离初始模型，代理奖励一路上升，而用金标准衡量的真实奖励先升后降。

**KL 惩罚**把策略限制在参考模型附近，让它待在奖励模型评分可信的区域。$\beta$ 太小容易作弊、丢掉语言能力，太大则几乎学不动。用规则奖励训练长链推理时，策略本来就需要大幅偏离初始模型，所以很多配置把 KL 设得很小或去掉（DAPO 去掉 KL 时给出的就是这个理由）。其他缓解办法：奖励模型集成、早停、长度惩罚、定期用新数据更新奖励模型。

## RL 训练框架怎么搭

一步 RL 的数据流：

1. **生成（rollout）**：推理引擎（vLLM、SGLang）用当前策略对一批问题各采 $G$ 个回答。这一步通常占掉大部分时间，长回答形成长尾，拖住整批。
2. **打分**：奖励模型前向，或者跑规则（答案比对、单元测试、沙箱执行）。
3. **准备训练量**：训练引擎对生成的序列做前向，得到 `old_logps`、`ref_logps`，PPO 还要 critic 的 `values`（「逐 token 对数概率」）。
4. **算优势**：GAE 或组内基线。
5. **更新**：把 batch 切成 mini-batch，更新一到若干轮。
6. **同步权重**：把新权重推给推理引擎，进入下一步。

几个绕不开的工程问题：

- **放在哪**：**共置**（colocate）是生成和训练共用同一批卡、分时复用，切换时卸载显存或换布局，资源利用率高（verl 的 HybridEngine 是这一类）。**分离**是两组卡各干各的，靠 Ray 之类调度，扩展灵活，但两边会互相等待（OpenRLHF 的 Ray 放置组可以两种都配）。
- **异步与离策略**：让生成提前跑几步，训练用的就是稍旧的策略采的数据。吞吐上去了，但比率不再接近 $1$，需要更依赖裁剪或做重要性修正；长回答可以分段生成（partial rollout），下一步接着生成。
- **训推不一致**：推理引擎和训练引擎的 kernel、精度、MoE 路由都可能不同，同一个 token 在两边算出的对数概率不一样，哪怕严格 on-policy，比率也不等于 $1$。常见做法是 `old_logps` 一律由训练引擎重算，而不是直接用推理引擎返回的；进一步可以用截断重要性采样（TIS）按 $\min\bigl(\pi_{\text{train}} / \pi_{\text{rollout}},\, C\bigr)$ 给每个 token 加权修正。
- **显存**：PPO 要放 actor、critic、reference、reward 四个模型；reference 不训练，可以卸载到 CPU，用 LoRA 时干脆用「关掉 adapter 的同一个模型」当 reference。
- **常见框架**：TRL（和 Hugging Face 生态贴合，上手快）、OpenRLHF（Ray + vLLM + DeepSpeed）、verl（HybridFlow，训练后端可选 FSDP 或 Megatron，推理后端可选 vLLM 或 SGLang）。三者都实现了本专题的大部分方法，名字和默认值各不相同，以当前版本的文档为准。

## 训练监控与调参

RL 训练出问题往往不报错，只是曲线慢慢变怪。最常看的曲线：

| 指标 | 健康时 | 异常与含义 | 常见处理 |
| --- | --- | --- | --- |
| 平均奖励 / 正确率 | 稳步上升 | 长期不动：题目太难或太简单，大量组没有信号 | 按通过率筛数据，动态采样 |
| 回答长度 | 推理任务里缓慢变长 | 暴涨并大量触顶：长度作弊或复读；骤降：学会了偷懒的短答 | 看截断比例，超长惩罚，检查聚合方式 |
| 策略熵 | 缓慢下降 | 很快跌到接近 $0$：熵塌缩，探索停止，奖励随后停滞 | clip-higher，提高采样温度，减小学习率 |
| 与 reference 的 KL | 缓慢增长 | 突然飙升：训练不稳定，常伴随输出乱码 | 降学习率，加大 KL 系数，回滚检查点 |
| clipfrac | 较小（随任务而异） | 偏大：一步走得太远，学习率或更新轮数过大 | 降学习率，减少每批更新轮数 |
| approx_kl（新旧策略） | 很小 | 偏大：同上 | 同上，或按阈值提前停止本批更新 |
| 梯度范数 | 平稳 | 尖峰：不稳定的前兆 | 梯度裁剪，排查异常样本 |
| 训推对数概率差 | 接近 $0$ | 变大：训推不一致，比率被污染 | 训练端重算 logps，TIS 修正，检查精度设置 |
| 全对 / 全错组的比例 | 适中 | 全对比例越来越高：题目被学会了 | 换更难的数据 |
| 价值损失、解释方差（PPO） | 价值损失下降，解释方差上升 | 解释方差长期接近 $0$：critic 没学到东西 | critic 预热，调 critic 学习率 |

调参经验（常见量级，不是定律）：actor 学习率在 $10^{-6}$ 量级；组大小常取 $8$ 到 $16$；生成温度常取 $1.0$ 附近，保证探索；推理任务的 KL 系数很小或为 $0$；一批数据往往只更新一轮，这时比率在第一步恒为 $1$，裁剪只在 mini-batch 之间起作用。

## 怎么选

- **任务能自动判对错**（数学、代码）：GRPO 一族配规则奖励。上来就用 token 平均、clip-higher、动态采样这几个 DAPO 改动，基本没有坏处。
- **MoE 模型或很长的回答**：考虑 GSPO 的序列级比率。
- **奖励来自奖励模型、需要细粒度信用分配**：PPO 加 critic，接受更高的工程成本；或者 RLOO / REINFORCE++ 这类无 critic 的方法。
- **只有偏好对数据、资源有限**：不必上 RL，见「偏好优化」专题的 DPO 一族。

## 题目顺序

1. **KL 估计器 k1 / k2 / k3**：先把 KL 怎么从采样里估出来弄清楚，后面 PPO 和 GRPO 都要用。
2. **PPO 损失**：序列级的简化版，学会重要性比率和裁剪。
3. **RLHF 奖励与 GAE**：KL 进奖励、奖励只在最后一个 token，再用 GAE 反向递推出每个 token 的优势。
4. **完整版 PPO 损失**：token 级的策略损失、裁剪的价值损失，以及 clipfrac、approx_kl 这些监控量。
5. **GRPO 损失**：去掉 critic，组内标准化奖励。
6. **完整版 GRPO 损失**：加上裁剪、k3 KL 和掩码，对齐 DeepSeekMath 的公式。
7. **组内基线：GRPO / Dr. GRPO / RLOO / REINFORCE++**：比较几种基线和归一化的选择。
8. **损失聚合方式**：同一组 token 损失，四种平均方式带来不同的长度偏差。
9. **DAPO 损失**：把动态采样、超长惩罚、clip-higher、token 平均组合到一起。
10. **GSPO 序列级比率损失**：比率从 token 级换成序列级。

## 面试追问

1. **完整的 RLHF 流程是什么？**
   SFT 得到初始策略；用人类成对偏好训练奖励模型；用 PPO 在奖励模型上优化策略，每个 token 的奖励扣掉 KL，拴住参考模型。
2. **PPO、GRPO 的核心区别？KL 放的位置为什么不同？**
   PPO 用 critic 和 GAE 估计每个 token 的优势，KL 进奖励；GRPO 用同一问题一组回答的相对奖励做优势，没有 critic，KL 作为损失项单独加，不经过优势计算，实现更简单。
3. **GRPO 有哪些已知问题，各自怎么修？**
   全对全错的组没有信号（动态采样）；对称裁剪导致熵塌缩（clip-higher）；按序列平均带来长度偏差（token 平均或除以常数）；除以标准差带来难度偏差（不除，或用全 batch 标准差）；token 级比率方差大（GSPO 序列级比率）。
4. **训练中熵很快塌到接近 0，说明什么，怎么办？**
   策略过早变得确定，不再探索，奖励随后会停滞。可以放宽裁剪上界、提高采样温度、降低学习率，必要时加一点熵奖励，并检查数据是不是太简单。
5. **为什么 old_logps 要用训练引擎重算，而不直接用 vLLM 返回的？**
   两边的 kernel、精度、MoE 路由不同，对数概率有偏差。用推理引擎的值当分母，比率从第一步就不等于 1，裁剪和优势都被污染。重算让比率只反映参数更新；残留的差异可以再用截断重要性采样修正。
6. **共置和分离两种部署各有什么取舍？**
   共置让生成和训练分时共用同一批卡，利用率高，但要来回切换显存和并行布局；分离让两组卡各干各的，扩展灵活、可以异步，但两边会互相等待，异步时还要处理数据过时带来的离策略问题。
7. **为什么 RLHF 里要有 KL 项？为什么推理 RL 里常把它去掉？**
   KL 一方面防止策略为了奖励偏离语言分布、丢掉预训练和 SFT 学到的能力，另一方面把策略限制在奖励模型评分可信的区域，减少作弊。用规则奖励训练长链推理时，奖励不依赖神经网络打分，策略又需要大幅偏离初始模型，所以很多配置把 KL 设得很小或去掉。
8. **什么是奖励作弊？怎么发现、怎么缓解？**
   策略利用奖励的漏洞拿高分、真实质量却不高。看回答长度、截断比例和抽样人工检查最容易发现。缓解办法有 KL 惩罚、长度惩罚、奖励模型集成、早停，能验证的任务改用规则奖励，并把规则写严。
