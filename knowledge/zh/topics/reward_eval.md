## 解决什么问题

RL 训练和推理时搜索都离不开两件事：**给回答打分**，以及**衡量模型到底变好了没有**。这两件事做错，训练会被带偏，评测数字也会骗人。

奖励从哪来，有几种选择：

| 来源 | 打分方式 | 优点 | 风险 |
| --- | --- | --- | --- |
| 规则 / 验证器 | 答案比对、单元测试、格式检查 | 准确、便宜、难以被「说服」 | 只适用于能自动判对错的任务；规则写得松就会被钻空子 |
| 结果奖励模型（ORM） | 给整条回答一个分 | 适用于开放任务 | 是人类偏好的代理，会被作弊 |
| 过程奖励模型（PRM） | 给每一步推理一个分 | 信号密集，能定位错误步骤 | 步骤标注贵，容易被作弊 |
| LLM 评审 / 生成式奖励模型 | 让大模型写评语再给分 | 灵活，能处理复杂标准 | 贵、慢，有位置和长度偏好 |

## 可验证奖励

DeepSeek-R1-Zero 对基础模型只用两类规则奖励做 GRPO：

- **准确性奖励**：从回答里抽出最终答案（比如最后一个 `\boxed{}` 里的内容），与标准答案比对；代码题跑测试用例。
- **格式奖励**：推理过程是否放在规定的标签里。

难点全在「比对」：`1/2`、`0.5`、`\frac{1}{2}` 是同一个答案，`\boxed{}` 里还可能嵌套花括号。比对写得太严，对的答案拿不到分，奖励就有噪声；写得太松，会被钻空子。实际系统常用 sympy 一类的符号比较做等价判断。

## 过程奖励与结果奖励

- **ORM** 只看最终结果，训练数据便宜（答案对不对），但信用分配粗：一个长推理里哪一步错了，它说不出来。
- **PRM** 对每一步打分。标注来源有两种：人工逐步标注（PRM800K），或者自动标注，从某一步出发多次补全到底，看能不能得到正确答案（Math-Shepherd 的蒙特卡洛估计）。
- **整条回答的分怎么从步骤分得到**：取最小值（一步错就全错）、取乘积、或取最后一步，不同选择对长推理的偏好不同。

## 评测指标

| 指标 | 定义 | 衡量什么 |
| --- | --- | --- |
| pass@1 | 采一次答对的概率 | 日常使用时的准确率 |
| pass@k | 采 $k$ 次至少一次答对的概率 | 能力上限：模型「会不会」 |
| maj@k | 采 $k$ 次做多数投票后答对的概率 | 不靠验证器、只靠一致性能达到多少 |
| pass^k | 连续 $k$ 次都答对的概率 | 可靠性，Agent 评测常用 |

pass@k 不能用「采 $k$ 次看有没有对」直接估，方差很大；标准做法是采 $n \ge k$ 次，数出 $c$ 次答对，用组合数公式无偏估计（「pass@k 无偏估计」一题）。

一个常被讨论的现象：RL 通常能明显提高 pass@1，但在 $k$ 很大时，RL 后模型的 pass@k 未必超过基础模型。一种解释是 RL 主要把基础模型已经会的解法变得更容易采到，而没有带来新的解法。

## 推理时搜索

前面的方法都在训练时改权重。另一条线是推理时多花算力：不改模型，生成多个候选，再由验证器、奖励模型或投票挑出结果。

| 方法 | 做法 | 需要什么 |
| --- | --- | --- |
| 多数投票（self-consistency） | 采 $N$ 个回答，选出现最多的最终答案 | 只要能抽出答案 |
| Best-of-N | 采 $N$ 个回答，用奖励模型选最高分 | ORM 或验证器 |
| 加权投票 | 按答案分组，把同组的奖励加起来再选 | ORM 或 PRM |
| 带 PRM 的 Beam Search | 每走一步用 PRM 打分，保留得分高的若干条路径 | PRM |
| MCTS | 树上反复「选择 → 扩展 → 评估 → 回传」，把计算集中到有希望的分支 | 能评估中间步骤的价值模型或 PRM |

MCTS 选子节点时用 **UCT**（UCB1 用在树上）：

$$
\operatorname{UCT}(i) = Q(i) + c \sqrt{\frac{\ln N}{n_i}}
$$

$Q(i)$ 是子节点平均价值，$n_i$ 是它的访问次数，$N$ 是父节点访问次数，$c$ 是探索常数。AlphaGo / AlphaZero 系列改用 **PUCT**，把策略网络的先验 $P(a)$ 加进来：

$$
\operatorname{PUCT}(a) = Q(a) + c\, P(a)\, \frac{\sqrt{N}}{1 + n_a}
$$

用在 LLM 上，$P(a)$ 可以取语言模型对下一步的概率，$Q$ 由 PRM 或价值模型评估。难点在于：动作空间是整个词表，通常要以「一步推理」为节点；价值模型难训练；每次评估都要调用大模型。DeepSeek-R1 的报告把 MCTS 列在没有成功的尝试里。o1 一类模型具体怎么推理没有公开，不要断言它用了 MCTS。

## 演进

1. **Codex（2021）**：提出 pass@k 的无偏估计，代码生成开始用单元测试当验证器。
2. **Self-consistency（2022）**：多次采样做多数投票，不需要任何额外模型就能明显提升推理准确率。
3. **过程监督（2023）**：*Let's Verify Step by Step* 发布 PRM800K，显示在挑选答案上 PRM 优于 ORM；Math-Shepherd 用蒙特卡洛补全自动生成步骤标签。
4. **可验证奖励的 RL（2025）**：DeepSeek-R1 用规则奖励训练推理，并报告 PRM 和 MCTS 在大规模 RL 中没有奏效。
5. **推理时扩展**：生成更长的思维链、采更多样本、搜索，成为和训练时扩展并列的另一条提升路线。

## 怎么选

- **有标准答案或测试用例**：规则奖励优先，并花时间把答案比对写对。
- **开放任务**：奖励模型或 LLM 评审，配合 KL 和长度控制防作弊。
- **推理时预算有限**：多数投票最便宜；有可靠的奖励模型就用加权投票或 Best-of-N。
- **评测**：同时报 pass@1 和 pass@k，固定采样温度和样本数；Agent 任务关注 pass^k。

## 题目顺序

1. **可验证数学奖励**：抽出最后一个 `\boxed{}`、规范化、判断数值等价，再加格式检查。
2. **过程奖励模型损失**：只在步骤结束位置算二分类损失，再把步骤分聚合成整条回答的分。
3. **pass@k 无偏估计**：组合数公式和数值稳定的乘积形式。
4. **答案投票：多数 / Best-of-N / 加权**：多数投票、Best-of-N、加权投票，以及平局怎么处理。
5. **推理蒙特卡洛树搜索**：用 UCB 平衡探索与利用，把推理时的算力集中到有希望的分支。

## 面试追问

1. **可验证奖励的好处和局限？**
   准确、便宜、不容易被「说服」；但只适用于有标准答案或能自动检验的任务，规则写得松会被钻空子，比如只学会输出格式正确的空答案。
2. **ORM 和 PRM 各有什么优缺点？**
   ORM 训练数据便宜，但信用分配粗；PRM 能定位错误步骤，适合引导搜索，但步骤标注贵，在大规模 RL 里还容易被作弊。
3. **为什么 pass@k 要用 n 个样本的无偏估计，而不是直接采 k 个？**
   直接采 $k$ 个只给出一个 0/1 的观测，方差很大；采 $n \ge k$ 个再用组合数公式，等于对所有 $k$ 子集取平均，估计稳定得多，而且无偏。
4. **多数投票和 Best-of-N 什么时候谁更好？**
   奖励模型可靠时 Best-of-N 更好；奖励模型有偏、$N$ 很大时，Best-of-N 容易挑中奖励模型的漏洞，多数投票反而更稳。加权投票把两者结合起来。
5. **MCTS 和 Best-of-N 有什么不同？**
   Best-of-N 对每个回答独立采样、最后才评分，算力平均分配；MCTS 按中间步骤的价值动态分配算力，但需要能评估中间步骤的价值模型，实现更复杂。
