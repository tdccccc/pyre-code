## 解决什么问题

序列里每个位置都要按相关程度，去汇总其他位置的信息。**注意力**（attention）用一个公式完成这件事：

$$
O = \operatorname{softmax}\!\left(\frac{Q K^{\top}}{\sqrt{d_k}} + M\right) V
$$

$Q$ 是查询，$K$ 是键，$V$ 是值，$M$ 是掩码：允许看的位置加 $0$，不许看的位置加 $-\infty$。本专题的所有变体都是在这个公式上改三处地方：

1. **K、V 怎么存、怎么共享**：推理时每个 token 的 K、V 都要缓存，缓存太大就是瓶颈。MQA、GQA、MLA 解决的是这个问题。
2. **掩码 $M$ 是什么**：因果掩码、滑动窗口、打包序列的块对角掩码，都只是 $M$ 的不同取法。
3. **计算本身**：$Q K^{\top}$ 是 $S \times S$ 的矩阵，代价 $O(S^2)$。线性注意力换掉 softmax 绕开它；差分注意力则是针对 softmax 的「噪声」做修正。

前两题（Softmax、Softmax 注意力）是地基，其余各题都建立在它们之上。

## 对比

| 方法 | 改动 | 代价 / 收益 | 典型使用 |
| --- | --- | --- | --- |
| 多头注意力（MHA） | 每个查询头有自己的 K、V | 缓存最大，质量基线 | 原始 Transformer、BERT、GPT-2 |
| 交叉注意力 | Q 与 K、V 来自不同序列 | 代价 $O(S_q S_{kv})$ | 翻译解码器、扩散模型的文本条件 |
| MQA | 所有查询头共享 $1$ 组 K、V | 缓存缩小为 $1/H$，质量略降 | PaLM |
| GQA | 每组查询头共享 $1$ 组 K、V | 缓存缩小为 $H_{kv}/H$，质量接近 MHA | LLaMA 3、Mistral、Qwen2 |
| MLA | 只缓存低秩潜向量 | 缓存最小，需处理 RoPE | DeepSeek-V2 / V3 |
| 因果注意力 | $M$ 取下三角 | 只看过去，可做自回归 | GPT 类解码器 |
| 滑动窗口 | $M$ 取对角带 | 计算和缓存 $O(S \cdot w)$ | Longformer、Mistral |
| 变长打包 | $M$ 取块对角 | 不浪费 padding | 训练时打包文档、批量预填充 |
| 差分注意力 | 两张 softmax 图相减 | 多算一张注意力图 | Differential Transformer |
| 线性注意力 | 用特征映射替换 softmax | 代价 $O(S D^2)$，表达力受限 | 线性 Transformer 及其后续工作 |

## KV 头共享：MHA、MQA、GQA、MLA

自回归生成时，每个历史 token 的 K、V 都留在显存里（KV cache，详见「推理服务」专题），每生成一个 token 又要把它们全部读一遍。所以这一条线衡量的指标是：**每个 token、每层要缓存多少个数**。设 $H$ 个查询头，每头 $d_h$ 维：

| 方法 | 每 token 每层缓存的元素数 | $H=32,\ d_h=128$ | 32 层、bf16 |
| --- | --- | --- | --- |
| MHA | $2\, H\, d_h$ | $8192$ | $512$ KiB |
| GQA（$H_{kv}=8$） | $2\, H_{kv}\, d_h$ | $2048$ | $128$ KiB |
| MQA | $2\, d_h$ | $256$ | $16$ KiB |
| MLA | $d_c$ | $512$ | $32$ KiB |

因子 $2$ 是 K 和 V 各一份。MLA 一行的 $d_c = 512$ 沿用 DeepSeek-V2 的取值，只是为了把数量级摆出来；真实模型的头数和 $d_h$ 不同，而且还要再加上一条 RoPE 分支（见「多头潜在注意力（MLA）」一题的延伸）。

按 MHA 算，$4096$ 个 token 的缓存就是 $512\ \text{KiB} \times 4096 = 2$ GiB，每个请求一份。

这四种方案走了两条路：

- **减少 KV 头的个数**（MQA、GQA）：多个查询头共用同一组 K、V。MQA 是极端情形（$H_{kv} = 1$），GQA 在 MHA 和 MQA 之间取一个折中，$H_{kv} = H$ 时就是 MHA。它们只省缓存，注意力分数的计算量不变。
- **压缩 K、V 的表示**（MLA）：不删头，每个查询头仍然有自己独立的 K、V，只是缓存里存的是更小的潜向量 $c$，用的时候再通过上投影还原。靠的是 K、V 的低秩结构。

另外两点：

- **为什么省缓存能提速**：解码一步只处理一个新 token，计算量很小，时间主要花在把整份 KV cache 从显存搬进来。缓存小了，每步读的数据就少；省下的显存还能换成更大的 batch 或更长的上下文。
- **GQA 的复用**：一组 K、V 读进来，被组内 $g = H / H_{kv}$ 个查询头同时使用，计算量与访存量之比提高了 $g$ 倍，更能喂饱计算单元（见「性能估算」专题的推理 roofline）。

## 掩码与范围

因果、滑动窗口、打包，都是同一个机制：先算出完整的分数，在 softmax 之前把不允许的位置填上 $-\infty$（`masked_fill`）。区别只在于**允许 $(i, j)$ 的条件**：

| 掩码 | 允许 $(i, j)$ 的条件 | 第 $i$ 行可见数 |
| --- | --- | --- |
| 全注意力 | 所有 $j$ | $S$ |
| 因果 | $j \le i$ | $i + 1$ |
| 滑动窗口（对称） | $\lvert i - j \rvert \le w$ | 至多 $2w + 1$ |
| 因果滑动窗口 | $i - w \le j \le i$ | 至多 $w + 1$ |
| 变长打包 | $\operatorname{seg}(i) = \operatorname{seg}(j)$ | 所在序列的长度 |

几点要记住：

- **掩码可以叠加**，逻辑上取「与」。Mistral 用的是因果加窗口，训练时打包文档再套一层块对角，也是如此。本站的「滑动窗口注意力」一题是对称窗口，只用于演示规则。
- **整行都被屏蔽会出 NaN**：全是 $-\infty$ 的一行，softmax 是 $0 / 0$。遇到 padding 位置作查询时要小心；「变长序列打包注意力」一题里，长度为 $0$ 的序列不含任何 token，所以不会遇到这种情形。
- **范围的大小决定了计算量**：因果注意力有效的分数约一半；滑动窗口每行至多 $2w + 1$ 个，总量 $O(S \cdot w)$；打包后每条序列只需和自己算，总量是 $\sum_j \ell_j^2$，而不是 $T^2$。
- **打包省多少**：长度 $[100, 2000, 300]$ 补齐到 $2000$，三条序列的分数共 $3 \times 2000^2 = 1.2 \times 10^7$ 个；只算块内是 $100^2 + 2000^2 + 300^2 \approx 4.1 \times 10^6$ 个，约 $3$ 倍的差距。
- **题目里的实现都会构造完整的 $S \times S$ 掩码**，是为了把规则写清楚。真正的 kernel 不会生成这个矩阵，而是按块判断，整块被屏蔽就直接跳过（详见「IO 感知 kernel」专题）。

## 复杂度与另辟蹊径

设序列长 $S$，Q、K 的特征维为 $D_k$，V 的特征维为 $D_v$：

| 方法 | 训练 / 预填充的计算 | 解码每步的计算 | 解码需要保存的状态 |
| --- | --- | --- | --- |
| 标准（全）注意力 | $O(S^2 D)$ | $O(S D)$ | KV cache，随 $S$ 线性增长 |
| 滑动窗口 | $O(S\, w\, D)$ | $O(w D)$ | 最近 $w$ 个 token 的 KV |
| 线性注意力 | $O(S\, D_k D_v)$ | $O(D_k D_v)$ | 一个 $D_k \times D_v$ 的矩阵，与 $S$ 无关 |

线性注意力能这样做，是因为把 $\operatorname{softmax}$ 的指数核换成了可分解的 $\phi(q)^{\top}\phi(k)$，于是

$$
\bigl(\phi(Q)\, \phi(K)^{\top}\bigr)\, V = \phi(Q)\, \bigl(\phi(K)^{\top} V\bigr)
$$

右边先算出一个 $D_k \times D_v$ 的小矩阵，再乘 $\phi(Q)$，不会出现 $S \times S$ 的中间量。代价是表达力：

- $\phi(Q)\,\phi(K)^{\top}$ 的秩不超过 $D_k$，而 softmax 注意力的权重矩阵没有这个限制。
- 指数核可以把几乎全部权重压到某一个 token 上（尖锐的检索），而线性核的权重较平，同样的位置难以挑得那么准。
- 解码时的状态大小固定，意味着历史信息被压进一个定长的矩阵里，长上下文里的精确回忆因此更难。

所以精确的 softmax 注意力至今仍是主流，它的 $O(S^2)$ 靠 FlashAttention 这类 IO 感知的实现来对付，见「IO 感知 kernel」专题。线性注意力的思路则被带到了循环式的结构里，和 Mamba 这类状态空间模型很接近，见「模型架构」专题。

**差分注意力**要解决的不是复杂度，而是质量。softmax 的权重永远为正，无关的 token 也总会分到一点；序列越长，这些小权重加起来越多，把真正相关的信息淹没。差分注意力算两张 softmax 图再相减，两张图共有的那部分基线被抵消：

$$
\operatorname{DiffAttn} = \bigl(A_1 - \lambda A_2\bigr)\, V
$$

代价是多算一张注意力图，权重可以是负数。

## 演进

1. **加性注意力（2014）**：Bahdanau 等人在 seq2seq 翻译里引入注意力，解码器每一步回看编码器的所有位置，也就是最早的交叉注意力。
2. **缩放点积注意力与多头（2017）**：Transformer 用点积代替加性打分，因为它只是矩阵乘法，在硬件上很快；加上 $1/\sqrt{d_k}$ 保证数值稳定，再切成多个头。
3. **MQA（2019）**：Shazeer 观察到增量解码受限于读 KV，让所有头共享一组 K、V。
4. **局部注意力与线性注意力（2020）**：Longformer 用滑动窗口把代价降到线性；Katharopoulos 等人用特征映射 $\phi$ 把注意力改写成线性，并指出因果形式等价于一个 RNN。
5. **GQA 与 Mistral（2023）**：GQA 把 MQA 推广成可调的分组，可以从已有的 MHA 检查点出发，用少量额外训练转换过来。Mistral 7B 把 GQA 和滑动窗口结合起来。
6. **MLA（2024）**：DeepSeek-V2 用低秩潜向量压缩 KV 缓存，配合解耦的 RoPE 分支。
7. **差分注意力（2024）**：Differential Transformer 针对 softmax 的注意力噪声，在 ICLR 2025 发表。

同一时期，工程上的重大进展不在公式里：FlashAttention 让精确注意力不再把 $S \times S$ 的分数写进显存，PagedAttention 等把 KV cache 管理得更高效，它们属于另外两个专题。

## 怎么选

- **自回归语言模型**：因果注意力是标配。现在的大模型默认用 GQA；追求极致的 KV 缓存（长上下文、高并发）可以考虑 MLA。
- **KV 缓存压力小**（短上下文、小模型）：MHA 最简单，也最稳。
- **MQA**：缓存最小，但质量有损，通常只在极端追求推理速度时才选，大多已被 GQA 取代。
- **超长序列、想进一步压住计算和缓存**：滑动窗口，通常和少量全局注意力的层混用，让信息还能跨越很远。
- **训练时文档长短不一**：打包加块对角掩码，不要补齐。
- **两个序列要交互**（翻译、文生图、图文对话）：交叉注意力；或者像不少多模态模型那样，直接把另一个序列拼进同一条序列里做自注意力。
- **线性注意力、差分注意力**：更多是研究方向。线性注意力在效率和表达力之间取舍，差分注意力主要针对长上下文里的噪声。

## 题目顺序

1. **实现 Softmax**：所有注意力的归一化步骤，先把数值稳定写对。
2. **Softmax 注意力**：三步（打分、softmax、加权求和）和缩放因子，序列长度可以不等。
3. **因果自注意力**：加一个掩码，学会「$-\infty$ 屏蔽」。
4. **多头注意力**：把头当作批维度，掌握 `view` / `transpose` 的形状变换。
5. **多头交叉注意力**：Q 与 K、V 来自不同序列，$S_q \ne S_{kv}$ 时形状不能写混。
6. **分组查询注意力（GQA）**：KV 头少于查询头，学会用 `repeat_interleave` 扩展。
7. **多头潜在注意力（MLA）**：KV 头共享的另一条路，先压缩再还原。
8. **滑动窗口注意力**：掩码从下三角换成对角带。
9. **变长序列打包注意力**：掩码变成块对角，要由 `cu_seqlens` 推出每个 token 所属的序列。
10. **差分注意力**：在前面的基础上，两张注意力图相减。
11. **线性自注意力**：换掉 softmax，用结合律改变计算顺序。

## 面试追问

1. **为什么要除以 $\sqrt{d_k}$？为什么不是 $d_k$？**
   设 $q$、$k$ 的各分量独立、均值 $0$、方差 $1$，则 $q \cdot k$ 的方差是 $d_k$，标准差是 $\sqrt{d_k}$。不缩放时，$d_k$ 越大分数越大，softmax 趋于 one-hot；而 softmax 的梯度 $\partial p_i / \partial x_j = p_i(\delta_{ij} - p_j)$ 在 $p$ 接近 one-hot 时趋近 $0$，训练几乎停滞。除以 $\sqrt{d_k}$ 刚好把方差拉回 $1$；若除以 $d_k$，分数会被压得过小，权重接近均匀，注意力失去选择性。
2. **softmax 怎么做到数值稳定？还有哪些情况会出问题？**
   减去每行的最大值，让指数的最大项是 $e^0 = 1$，既不上溢，分母也不会为 $0$。仍会出问题的情形：整行都是 $-\infty$（比如全被 padding 掉的行）会得到 $0/0 = \text{NaN}$；半精度下求和要用 fp32 累加。FlashAttention 一类 kernel 在分块计算时，用的是「在线 softmax」，边扫描边维护当前的最大值和归一化和，不必先把整行分数存下来。
3. **注意力的时间、空间复杂度是多少？解码时每步呢？**
   训练 / 预填充时，计算 $O(S^2 D)$，朴素实现要存 $O(S^2)$ 的分数矩阵。解码时新来一个 token，只需和 $S$ 个缓存的 K 算分数，每步计算 $O(S D)$，但要读整份 KV cache，实际受限于显存带宽。
4. **MHA、MQA、GQA、MLA 的取舍是什么？**
   四者的计算框架一样，区别是每个 token 每层缓存多少：MHA 为 $2 H d_h$，MQA 为 $2 d_h$，GQA 为 $2 H_{kv} d_h$，MLA 为 $d_c$（外加一小段 RoPE 分支）。MQA 缓存最小但质量有损，GQA 取折中，MLA 保留每个头独立的 K、V，靠低秩压缩换来很小的缓存，代价是实现复杂，且要解决 RoPE 与矩阵吸收的冲突。
5. **因果掩码、滑动窗口、变长打包是怎么统一起来的？**
   都是在 softmax 之前往分数上叠加一个掩码 $M$，允许的位置是 $0$，不允许的位置是 $-\infty$。三者只是允许条件不同：$j \le i$、$\lvert i - j \rvert \le w$、$\operatorname{seg}(i) = \operatorname{seg}(j)$。多个条件取「与」就能组合。
6. **线性注意力为什么没有取代 softmax 注意力？**
   线性核的注意力矩阵秩不超过 $D_k$，不能像指数核那样把权重集中到一个 token 上；因果形式下状态是定长的，精确回忆很久以前的内容更难。在需要精确检索的任务上，线性注意力通常落后于 softmax 注意力。更常见的做法是在局部或少数几层里保留标准注意力，其余部分用线性或循环结构。
