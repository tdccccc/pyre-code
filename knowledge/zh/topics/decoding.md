## 解决什么问题

语言模型每一步只输出词表上的一个分布，一段文本要靠**解码**（decoding）一步步挑 token 拼出来。挑法决定了输出的质量、多样性和速度，这三件事互相牵制：

- **质量与多样性**：永远挑概率最大的（贪心）稳定但单调，容易陷入重复；完全按原分布采样多样，但词表有几万个 token，长尾加起来的概率不可忽视，偶尔会采到离谱的词。
- **速度**：自回归必须一个 token 一个 token 地生成，每一步都要读一遍全部权重，慢在访存，而不是算力。

本专题的四道题分成三条线：

- **采样**（`topk_sampling`）：怎样砍掉长尾再采样。
- **logits 处理**（`sampling_penalties`）：采样前对 logits 做的各种改写，包括抑制重复。
- **搜索**（`beam_search`）和**加速**（`speculative_decoding`）：前者追求整体概率最高的序列，后者在不改变输出分布的前提下让生成更快。

采样类方法可以写成同一个流程：先对 logits $z$ 做处理（惩罚、温度），再算概率，然后只保留一个候选集合 $S$，重新归一化后采样：

$$
p_i = \operatorname{softmax}\!\left(\frac{z}{T}\right)_i, \qquad
p'_i = \frac{p_i \cdot \mathbb{1}[i \in S]}{\sum_{j \in S} p_j}
$$

其中 $T$ 是温度。各种截断方法的区别只有一个：**候选集合 $S$ 怎么选**。

| 方法 | 候选集合 $S$ |
| --- | --- |
| 贪心 | 概率最大的 $1$ 个 token |
| top-k | 概率最大的 $k$ 个 |
| top-p | 按概率从大到小，累积概率刚好达到 $p$ 的最小前缀 |
| min-p | $p_i \ge p_{\min} \cdot \max_j p_j$ 的 token |

## 对比

| 方法 | 做什么 | 随机性 | 典型使用 |
| --- | --- | --- | --- |
| 贪心 | 每步取 argmax | 无 | 代码补全、事实问答、需要可复现时 |
| 束搜索 | 保留得分最高的 $B$ 条序列 | 无 | 机器翻译、语音识别 |
| 温度 | 调整整个分布的尖锐程度 | 有 | 几乎所有采样的第一步 |
| top-k | 固定保留 $k$ 个 | 有 | 通用采样 |
| top-p | 按累积概率自适应保留 | 有 | 对话、创作，API 常见参数 |
| min-p | 按相对最大概率的比例保留 | 有 | vLLM、Hugging Face 等引擎提供 |

几点说明：

- **温度不改变排序**：$T$ 对所有 logits 是同一个单调变换，所以 top-k 选出的集合与温度无关，先后顺序无所谓。但 top-p 和 min-p 看的是概率，温度会改变候选集合，所以顺序必须固定（题目约定先温度，再 top-k，再 top-p）。
- **top-k 的缺陷**：$k$ 固定，分布很集中时（只有一两个合理选项）会放进不合理的词，分布很平坦时（合理选项很多）又砍得太狠。top-p 和 min-p 的保留个数随分布形状自适应，就是为了解决这个问题。
- **top-p 与 min-p**：top-p 看累积概率，min-p 看单个 token 相对最大概率的比例。模型很有把握时，min-p 的门槛高，砍得多；分布平坦时门槛低，保留得多。

## 演进

1. **贪心与束搜索**：早期序列生成（翻译、语音识别）的默认选择，目标是找到概率最高的序列。
2. **开放式生成不适合最大化概率**：Holtzman 等人（2019，Neural Text Degeneration）指出，用束搜索这类追求最大似然的解码生成长文本，常常平淡、重复；人写的文本并不总是每步都选概率最高的词。于是开放式生成转向**随机采样**。
3. **截断长尾**：top-k（Fan 等人，2018）限定候选个数；top-p / 核采样（Holtzman 等人）让候选个数随分布变化；min-p 是更晚出现的做法，用相对阈值。
4. **抑制重复**：CTRL（2019）提出重复惩罚；OpenAI 的 API 提供频率和存在惩罚。它们作用在 logits 上，和上面的截断方法可以叠加使用。
5. **推测解码**（2022–2023，Leviathan 等人与 Chen 等人分别独立提出）：不改变输出分布，只想办法让大模型每次前向多产出几个 token。后续的 Medusa、EAGLE 等工作主要在改进「草稿」怎么来。

## 三种惩罚的区别

三种惩罚都作用在已经出现过的 token 上，区别是形式和对次数的敏感程度：

| 惩罚 | 形式 | 和次数的关系 |
| --- | --- | --- |
| 重复惩罚 | 乘性：正 logit 除以 $\theta$，负 logit 乘以 $\theta$ | 无关，每个不同 token 一次 |
| 频率惩罚 | 加性：减 $\alpha_{\text{freq}} \cdot c$ | 线性，出现越多减得越多 |
| 存在惩罚 | 加性：减 $\alpha_{\text{pres}}$ | 无关，出现过就减一次 |

几个要点：

- **加性惩罚的含义**：从 logit 里减 $a$，相当于把未归一化概率乘以 $e^{-a}$。所以频率惩罚是按次数指数级压低，存在惩罚是一次性压低。
- **乘性惩罚为什么分正负**：目的是让 logit 变小。正数除以 $\theta > 1$ 变小，负数除以 $\theta$ 反而变大，所以负数要乘。
- **作用范围**：不同引擎对「已出现」的范围规定不同，例如 vLLM 的重复惩罚同时看提示词和已生成部分，而频率、存在惩罚只看已生成部分。用别人的接口前先看文档。
- **副作用**：代码里的变量名、数学推导里的符号、引用原文，合理的重复很多。惩罚过大会让模型回避这些必要的重复，甚至选出不通顺的词。通常取接近中性的小值。
- **顺序**：惩罚在温度之前作用于原始 logits，常见引擎（Hugging Face、vLLM）都是这样的顺序，本站题目也这样规定。

## 解码为什么慢，推测解码为什么可行

训练和预填充（prefill）时，一次前向要处理很多 token，算力是瓶颈。解码时每个序列每步只处理 $1$ 个 token，却要把全部权重（外加不断变长的 KV cache）从显存读一遍。

用 roofline 的思路估算（见「性能估算」专题和 Decode Roofline 一题）：每个参数每处理一个 token 做 $2$ 次浮点运算，用 bf16 存储则每个参数读 $2$ 字节，算术强度约为 $B$ FLOP/字节（$B$ 为同时处理的 token 数）。A100 这类 GPU 要上百 FLOP/字节才能把算力喂饱，所以 $B$ 较小时是**访存受限**，算力大量闲置。

推测解码利用的正是这点闲置算力：目标模型验证 $K$ 个位置，和处理 $1$ 个位置读的权重一样多，耗时差不多，但可能一次产出多个 token。注意它**不省总计算量，反而多算了**，换来的是更低的延迟；一旦 batch 大到变成计算受限，这笔交易就不划算了。

KV cache 的原理见「推理服务」专题。

## 推测解码的草稿从哪来

| 做法 | 草稿来源 | 额外开销 |
| --- | --- | --- |
| 小模型 | 同系列的小模型，词表须一致 | 要部署和维护第二个模型 |
| Medusa | 目标模型顶上加几个预测头，一次预测后面几个位置 | 要训练额外的头 |
| EAGLE | 轻量的草稿网络，利用目标模型的隐藏状态来预测 | 要训练草稿网络 |
| MTP | 用多 token 预测训练出的模块当草稿 | 模型训练时就要带上这个模块 |
| n-gram / prompt lookup | 在提示词或已生成内容里找匹配的片段直接抄 | 几乎没有，不需要任何模型 |

这些做法都套用同一套「草稿 + 验证」框架，区别只在草稿的质量（接受率）和获得草稿的成本。输出越容易从上下文里抄（总结、改写、检索增强、代码修改），n-gram 一类的做法越有效。

## 怎么选

- **需要可复现、答案唯一**（数学、事实问答、结构化输出）：贪心，或者很低的温度。
- **对话、创作等开放式生成**：温度加 top-p（或 min-p），按需要再加小幅度的重复相关惩罚。
- **翻译、语音识别这类有「标准答案」的序列任务**：束搜索，通常配合长度归一化。
- **延迟敏感、batch 较小**：在上面任一策略之上加推测解码，输出分布不变。
- **吞吐优先、batch 很大**：推测解码收益变小甚至为负，优先用连续批处理（见「推理服务」专题）。

## 题目顺序

1. **Top-k / Top-p 采样**：最基础的一步，从 logits 到 token，认识温度、截断和重新归一化。
2. **采样惩罚与 Min-p**：在同一条流水线上加更多 logits 处理器，重点是步骤顺序和边界条件。
3. **束搜索解码**：换成搜索的思路，维护多条候选序列，考验对累积对数概率和结束条件的处理。
4. **推测解码**：最难的一题，需要理解拒绝采样为什么能保证分布不变，放在最后。

## 面试追问

1. **为什么开放式生成不用束搜索？**
   束搜索追求整体概率最高，但人写的文本并不是每步都选概率最高的词；最大化概率的结果常常平淡、重复，而且各条束共享大部分前缀，几乎没有多样性。开放式生成用采样，翻译这类有标准答案的任务才适合束搜索。
2. **温度、top-k、top-p 的作用各是什么？先后顺序有影响吗？**
   温度调整分布整体的尖锐程度，top-k 和 top-p 截断长尾。top-k 只看排序，与温度先后无关，top-p 看累积概率，必须在温度之后算；top-p 是在 top-k 过滤并重新归一化后的分布上算的。
3. **重复惩罚、频率惩罚、存在惩罚怎么选？**
   重复惩罚和存在惩罚都与次数无关，只区分出现过与否；频率惩罚随次数累加，能压制反复出现的词。惩罚过强会伤害合理的重复（变量名、引用），一般取接近中性的小值。
4. **解码阶段为什么慢？有哪些办法？**
   每步只处理一个 token，却要读完所有权重和 KV cache，算术强度低，是访存受限。办法有：增大 batch 来摊薄权重读取（连续批处理）、减少要读的数据（量化、GQA/MLA 压缩 KV）、一次验证多个 token（推测解码）。
5. **推测解码为什么是无损的？什么时候没用？**
   接受时按 $\min(1, p/q)$、拒绝时从残差分布重采样，两部分加起来恰好等于目标分布 $p$。草稿和目标差得远（接受率低）、草稿本身太慢，或 batch 已大到计算受限时，加速都会变小甚至为负。
