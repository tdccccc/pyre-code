## 背景

大模型逐个生成 token 时，每一步都要把全部权重从显存读一遍，GPU 的算力大多闲着。一次前向处理 $1$ 个 token 和处理 $K$ 个 token，耗时差不多。

**推测解码**利用这一点：

1. 用一个小而快的**草稿模型**先连续猜 $K$ 个 token
2. 大的**目标模型**一次前向，同时算出这 $K$ 个位置上它自己的概率
3. 按一个接受规则逐个验证：接受的直接保留，遇到第一个被拒绝的就用修正分布重新采一个，然后结束本轮

关键在于：这个接受规则能保证最终输出的分布**和直接用目标模型采样完全相同**，加速是无损的。

## 核心公式

在某个位置，记目标模型的分布为 $p$，草稿模型为 $q$，草稿提议的 token 为 $x \sim q$。

**接受概率**：

$$
P(\text{接受 } x) = \min\!\left(1,\ \frac{p(x)}{q(x)}\right)
$$

草稿给出的概率不比目标高（$q(x) \le p(x)$）时必定接受；草稿「过度自信」时按比例拒绝。

**拒绝后重新采样**，从残差分布中采：

$$
r(x) = \frac{\max\bigl(0,\ p(x) - q(x)\bigr)}{\sum_{x'} \max\bigl(0,\ p(x') - q(x')\bigr)}
$$

**为什么输出分布恰好是 $p$**：记总接受概率 $\beta = \sum_x q(x) \min\!\bigl(1, \tfrac{p(x)}{q(x)}\bigr) = \sum_x \min\bigl(q(x), p(x)\bigr)$。注意 $\sum_x \max(0, p - q) = 1 - \sum_x \min(p, q) = 1 - \beta$。于是最终输出 $x$ 的概率为

$$
\begin{aligned}
P(\text{输出 } x) &= \underbrace{\min\bigl(q(x), p(x)\bigr)}_{\text{提议并被接受}} + \underbrace{(1 - \beta)\cdot \frac{\max\bigl(0, p(x) - q(x)\bigr)}{1 - \beta}}_{\text{被拒绝后重采样}} \\
&= \min(q, p) + \max(0, p - q) = p(x)
\end{aligned}
$$

## 形状

| 量 | 形状 |
| --- | --- |
| `target_probs`、`draft_probs` | `(K, V)`，第 $i$ 行是第 $i$ 个位置的分布 |
| `draft_tokens` | `(K,)` |
| 返回 | Python 列表，长度 $1$ 到 $K$ |

## 用到的 PyTorch 操作

- `torch.rand(1).item()`：$[0, 1)$ 上的均匀随机数，小于接受概率就接受。
- `torch.clamp(t, min=0)`：实现 $\max(0, \cdot)$。
- `torch.multinomial(probs, 1)`：按分布采样。

## 常见坑

- **比值写反**：是 $p_{\text{target}} / p_{\text{draft}}$。
- **拒绝后从 $p$ 重新采样**：必须从残差分布 $r$ 采样，否则输出分布就偏了。
- **拒绝后还继续验证后面的 token**：后面的草稿 token 是以被拒绝的 token 为前提生成的，已经无效，要立刻返回。
- **残差没有归一化**：`multinomial` 虽然能接受未归一化的权重，但要处理残差全为 $0$ 的情况（此时 $p = q$，不会发生拒绝，但写代码时要防止除以零）。
- 真实实现中全部接受时还会从目标模型多采一个「奖励 token」；本题不要求，全部接受时返回 $K$ 个。

## 延伸

- **加速比**：设草稿每步被目标模型接受的概率为 $\alpha$（前面的 $\beta$ 的期望，$\alpha = \mathbb{E}\sum_x \min(p(x), q(x))$），假设各位置接受相互独立，每轮提议 $K$ 个。算上全部接受时附赠的那一个 token，每轮目标模型一次前向平均产出

$$
\frac{1 - \alpha^{K+1}}{1 - \alpha}
$$

  个 token。设一次草稿前向的耗时是目标模型一次前向的 $c$ 倍，则相对普通解码的加速比为

$$
\frac{1 - \alpha^{K+1}}{(1 - \alpha)(K c + 1)}
$$

  这是 Leviathan 等人论文里的结果。$\alpha$ 越高越好；$K$ 变大时分子趋于上限 $1/(1-\alpha)$，而分母继续线性增长，所以存在最优的 $K$。草稿太慢（$c$ 大）也会吃掉收益。

- **奖励 token**：目标模型一次前向在 $K+1$ 个位置给出分布（前缀的最后一个位置加上 $K$ 个草稿位置）。$K$ 个草稿全部被接受时，第 $K+1$ 个位置的分布不用额外代价，可以直接采一个 token。被拒绝时，重新采的那个 token 同样是免费的，所以每轮至少产出 $1$ 个 token，不会比普通解码更差（不算草稿的开销）。
- **贪心情形**：温度为 $0$ 时，接受规则退化为「草稿 token 等于目标模型的 argmax 就接受」，第一个不一致的位置改用目标模型的 argmax，输出和纯贪心解码一致。
- **无损的前提**：保证的是和「目标模型经过同样的 logits 处理之后的分布」一致，所以 $p$ 和 $q$ 都应该是做完温度、top-k、top-p 等处理后的分布，两者的处理要统一。
- **不省算力，省的是延迟**：目标模型每轮验证 $K$ 个位置，被拒绝的位置白算了。它换到的是更少的前向轮数。batch 大到计算受限时，多算的这部分就会拖慢吞吐。
- **工程细节**：
  - 被拒绝的位置对应的 KV cache 要回滚（见 KV Cache Attention 一题和「推理服务」专题）。
  - 草稿模型通常需要和目标模型使用同一个词表。
  - 同一个 batch 里各个序列每轮接受的个数不同，需要处理长度不齐的问题。

## 面试追问

1. **为什么推测解码的输出分布和直接用目标模型采样完全一致？**
   一个位置上，被提议并被接受的概率是 $\min(q, p)$，被拒绝后从残差分布 $\max(0, p - q)$（归一化）重采，这一部分贡献 $\max(0, p - q)$。两者相加正好是 $p$。
2. **拒绝后为什么不能直接从 $p$ 重新采样？**
   草稿已经「抢先」采走了 $\min(q, p)$ 那部分概率质量，直接从 $p$ 重采会让这部分被重复计入，分布就偏了。残差分布只补上被草稿少给的那部分。
3. **接受率、$K$ 和加速比的关系是什么？**
   每轮平均产出 $(1 - \alpha^{K+1}) / (1 - \alpha)$ 个 token。接受率 $\alpha$ 越高，$K$ 可以取得越大；$K$ 越大，草稿的开销越高，所以存在最优的 $K$。
4. **推测解码什么时候没有加速，甚至更慢？**
   接受率低（草稿和目标差得远）、草稿模型本身不够快，或者 batch 很大、解码已经变成计算受限，此时多算的验证位置是纯额外开销。
5. **为什么验证 $K$ 个 token 的耗时和生成 $1$ 个差不多？**
   解码是访存受限的，瓶颈在读取权重，而不是计算。一次前向读一遍权重，处理 $1$ 个或 $K$ 个位置读的数据量几乎相同，所以 $K$ 较小时耗时基本不变。
